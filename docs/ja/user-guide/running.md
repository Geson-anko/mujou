# ネットワークを走らせる

`mujou.run` はネットワークをバックグラウンドで走らせ、実行のハンドル `Run` を返す。ホスト（ネットワークを走らせる Python のプログラム）は、`Run` のメソッドで入力を書き、出力を読み、終了させる。このページはその手順を説明する。

## 基本の形

```python
--8<-- "examples/quickstart.py:run"
```

1. `mujou.run(net)` が、ネットワークを構築し、全ノードを起動する。全ノードの `on_start` が終わってから戻る
2. 戻った時点で、各ノードは自分のスレッドで `on_update` を繰り返している。ホストのスレッドは止まらない
3. ホストは `write` で入力を書き、`read`・`subscribe`・`wait_for` で出力を読む。上の例は、期待した値が届くまで `wait_for` で待つ
4. `with` 文を抜けると `shutdown()` が呼ばれ、全ノードの `on_stop` が終わるまで待つ

`mujou.run` の引数は次のとおりである。

| 引数                     | 意味                                                                                              | 既定                         |
| ------------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------- |
| `component, *components` | 走らせるネットワークかノード。2 つ以上なら 1 つの実行に束ねる（[ネットワークを束ねる](group.md)） | 必須                         |
| `timer`                  | 実行のタイマー（[時間の制御](time.md)）                                                           | `None`（グローバルタイマー） |
| `inputs`                 | 入力の初期値。`{port: value}`                                                                     | `None`                       |
| `state`                  | 復元する状態の木（[状態の保存と復元](state.md)）                                                  | `None`                       |
| `pause_timeout`          | `state_dict` が全ノードの一時停止を待つ実時間（秒）                                               | `30.0`                       |

ノード 1 つだけを走らせるときは、ネットワークで包まずに `mujou.run(node)` と渡せる。このときノードのパスは `""`、その Port のパスは `"prev"` などになる（[ネットワークを束ねる](group.md)）。

1 つのネットワークが走るのは 1 回だけである。一度 `mujou.run` に渡したネットワークを、走っている間でも終わった後でも、もう一度 `mujou.run` に渡すと `RuntimeError` になる。もう一度走らせるときは、ノードも含めて新しいインスタンスを作る。

## 入力を書く

ホストが書けるのは、つながっておらず、相手を 1 つしか取らず、受け取る型を持つ Port である。つながっている Port にはノードが書くので、ホストは書けない。

| 方法                                   | いつ使うか                                    |
| -------------------------------------- | --------------------------------------------- |
| `mujou.run(net, inputs={port: value})` | 最初の `on_update` から見せたい入力（初期値） |
| `run.write({port: value, ...})`        | 走っている途中で入力を切り替える              |

`inputs` を渡さなければ、入力の初期値はゼロである。`mujou.run` が戻った時点で、ノードはすでに `on_update` を繰り返している。そのため、`mujou.run` の後で `write` しても、`write` するまでの更新ではノードはゼロを読む。最初の更新からゼロ以外を見せたいなら `inputs` で渡す。

`write` の性質は次のとおりである。

- 書いた値は、次に書くまで保たれる。入力は「時間とともに変わる信号」で、ノードは同じ入力を何度も読む
- 1 回の `write` で書いた複数の Port の値は、同時に切り替わる。ノードが片方だけ新しい値を読むことはない。入力と教師信号のように組で切り替えたい値は、1 回の `write` にまとめる
- 値はコピーされる。書いた後でテンソルを書き換えても、ネットワークには届かない
- `write` は、値を書いた時刻を返す

### 入力を一定の時間だけ見せる

入力を見せる長さは、実行のタイマーで待って決める。グローバルタイマーで走らせているなら `mujou.time.sleep(seconds)` を使う。標準の `time.sleep` は、時間の速さの変更も、状態の取得による一時停止も無視するので使わない。

```python
for x in stream:
    run.write({net.prev: x})
    mujou.time.sleep(0.1)          # x を 0.1 秒見せる
    y, t = run.read(net.next)      # 見せ終わる時点の出力を、x への応答とみなす
```

出力は、入力が変わってから遅れて追いつく。遅れの長さはネットワークのダイナミクス（ノードの時定数や段数）で決まり、mujou は決めない。見せる時間の長さは、出力が十分に追いつくように利用者が選ぶ。`write` の直後に `read` すると、前の入力に対する出力が返る。入力と出力を対応させたいときは、見せる時間の終わりに読む。期待する出力が分かっているなら、代わりに `wait_for` で待つ（下の「出力を読む」）。

## 出力を読む

出力の読み方は 3 つある。

| 方法                            | 返すもの                                                    | 向いている用途                     |
| ------------------------------- | ----------------------------------------------------------- | ---------------------------------- |
| `run.read(port)`                | その時点の最新の値と、送られた時刻の組 `(value, Timestamp)` | ホストが自分の都合のよいときに読む |
| `run.subscribe(port)`           | `(value, Timestamp)` を順に返すイテレータ                   | 出力が新しくなるたびに処理する     |
| `run.wait_for(port, condition)` | 値が `condition` を満たす最初の `(value, Timestamp)`        | 期待した出力が届くまで待つ         |

どれも、送る型を持つどの Port からでも読め、時刻を `mujou.time.Timestamp` で返す（[時間の制御](time.md)）。つながっていない Port を読めばネットワークの出力になり、つながっている Port を読めば途中のノードの値を観測できる。ノードの動作は変わらない。

`read` の性質は次のとおりである。

- 返すのは、その Port の持ち主のノードが最後に `send` した値である。まだ `send` していなければ、その Port の初期値（`initial`。無ければゼロ）を返す。`send_to` で送った値は `read` に反映されない
- 値は CPU 上の新しいコピーである

`subscribe` は次のように進む。

1. 最初の 1 つは、呼んだ時点の最新の値を待たずに返す。まだ送られていなければ、その Port の初期値である
2. 以後は、新しい値が送られるまで待ち、その時点の最新の値を返す。読むのが遅ければ、間の値は飛ばされる
3. 実行が正常に終了すると、反復が終わる。ノードの例外で終了したときは、反復が `NetworkError` を送出する
4. `timeout=seconds` を渡すと、`subscribe` を呼んでから実時間でその秒数がたった時点で、反復が `TimeoutError` を送出する。ループの本体にかかった時間も数える。実行は走り続ける。既定では無期限である

待つのはホストの側だけで、送るノードはホストを待たない。次の例は、20 個受け取ったら `break` でループを抜ける。`break` も `timeout` も無ければ、ループは実行が終わるまでそのスレッドをふさぐので、別のスレッドから `shutdown()` を呼べば終わらせられる。

```python
--8<-- "examples/subscribe.py:subscribe"
```

期待した出力が届くまで待つには、`wait_for` を使う。最新の値から順に、新しい値ごとに条件を確かめ、条件を満たした最初の値を返す。実時間で `timeout` 秒たつと `TimeoutError` を送出し（実行は走り続ける）、先に実行が止まると `RuntimeError` を送出する。

```python
y, t = run.wait_for(net.next, lambda y: torch.equal(y, expected), timeout=5.0)
```

## 終了させる

| 方法                          | すること                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `with mujou.run(...) as run:` | ブロックを抜けるときに `shutdown()` を呼ぶ。普通はこれを使う                                                      |
| `run.shutdown(timeout=...)`   | 全ノードに終了を求め、全ノードの `on_stop` が終わるまで待つ                                                       |
| `run.join(timeout=...)`       | 終了を求めずに、終了するまで待つ。別のスレッドが `shutdown()` を呼んだ後や、`shutdown` が時間切れになった後に使う |

`timeout` は実時間の秒数で、既定は無限である。時間切れのときの振る舞いは[例外と終了](errors.md)の「タイムアウト」にある。

正常に終了した後に `shutdown` を呼んでも何もしない。正常に終了した後も `run.state_dict()` で最後の状態を取れる（[状態の保存と復元](state.md)）。終了した実行に `write` すると `RuntimeError` になる。

`Run` を捨てても実行は止まらない。`shutdown` か `with` 文で、必ず終了させる。

どれかのノードが例外を投げると、ネットワーク全体が終了し、以後の `Run` のメソッドが `NetworkError` を送出する。詳しくは[例外と終了](errors.md)にある。
