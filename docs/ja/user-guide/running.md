# 🏃 ネットワークを走らせる

`mujou.run` はネットワークをバックグラウンドで走らせ、実行のハンドル `Run` を返す。ホスト（ネットワークを走らせる Python のプログラム）は `Run` のメソッドで入力を書き、出力を読み、実行を終了させる。

## 基本の形

```python
--8<-- "examples/quickstart.py:run"
```

1. `mujou.run(net)` でネットワークを構築し、全ノードを起動する。全ノードの `on_start`（復元なら `load_state_dict` も）が終わってから戻る
2. 以後、各ノードは実行のワーカースレッドの上で周期ごとに `on_update` を繰り返す（[実行のスレッド](#%E5%AE%9F%E8%A1%8C%E3%81%AE%E3%82%B9%E3%83%AC%E3%83%83%E3%83%89)）。ホストのスレッドは止まらない
3. ホストは `write` で入力を書き、`read`・`read_with_time`・`subscribe`・`wait_for` で出力を読む。上の例では期待した値が届くまで `wait_for` で待つ
4. `with` 文を抜けると `shutdown()` が呼ばれ、全ノードの `on_stop` が終わるまで待つ

`mujou.run` の引数は次のとおり。

| 引数                     | 意味                                                                                                             | 既定                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `component, *components` | 走らせるネットワークかノード。2 つ以上なら 1 つの実行に束ねる（[ネットワークを束ねる](group.md)）                | 必須                                 |
| `timer`                  | 実行のタイマー（[時間の制御](time.md)）                                                                          | `None`（グローバルタイマー）         |
| `inputs`                 | 入力の初期値。`{port: value}`                                                                                    | `None`                               |
| `state`                  | 復元する状態の木（[状態の保存と復元](state.md)）                                                                 | `None`                               |
| `workers`                | 実行のワーカースレッドの数（[実行のスレッド](#%E5%AE%9F%E8%A1%8C%E3%81%AE%E3%82%B9%E3%83%AC%E3%83%83%E3%83%89)） | `None`（CPU の数。GIL ありなら半分） |

`run.timer` は実行のタイマーを返す。`timer` を渡していればそれ、渡していなければ `mujou.time` が読むグローバルタイマーである。

ノード 1 つだけならネットワークで包まずに `mujou.run(node)` と渡せる。このときノードのパスは `""`、その Port のパスは `"prev"` などになる（[ネットワークを束ねる](group.md)）。

!!! warning "ネットワークは 1 回しか走らせられない"

    一度 `mujou.run` に渡したネットワークをもう一度 `mujou.run` に渡すと、実行中でも終了後でも `RuntimeError` になる。再び走らせるときはノードも含めて新しいインスタンスを作る。

## 実行のスレッド

実行はノードごとにスレッドを立てない。実行ごとにワーカースレッドのプールを作り、ワーカーがノードを分け合って動かす。ワーカーは 1 つのノードの hook を 1 回実行したら、期限の早い更新から次の仕事を取る。ノードが多くてもスレッドは少ないままで、OS がスレッドの切り替えに時間を取られない。

- ワーカーの数は `workers` で決める。既定の `None` はプロセスが使える CPU の数（論理コア数。CPU の affinity や割り当ての上限があればそれより少ない）、GIL ありならその半分（最低 1）で、ワーカーに載るノードの数を超えない
- 1 つのノードの hook が同時に走ることはなく、前の hook が書いた値は次の hook から見える。どのワーカーがノードを動かすかは hook ごとに変わりうる
- ブロッキングする hook（`time.sleep`、I/O や lock の待ち）はその間ワーカーをふさぎ、ほかのノードの `dt` が伸びる。そういうノードには `dedicated_thread=True` を渡し、ワーカーでなく専用のスレッドで動かす（[ノードを書く](writing-a-node.md#%E5%B0%82%E7%94%A8%E3%81%AE%E3%82%B9%E3%83%AC%E3%83%83%E3%83%89%E3%81%A7%E5%8B%95%E3%81%8B%E3%81%99)）

GIL ありの Python では Python のコードを同時に実行できるスレッドが 1 本だけなので、ノードが並列に動くのは torch の演算の中に限られる。CPU の数の半分を超えてワーカーを増やしても GIL を取り合うだけなので、既定を半分にしている。Python の処理が大半を占めるノードなら、`workers` をさらに小さくしても速さはほとんど変わらない。

## 入力を書く

ホストが書けるのは次の条件をすべて満たす Port である。

- つながっていない
- 相手を 1 つしか取らない
- 受け取る型を持つ

つながっている Port にはノードが書くので、ホストは書けない。

| 方法                                   | いつ使うか                                    |
| -------------------------------------- | --------------------------------------------- |
| `mujou.run(net, inputs={port: value})` | 最初の `on_update` から見せたい入力（初期値） |
| `run.write({port: value, ...})`        | 実行中に入力を切り替える                      |

`inputs` を渡さなければ入力の初期値はゼロになる。

!!! tip "最初の入力は `inputs` で渡す"

    `mujou.run` が戻るとノードはすぐに `on_update` を始めるので、後から `write` すると、それより前の更新ではノードがゼロを読むことがある。最初の更新からゼロ以外の値を見せたいなら `inputs` で渡す。

`write` の性質は次のとおり。

- 書いた値は次に書くまで保たれる。入力は「時間とともに変わる信号」で、ノードは同じ入力を何度も読む
- 1 回の `write` で書いた複数の Port の値は同時に切り替わる。ノードが片方だけ新しい値を読むことはない。入力と教師信号のように組で切り替えたい値は 1 回の `write` にまとめる
- 値はコピーされる。書いた後でテンソルを書き換えてもネットワークには届かない
- 戻り値は値を書いた時刻

### 入力を一定の時間だけ見せる

入力を見せる長さは実行のタイマーで待って決める。グローバルタイマーで走らせているなら `mujou.time.sleep(seconds)` を使う。

!!! warning "`time.sleep` を使わない"

    標準の `time.sleep` は時間の速さの変更や、状態の取得による一時停止を無視するので使わない。

```python
for x in stream:
    run.write({net.prev: x})
    mujou.time.sleep(0.1)          # x を 0.1 秒見せる
    y = run.read(net.next)         # 見せ終わる時点の出力を、x への応答とみなす
```

出力は入力が変わってから遅れて追いつく。遅れの長さはネットワークのダイナミクス（ノードの時定数や段数）で決まり、mujou は決めない。出力が十分に追いつくよう、見せる時間は利用者が選ぶ。

`write` の直後に `read` すると前の入力に対する出力が返る。入力と出力を対応させたいときは見せる時間の終わりに読む。期待する出力が分かっているなら、代わりに `wait_for` で待つ（下の「出力を読む」）。

## 出力を読む

出力の読み方は 4 つある。

| 方法                            | 返すもの                                                  | 向いている用途                 |
| ------------------------------- | --------------------------------------------------------- | ------------------------------ |
| `run.read(port)`                | その時点の最新の値                                        | 任意のタイミングで読む         |
| `run.read_with_time(port)`      | その時点の最新の値と送られた時刻の組 `(value, Timestamp)` | 値を時刻と合わせて読む         |
| `run.subscribe(port)`           | `(value, Timestamp)` を順に返すイテレータ                 | 出力が新しくなるたびに処理する |
| `run.wait_for(port, condition)` | 値が `condition` を満たす最初の `(value, Timestamp)`      | 期待した出力が届くまで待つ     |

どれも送る型を持つどの Port からでも読める。`read` 以外は時刻を `mujou.time.Timestamp` で返す（[時間の制御](time.md)）。

つながっていない Port を読むとネットワークの出力になる。つながっている Port を読めば途中のノードの値を観測できる。読んでもノードの動作は変わらない。

`read` と `read_with_time` の性質は次のとおり。

- 返すのはその Port の持ち主のノードが最後に `send` した値。まだ `send` していなければ、その Port の初期値（`initial`。無ければゼロ）を返す。`send_to` で送った値は `read` に反映されない
- 値は CPU 上の新しいコピー

`subscribe` は次のように進む。

1. 最初の 1 つは、呼んだ時点の最新の値を待たずに返す。まだ送られていなければその Port の初期値
2. 以後は新しい値が送られるまで待ち、その時点の最新の値を返す。読むのが遅ければ間の値は飛ばされる
3. 実行が正常に終了すると反復が終わる。ノードの例外で終了したときは反復が `NetworkError` を送出する
4. `timeout=seconds` を渡すと、`subscribe` を呼んでから実時間でその秒数がたった時点で反復が `TimeoutError` を送出する。ループ本体にかかった時間も数える。実行は走り続ける。既定は無期限

待つのはホストの側だけで、送るノードはホストを待たない。次の例では 20 個受け取ったら `break` でループを抜ける。`break` も `timeout` も無ければ、ループは実行が終わるまでそのスレッドをふさぐ。その場合は別のスレッドから `shutdown()` を呼べば終わらせられる。

```python
--8<-- "examples/subscribe.py:subscribe"
```

期待した出力が届くまで待つには `wait_for` を使う。最新の値から順に新しい値ごとに条件を確かめ、条件を満たした最初の値を返す。実時間で `timeout` 秒たつと `TimeoutError` を送出し（実行は走り続ける）、先に実行が止まると `RuntimeError` を送出する。

```python
y, t = run.wait_for(net.next, lambda y: torch.equal(y, expected), timeout=5.0)
```

## 終了させる

| 方法                          | すること                                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `with mujou.run(...) as run:` | ブロックを抜けるときに `shutdown()` を呼ぶ。通常はこれを使う                                                |
| `run.shutdown(timeout=...)`   | 全ノードに終了を求め、全ノードの `on_stop` が終わるまで待つ                                                 |
| `run.join(timeout=...)`       | 終了を求めずに終了まで待つ。別のスレッドが `shutdown()` を呼んだ後や、`shutdown` が時間切れになった後に使う |

`timeout` は実時間の秒数で、既定は無限。時間切れのときの振る舞いは[例外と終了](errors.md)の「タイムアウト」を参照。

正常に終了した後に `shutdown` を呼んでも何もしない。正常に終了した後も `run.state_dict()` で最後の状態を取得できる（[状態の保存と復元](state.md)）。終了した実行に `write` すると `RuntimeError` になる。

!!! warning "`Run` を捨てても実行は止まらない"

    `shutdown` か `with` 文で必ず終了させる。

どれかのノードが例外を投げるとネットワーク全体が終了し、以後の `Run` のメソッドは `NetworkError` を送出する。詳しくは[例外と終了](errors.md)を参照。
