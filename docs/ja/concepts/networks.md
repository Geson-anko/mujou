# ネットワーク

ネットワークは、ノードの組み合わせ方を宣言する構造である。利用者は `mujou.Network` を継承したクラスとしてネットワークを書く。

## 宣言の仕方

ネットワークの `__init__` では、次の 3 つを書く。PyTorch の `nn.Module` に子のモジュールを属性として持たせるのと同じ書き方である。

1. ノードや別のネットワークを属性として持つ
2. それらの Port を `connect` でつなぐ
3. 外からつなぎたい Port を、自分の属性として公開する

```python
class Stack(mujou.Network):
    def __init__(self) -> None:
        super().__init__()
        self.l1 = Hidden(784, 256)
        self.l2 = Hidden(256, 256)
        self.l1.connect(self.l2)       # l1.next と l2.prev をつなぐ
        self.prev = self.l1.prev       # 公開した PrevPort がネットワークの前側になる
        self.next = self.l2.next       # 公開した NextPort がネットワークの次側になる
```

`PrevPort` と `NextPort` を公開したネットワークは、ノードと同じように `stack.connect(head)` でつなげる。

ネットワークは、別のネットワークを子として持てる（入れ子）。ノードは、ほかのノードやネットワークを属性に持てない。

## ネットワークは実行の単位ではない

ネットワークは、構築するときにだけ使う構造である。ネットワークには hook も `on_update` も無い。ネットワークの中のノードは、実行中もそれぞれ独立に、互いを待たずに動く。ネットワークで囲んでも、中のノードが同期することはない。

複数の層を同期させて計算したいときは、ネットワークではなく、それらをまとめた 1 つのノードのクラスを書く（[ノード](nodes.md)）。

## 構築と実行

ネットワークは、宣言 → 構築 → 実行 の順に使う。

1. 宣言: ネットワークのインスタンスを作る。この時点ではまだ接続を足せる
2. 構築: `net.build()` が構造と型を検査して凍結し、構築した構造（`Graph`）を返す。何度呼んでも同じ `Graph` を返す。構築した後は `connect` できない
3. 実行: `mujou.run(net)` が構築し、その `Graph` をバックグラウンドで走らせ、実行のハンドル `Run` を返す

`mujou.run` が `build()` を呼ぶので、利用者が `build()` を呼ぶ必要は普通は無い。`Graph` は宣言したネットワークとは別のオブジェクトで、mujou はこの `Graph` を走らせる。1 つの `Graph` が走るのは 1 回だけである。

`Graph` が公開するのは、パスとノードの組の一覧 `nodes` と、Port のパスを返す `port_path(port)` だけである。走らせるのも入出力も `mujou.run` と `Run` で行うので、利用者が `Graph` を使う必要は普通は無い。

`mujou.run` には、ネットワークの代わりにノードを渡してもよい。ノードを 1 つだけ渡せば、ネットワークで包まずにそのノードだけを走らせる。そのときのパスは下の「パス」にある。

走り出した後、ホストは `Run` のメソッドだけでネットワークとやり取りする。

| メソッド              | すること                                         |
| --------------------- | ------------------------------------------------ |
| `run.write({...})`    | つながっていない Port に入力を書く               |
| `run.read(port)`      | Port の最新の値と、その時刻を読む                |
| `run.subscribe(port)` | ノードが新しい値を送るたびに、最新の値を受け取る |
| `run.state_dict()`    | 状態を取得する（[状態](state.md)）               |
| `run.shutdown()`      | 終了させ、終了するまで待つ                       |
| `run.join()`          | 終了させずに、終了するまで待つ                   |

`Run` は `with` 文で使え、抜けるときに `shutdown()` を呼ぶ。

## パス

ネットワークの中のノードは、ルートからの属性名を `.` でつないだパスで指す。たとえば、ルートの属性 `body` が `Stack` で、その属性 `l1` がノードなら、そのノードのパスは `"body.l1"` である。状態の木の中のノードも、このパスで区別される（[状態](state.md)）。

複数のネットワークを 1 つの実行で走らせるときは、`mujou.Compose` で束ねる。

| `mujou.run` に渡すネットワーク               | ノード `l1` のパス |
| -------------------------------------------- | ------------------ |
| `Compose(a, b)` で、`l1` は `b` の中         | `"1.l1"`           |
| `Compose(enc=a, dec=b)` で、`l1` は `a` の中 | `"enc.l1"`         |

位置で渡したネットワークは `"0"`, `"1"`, ... という名前に、キーワードで渡したネットワークはそのキーワードの名前になる。`mujou.run(a, b)` は `mujou.run(Compose(a, b))` と同じである。`Compose` にはノードも渡せ、ノードにも同じ規則で名前が付く（`Compose(node)` のノードのパスは `"0"`）。`Compose` は、渡したものが 1 つでも名前を足す。`mujou.run(Compose(enc=a))` なら、`l1` のパスは `"enc.l1"` である。

`mujou.run` にネットワークかノードを 1 つだけ渡すと、パスの前に名前を足さない。ノード 1 つの `mujou.run(node)` では、ノードのパスは `""`、その Port `prev` のパスは `"prev"` になる。状態の木でも、このノードはパス `""` で区別される（[状態](state.md)）。

ノードかネットワークを持つ属性の名前を変えたり、接続を変えたりすると、ノードのパスや値の置き場所の名前が変わる。そうなると、変える前に取得した状態は復元できない（[状態](state.md)）。

詳しい使い方は[ネットワークを組む](../user-guide/building-a-network.md)、[ネットワークを走らせる](../user-guide/running.md)、[ネットワークを束ねる](../user-guide/compose.md)にある。
