# 状態

mujou は、走っているネットワークを終了させずに状態を取得し、後でその状態から走らせ直せる。学習を終えてから重みを保存する従来の使い方とは違い、学び続けている途中の状態をそのまま保存する。

## 状態の木

`run.state_dict()` は、ネットワークの状態を 1 つの木（入れ子の dict）として返す。木には次のものが入る。

| キー             | 中身                                                                 | 誰が入れるか              |
| ---------------- | -------------------------------------------------------------------- | ------------------------- |
| `nodes`          | ノードのパスごとの、各ノードの状態（重み、活動など）                 | 各ノードの `state_dict()` |
| `slots`          | 値の置き場所ごとの、最新の値と、その時刻（ホストが書いた入力も含む） | mujou が自動で入れる      |
| `last_update_ns` | ノードのパスごとの、最後の更新の時刻（ナノ秒。次の `dt` の起点）     | mujou が自動で入れる      |
| `timer`          | 実行のタイマーの時刻と速さ（`time_ns` と `scale`）                   | mujou が自動で入れる      |

Port の値も木に入れるのは、ネットワークの状態が、ノードの状態とノードの間を流れている値を合わせたものだからである。Port の値を初期値に戻して走らせ直すと、隣のノードが初期値を読み、それまでの平衡から外れる。

`nodes` のキーはノードのパス（`"body.l1"` など。[ネットワーク](networks.md)）である。たとえば `mujou.run(net)` で走らせた `l1` の状態は `tree["nodes"]["l1"]` で取り出す。ノード 1 つの `mujou.run(node)` なら `tree["nodes"][""]` である。

## ノードの状態の自動収集

`mujou.Node` は、`nn.Module` と同じように、属性に代入した値から状態を自動で集める。

| 代入した値                                 | 状態に入るか                            |
| ------------------------------------------ | --------------------------------------- |
| `torch.Tensor`（`nn.Parameter` を含む）    | 入る                                    |
| `nn.Module`                                | 入る（そのモジュールの `state_dict()`） |
| 数値、`None`、Port、Tensor のリストや dict | 入らない                                |

属性の名前が `_` で始まっていてもいなくても、同じように集める。集めた属性に `None` などを代入し直すか `del` すると、状態から外れる。optimizer や乱数生成器の状態は自動では集めない。ほかのものを状態に入れたいときは、`state_dict` と `load_state_dict` を override する。

状態にするテンソルは `on_start` で作り、その後はその場で更新する。

`on_stop` では状態を変えない。正常に終了した後の `run.state_dict()` は、`run.shutdown()` で終了を求めた時点の状態を返す約束である。`on_stop` はその後に呼ばれるので、`on_stop` で状態を変えると、その変更が終了後の木に混ざってしまう。たとえば `on_stop` で `self.w = None` とすると、`w` が状態から外れ、終了後に取る木から `w` が消える。`on_stop` で解放するのは I/O などの資源で、状態のテンソルは手放さない。

## 取得できるとき

| ネットワークの状況 | `run.state_dict()`                                      |
| ------------------ | ------------------------------------------------------- |
| 実行中             | 取得できる。その瞬間の状態を返す                        |
| 正常に終了した後   | 取得できる。`shutdown()` で終了を求めた時点の状態を返す |
| 例外で終了した後   | 取得できない。`NetworkError` になる                     |

例外で終了したときの状態は保存しない。保存したい状態は、実行中か正常に終了した後に取る。

## 取得の間は時間が止まる

実行中に状態を取るとき、mujou は次の順に処理する。

1. その実行の全ノードに止まるよう求め、すぐに実行のタイマーを止める
2. 各ノードは実行中の `on_update` を最後まで終えてから止まり、`on_pause()` を呼ばれる。`on_update` の途中では止まらない
3. 全ノードが止まったら、全ノードの `state_dict()` を呼び、木のコピーを作る
4. タイマーとノードを再開する。各ノードは `on_resume()` を呼ばれてから次の `on_update` に進む
5. コピーした木をホストに返す

同じタイマーで走っているほかの実行のノードは、止まるよう求められず、`on_pause()` も呼ばれない。それらのノードの時間も止まるので、タイマーが再開するまで新しい `on_update` を始めない。止まっていた時間は、それらのノードの `dt` にも入らない。

止めている間はタイマーも止まっているので、再開後の `dt` に停止の時間は入らない（[グローバル時間](time.md)）。ノードの更新から見ると、状態の取得は無かったのと同じである。全ノードが止まっている間に取るので、木の中の値はすべて同じ時刻の状態としてそろう。

木はコピーなので、取得の後にノードが更新を続けても、ホストの手元の木は変わらない。木をどこにどう保存するか（`pickle` や `torch.save` など）は利用者が決める。mujou もノードもファイルを扱わない。

## 復元

保存した木から走らせ直すには、`mujou.run(net, state=木)` に渡す。mujou は各ノードの `on_start()` を呼んだ後、最初の `on_update` の前に、各ノードの `load_state_dict()` で状態を戻す。Port の値とタイマーの時刻も戻し、木を取った時刻から走り始める。

復元するネットワークは、木を取ったネットワークと同じノードのパスと同じ接続を持たなければならない。違えば `mujou.run` は `ValueError` を送出し、何も起動しない。

保存と復元の手順は[状態の保存と復元](../user-guide/state.md)にある。
