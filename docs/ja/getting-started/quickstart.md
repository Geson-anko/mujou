# クイックスタート

最小のプログラムを走らせ、出力を読む。このプログラムは 2 つのノードをつないで $y = 2x + 1$ を計算する。

```mermaid

    H1["ホスト"] -->|"x を書く"| S["scale（2 倍）"]
    S --> F["shift（+1）"]
    F -->|"y を読む"| H2["ホスト"]
```

## プログラム

```python title="examples/quickstart.py"
--8<-- "examples/quickstart.py"
```

ソースからビルドした環境なら、リポジトリのルートで次のように走らせる。

```sh
uv run python examples/quickstart.py
```

次のような 1 行が表示される。`t` の値は実行ごとに変わる。

```text
y = tensor([3., 5., 7.]) at t = 0.017 s
```

## ノードを定義する

`Scale` と `Shift` がノードである。ノードは `mujou.Node` を継承したクラスとして書く。

| コード                              | 意味                                                                                                                                            |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `VECTOR = TensorSpec((3,))`         | メッセージの形と dtype の宣言。ここでは長さ 3 の float32 のベクトル                                                                             |
| `super().__init__()`                | 継承したクラスの常として、まず `mujou.Node` の `__init__` を呼ぶ。override した hook でも同じように `super()` を呼ぶ（`super().on_update(dt)`） |
| `self.prev = PrevPort(recv=VECTOR)` | 前の側の Port。`VECTOR` のメッセージを受け取る                                                                                                  |
| `self.next = NextPort(send=VECTOR)` | 次の側の Port。`VECTOR` のメッセージを送る                                                                                                      |
| `def on_update(self, dt)`           | mujou が繰り返し呼ぶメソッド。1 回分の処理を書く。`dt` は前回の呼び出しからの経過時間（秒）で、このプログラムでは使わない                       |
| `x = self.prev.recv()`              | 前の側から届いている最新の値を読む。新しい値を待たない。まだ何も届いていなければゼロのテンソルを返す                                            |
| `self.next.send(self.factor * x)`   | 計算結果を次の側へ送る                                                                                                                          |

Port は `__init__` で宣言する。ループは mujou が回すので、ノードの中に `while` ループを書かない。新しい値が届くのを待つ代わりに、`on_update` のたびに最新の値を読んで計算する。新しい値かどうかを知りたいときは、`recv_with_time()` で値と送られた時刻を読み、前回読んだ時刻と比べる。

## ノードをつなぐ

`Affine` はネットワークである。ネットワークは `mujou.Network` を継承し、ノードを属性として持つ。

| コード                           | 意味                                                   |
| -------------------------------- | ------------------------------------------------------ |
| `self.scale.connect(self.shift)` | `scale` の `next` と `shift` の `prev` をつなぐ        |
| `self.prev = self.scale.prev`    | ネットワークの入力として、`scale` の `prev` を公開する |
| `self.next = self.shift.next`    | ネットワークの出力として、`shift` の `next` を公開する |

## 走らせて入出力する

ホストの部分は、`with mujou.run(net) as run:` から最後の `assert` までである。

1. `mujou.run(net)` がネットワークを走らせる。各ノードは自分のスレッドで `on_update` を繰り返す。ノードが動き出すと `mujou.run` は戻り、ホストのプログラムは先へ進む
2. `run.write({net.prev: x})` が、どこにもつながっていない入力の Port である `scale` の `prev` に `x` を書く。書いた値は、次に書くまでその Port に残る
3. `run.subscribe(net.next, timeout=5.0)` で、`shift` の `next` が送る値を追う。`for` ループの 1 周ごとに、値と送った時刻の組 `(y, t)` が得られる。最初の 1 周は最新の値をすぐに返し、以後の 1 周は新しい値が送られるまで待つ
4. `y` が $2x + 1$ になったら `break` でループを抜ける。実時間で 5 秒たっても届かなければ、ループが `TimeoutError` を送出し、プログラムは失敗する。`else` のブロックは `break` せずにループが終わったときだけ実行される。`y` が届く前に実行が止まった場合である
5. `with` ブロックを抜けると、ネットワークが止まる

`subscribe` の `timeout` は実時間の秒で数える。入力をしばらく見せるときなど、mujou の時間で待つときは、標準の `time.sleep` ではなく `mujou.time.sleep` を使う。`mujou.time.sleep` は mujou のグローバル時間で待つので、時間の速さを変えたときや、実行が一時停止したときにも正しく待てる（[グローバル時間](../concepts/time.md)）。

## 出力を読む

```text
y = tensor([3., 5., 7.]) at t = 0.017 s
```

| 部分                       | 意味                                                                                                                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `y = tensor([3., 5., 7.])` | `x = [1, 2, 3]` に対する $2x + 1$。最後の `assert` がこれを確かめる                                                                                                                      |
| `t = 0.017 s`              | `shift` が `y` を送ったグローバル時間の時刻（秒）。`y` を読んだ時刻ではない。グローバル時間は、プロセスの中で最初に使われた時点を 0 とする。目安として `import mujou` のころと考えてよい |

1 回読むのではなく出力を追うのは、`write` の直後に読むと、`y` が `[3., 5., 7.]` にならないことがあるからである。`x` が `scale` と `shift` を通って届くまでには、何回かの更新がかかる。値が届くまでは、`shift` はまだ前の入力（最初はゼロ）から計算した値を送っている。決まった時間の中で何回更新できるかは、スレッドの割り当てで変わる。そのため、決まった時間だけ待つのではなく、届くまで出力を追う。

`t` は実行ごとに変わる。ノードは互いを待たずに動くので、何回目の更新で値が届くかは実行ごとに違う。

## ノードが例外を投げたら

どれかのノードが例外を投げると、ネットワーク全体が止まる。その後に `write` や `read` を呼ぶと、ホストに `mujou.NetworkError` が送出される。`NetworkError` の `__cause__` が、ノードが投げた元の例外である（[例外と終了](../user-guide/errors.md)）。

## 実行周期

このプログラムのノードは `super().__init__()` に `period` を渡していないので、実行周期が無い。周期の無いノードは、待たずに `on_update` を繰り返し、CPU のコアを 1 つ使い切る。

一定の間隔で更新させるには、周期を秒で渡す（`super().__init__(period=秒)`）。

```python
class Scale(Node):
    def __init__(self, factor: float) -> None:
        super().__init__(period=0.01)  # 平均して 0.01 秒に 1 回 on_update が呼ばれる
        ...
```

周期があっても、`dt` は実際に経過した時間である。だいたい周期に近いが、遅れれば長くなる（[ノードを書く](../user-guide/writing-a-node.md)）。
