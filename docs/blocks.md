# ブロック

## 定義

**ブロック** は mujou の計算の基本単位であり、基盤となる抽象である。

- ブロックの **内側** は同期的に計算する
- ブロック **同士** は非同期にやり取りする
- 非同期・分散の境界は、常にブロックの境界と一致する

局所性・非同期性の不変条件は **ブロックの間** に課す。ブロックの内側の計算方法（ニューロンの合成、行列演算、BP など）は、ブロックごとに自由に選べる。

## ブロックの大きさ

ブロックの大きさは、実装・モード・設定で選べるようにする。対象とするのは次の 3 つのレベルである。

| レベル     | 内容                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| ニューロン | 1 ニューロンを 1 ブロックにする。最小のブロック                        |
| レイヤー   | 1 レイヤーを 1 ブロックにする。**既定**                                |
| スタック   | 複数のレイヤーを 1 ブロックにする。モデル全体を 1 ブロックにしてもよい |

既定をレイヤーにしたのは、わかりやすさのためである。

### ニューロンが最小である理由

既定の更新手法 PC-ALM の更新式（活動・双対変数・重み）は、ニューロン自身と、シナプスでつながった相手の値だけで閉じる。そのため、ニューロン 1 個を 1 ブロックにまで分割できる。

### 粒度を選べるようにする理由

どの粒度が最適かは、ハードウェアと用途（ロボティクス、ニューロモーフィックなど）によって変わる。ブロックを基盤にすれば、ニューロン単位の細かい非同期も、BP のような同期的な手法も、同じ枠組みで扱える。

## BP の取り込み

ブロックの内側は同期的なので、BP のような forward/backward も、そのブロックの中に閉じていれば許容する。外から見れば、値をやり取りする 1 つのブロックに過ぎない。

ただし、ブロックをまたいで計算グラフをつなげてはならない（ブロックをまたぐ `.backward()` は禁止）。ブロック内で autograd を使う書き方は skill `locality-and-async` を参照。

## ブロック間の契約

- ブロック間でやり取りする値は **結合ごとの値の束** として定義する。ブロックの大きさを変えても、ブロック間の契約が変わらないようにするためである
- **ブロックをまたぐ結合の重みは、後シナプス側のブロックが所有する。** 前シナプス側へは $W[k,j]\,\varepsilon_k$ を結合ごとの値として送る。両端で重みのコピーを持つと、非同期実行でコピー同士がずれる（weight transport の問題）
- 層内で横方向に結合する演算（softmax、LayerNorm など）も、ニューロン単位で表せるようにする。同じ層のニューロン同士の結合を横方向の値のやり取りとして扱い、ブロック間の不変条件を同じように適用する

## 設計目標から外すもの

**GPU 計算での最適性は設計目標にしない。** ニューロン単位の分割は行列積を値のやり取りの集まりに分解するので、GPU では非効率になる。しかし、それを理由に設計を制限しない。

## テストで確かめること

- PC-ALM のレイヤーブロックを、ニューロンブロックの合成として組んだ場合と、まとめて行列演算で組んだ場合とで、同じ結果になる
- ブロックの分け方とスケジュールを変えても、同じ不動点に収束する
