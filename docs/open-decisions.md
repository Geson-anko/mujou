# 未決定事項

2026-10-14 時点で、次の設計判断はまだ決まっていない。これらに関わる実装は、決定を待ってから進める。

## ネットワークスキーマの API

ブロックの組み合わせと双方向の接続を定義するネットワークオブジェクトを提供し、define-and-run で記述してスキーマオブジェクトを作ることは決定済み。Port・Channel による双方向接続の仕組みも決定済み。Block と Network の Composite、`a.connect(b)`、PrevPort・NextPort も決定済み。API の具体的な形（クラス名・メソッド名、shape の決め方、`build` をどこから呼ぶか、実行と外からの読み書きの API など）は未決定。関連: [ネットワーク](network.md)

## 実行の配置

複数のブロックを同じワーカーで決まった順に回すこと（[ブロック](blocks.md#非同期の境界と実行の配置)）を、利用者がどう指定するか。ブロックごとの実行クラス（タスク・専用スレッド）と目標周期の指定方法も未決定。関連: [ネイティブコア](native-core.md#mn-スケジューリング)

## ライフサイクルの細部

hook の構成（`on_start`・`on_update`・`on_pause`・`on_resume`・`on_stop`・`state_dict`・`load_state_dict`）と、停止・状態の取得・復元の流れは決定済み。hook が例外を投げたらシステム全体を終了し、設定しておけばそのときの状態の木を取得することも決定済み。状態の保存はユーザーが行う。停止のタイムアウトの既定値、スロットを識別する名前の付け方、状態の取得・復元と例外のときの木の受け取りの API は未決定。関連: [ブロック](blocks.md#ライフサイクル-hook)、[実行モデル](execution-model.md#停止と状態の取得復元)
