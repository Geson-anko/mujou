# PyTorch の利用

ブロックの内側で PyTorch を使うときの方針と、そのための支援モジュール `mujou.torch` の仕様を定める。

> 状態: `mujou.torch` は未実装。コアの `Block` を実装してから作る。

## GPU の扱い

mujou のコアとメッセージは GPU をサポートしない。Tensor はホストのメモリにだけ置き（[メッセージ](messages.md#tensor)）、デバイス上の Tensor は持たない。外部ライブラリとの変換はコピーで行い、DLPack は使わない。

ブロックの内側で GPU を使うかどうかは、ブロックの自由である。GPU で計算するブロックは、ブロックの境界で device → host → device とコピーする。大きな行列の計算を CPU で行うと CPU を食い潰すので、それを GPU に逃がす手段は残しておく。

コアで GPU をサポートしない理由は次のとおり。

- Tensor をデバイス上に置くと、スロットにバッファと CUDA event の組を持たせることになる。ストリームをまたぐ同期、バッファの再利用の安全性、タイムスタンプの意味（公開した時刻か、計算が完了した時刻か）を、すべてコアが背負うことになる
- ストリームから 1 サンプルずつ学ぶ非同期のブロックでは、計算は小さな行列×ベクトル積の連続になり、もともと GPU の効率は出にくい

対象とするデバイスは CPU と CUDA である。Apple の MPS は対象にしない。

## ブロック間の独立性

境界でホストへコピーするなら、GPU を使うブロック同士は、正しさと実行順序の面で互いに影響しない。ただし、次の 3 つを守る必要がある。

1. ブロックごとに自分の CUDA ストリームを持つ。既定のストリームを共有すると、ホストへ書き出す前の同期が、ほかのブロックが積んだ仕事まで待つ
2. 同期は自分のストリームに対してだけ行う。デバイス全体を待つ `torch.cuda.synchronize()` は使わない
3. プロセス全体に効く設定や状態を、ブロックの中で変えない（[プロセス全体に効くもの](#プロセス全体に効くもの)）

GPU の演算器・メモリ帯域・PCIe の帯域・GPU メモリは、全ブロックで取り合う。これは CPU のコアの取り合いと同じで、各ブロックの $\Delta t$ の伸びとして連続時間の定式化が吸収する（[実行モデル](execution-model.md)）。

各ステップの終わりに自分のストリームを同期するので、CPU が GPU を追い越してカーネルを積み続けることはない。グローバルタイマーで測る $\Delta t$ と、実際に計算した時間がずれない。

## TorchBlock

`mujou.torch.TorchBlock` は、PyTorch を使うブロックの基底クラスである。`Block` を継承する。上の 3 つの条件と、mujou で要らない機能を切る設定を、ブロックの作者に代わって行う。PyTorch を使うブロックは、専用スレッドで実行する（[ネイティブコア](native-core.md#mn-スケジューリング)）。

### 実行スレッドの設定

`on_start` はブロックを実行するスレッドの上で呼ばれる（[ブロック](blocks.md#ライフサイクル-hook)）。TorchBlock は `on_start` で次を設定する。どれもスレッドごとの設定なので、ほかのブロックには影響しない。

| 設定 | 内容 | 理由 |
| --- | --- | --- |
| 勾配の記録を止める | `torch.set_grad_enabled(False)` | mujou の更新手法は更新式を直接計算するので、autograd のグラフは要らない |
| ストリーム | CUDA のときは自分の `torch.cuda.Stream` を作り、`torch.cuda.set_stream` でこのスレッドの現在のストリームにする | 以降の演算がすべて自分のストリームに積まれる |
| 乱数生成器 | ブロックごとの `torch.Generator` を、渡された seed で作る | 既定の乱数生成器はプロセス全体で共有されるので、テストが決定的でなくなる |

デバイスと seed は、TorchBlock の構築時に渡す。

### 境界の変換

TorchBlock は、Port から読んだ Tensor を torch のテンソルにする変換と、torch のテンソルを Tensor にして Port に書く変換を提供する。

- 読むとき: Tensor をコピーして、ブロックのデバイスへ送る
- 書くとき: 自分のストリームでホストへコピーし、自分のストリームだけを同期してから、Tensor を作る

転送に pinned memory を使うかどうかは、実装するときに測って決める。

### 状態

パラメータや活動は、`nn.Module` や `nn.Parameter` を使わず、`requires_grad=False` のただのテンソルとして持つ。状態はブロックの `state_dict()` / `load_state_dict()` で扱う（[ブロック](blocks.md#ライフサイクル-hook)）。

### ブロック内の BP

ブロックの内側で BP を行う場合は、その部分だけを `with torch.enable_grad():` で囲み、`# mujou: local-autograd` を付ける（skill `locality-and-async`）。ブロックをまたぐ `.backward()` は禁止のままである（[ブロック](blocks.md#bp-の取り込み)）。

既定で `torch.inference_mode()` は使わない。その中で作ったテンソルは backward に使えないので、スロットから来た入力を使うブロック内の BP がエラーになる。

## プロセス全体に効くもの

次の設定と状態はプロセス全体で共有されるので、ブロックの中で変えない。必要ならホスト（またはテスト）が実行の前に 1 回だけ設定する。

- `torch.manual_seed` と既定の乱数生成器
- `torch.set_num_threads`、`torch.use_deterministic_algorithms`、`torch.backends.*` のフラグ
- `torch.cuda.synchronize()`、`torch.cuda.empty_cache()` などデバイス全体に効く操作

CPU で計算する torch の演算は、呼び出したスレッドごとに内部でスレッドを立てる。ブロックの数と内部のスレッド数の積がコア数を大きく超えると、CPU を取り合って全体が遅くなる。内部のスレッド数は小さく設定しておく。

## 依存関係

コアは torch に依存しない。torch が要るのは `mujou.torch` を使うときだけである。
