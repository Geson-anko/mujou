# 概要

## mujou とは

`mujou` は **Asynchronous Distributed Deep Learning Library for Continuous Learning**。推論と学習を同時に行い、知能に「無常」（常が無いこと）を実現する、PyTorch のような深層学習フレームワークである。

名前は「諸行無常」の「無常」から取った。従来の機械学習は、学習を終えたら重みを固定して推論する。mujou はそうではなく、ストリームから学び続け、常に変化し続ける学習機械を作る。

## 狙う用途

- リアルタイム処理
- ロボティクス
- 生涯学習し続ける機械

## 全体像

- 計算は **ブロック** 単位で行う。ブロックの内側は同期的に計算し、ブロック同士は非同期にやり取りする（[ブロック](blocks.md)）
- ブロックの大きさはニューロン・レイヤー・スタック（複数レイヤー、モデル全体も可）から選べる。既定はレイヤー
- ブロック同士は、lock 付きの共有スロットへの値の読み書きだけで通信する。システム全体は、グローバルタイマーの上の連続時間系（微分方程式）として定義する（[実行モデル](execution-model.md)）
- コアは Rust で実装し、Python はインターフェースになる（[ネイティブコア](native-core.md)）
- 既定の更新手法は **PC-ALM**（Augmented Lagrangian Predictive Coding、<https://pub.sakana.ai/pc-alm/>）。ただし暫定的な選択であり、更新手法は差し替えられる（[更新手法](update-rules.md)）

## なぜ BP を基盤にしないか

誤差逆伝播法（BP）は、ネットワーク全体の forward と backward を同期させる必要がある。これは、継続的かつ非同期に学習することと相性が悪い。PC-ALM は局所的な更新で BP に近い性能を出せると報告されているため、既定の更新手法に選んだ。

なお BP を排除するわけではない。1 つのブロックの内側に閉じていれば、BP もそのブロックの更新手法として使える（[ブロック](blocks.md#bp-の取り込み)）。

## 設計判断の拠り所

設計で迷ったときは、次の 3 つを壊さない側を選ぶ。

1. **局所性**: ブロックは自分の状態と隣接ブロックの値だけで更新する
2. **非同期性**: ブロックは互いを待たない。グローバルなバリアを持たない
3. **止まらずに学び続けること**: 学習モードと推論モードを分けない。エポックを前提にしない

具体的な不変条件と禁止パターンは skill `locality-and-async` にまとめてある。
