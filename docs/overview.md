# 概要

## mujou とは

`mujou` は **Asynchronous Distributed Deep Learning Library for Continuous Learning**。推論と学習を同時に行い、知能に「無常」（常が無いこと）を実現する、PyTorch のような深層学習フレームワークである。

名前は「諸行無常」の「無常」から取った。従来の機械学習は、学習を終えたら重みを固定して推論する。mujou はそうではなく、ストリームから学び続け、常に変化し続ける学習機械を作る。狙う用途は、リアルタイム処理、ロボティクス、生涯学習し続ける機械である。

## 全体像

計算はノード単位で行う。ノードの内側は同期的に計算し、ノード同士は非同期にやり取りする。ノードの大きさは、どのノードのクラスを書くか、使うかで決まる。レイヤーが既定で、複数レイヤーやモデル全体を 1 ノードにしてもよい。ニューロン単位のノードは future work である（[ノード](nodes.md)）。ノードは分散処理の最小単位で、フレームワークが呼ぶライフサイクル hook を override して書く。

ノード同士は、lock 付きの共有スロットへ値を読み書きするだけで通信する。システム全体は、グローバルタイマーの上の連続時間系（微分方程式）として定義する（[実行モデル](execution-model.md)）。コアの責務は、各ノードを非同期・分散的に回すことと、非同期・分散的に学習するためのフレームワーク（PC-ALM）自体を提供することの 2 つである。ノードを回す基盤は Rust で実装し、Python はインターフェースになる（[ネイティブコア](native-core.md)）。PC-ALM は PyTorch で実装し、`mujou.pc` から公開する（[更新手法](update-rules.md#実装と公開元)）。

既定の更新手法は PC-ALM（Augmented Lagrangian Predictive Coding、<https://pub.sakana.ai/pc-alm/>）である。ただしこれは暫定的な選択で、更新手法は差し替えられる（[更新手法](update-rules.md)）。

## なぜ BP を基盤にしないか

誤差逆伝播法（BP）は、ネットワーク全体の forward と backward を同期させる必要がある。そのため、継続的かつ非同期に学習することと相性が悪い。PC-ALM は局所的な更新で BP に近い性能を出せると報告されているので、既定の更新手法に選んだ。

なお BP を排除するわけではない。1 つのノードの内側に閉じていれば、BP もそのノードの更新手法として使える（[ノード](nodes.md#bp-の取り込み)）。

## 設計判断の拠り所

設計で迷ったときは、次の 3 つを壊さない側を選ぶ。

1. 局所性: ノードは自分の状態と隣接ノードの値だけで更新する
2. 非同期性: ノードは互いを待たない。グローバルなバリアを持たない（状態の取得などのための停止だけは例外。グローバル時間も止まる。[実行モデル](execution-model.md#グローバルなバリアとの関係)）
3. 止まらずに学び続けること: 学習モードと推論モードを分けない。エポックを前提にしない

具体的な不変条件と禁止パターンは skill `locality-and-async` にまとめてある。
