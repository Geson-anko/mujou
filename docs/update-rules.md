# 更新手法

## 差し替え可能にする

- フレームワークは、PC-ALM 以外の更新手法も与えられるようにする。**更新手法を差し替えられることは重要な要件である**
- mujou の本質は「推論と学習が同時に行われ、知能に『無常』を実現する」ことにある。特定の学習則は、それを実現する手段のひとつに過ぎない
- 継続的に変化し続ける知能を実現する手段は PC-ALM に限らない。学習則をフレームワークに焼き付けると、将来よりよい手法が出てきたときに差し替えられない

## 基盤と更新手法の分離

- ブロックという実行の基盤と、更新手法の実装を分離する。ブロック・スロット・スケジューラは、特定の学習則を前提にしない
- PC-ALM 固有の状態（双対変数 $\lambda$ など）や、やり取りする値の中身（$W^\top \varepsilon$ など）は、PC-ALM の更新手法の側に閉じ込める。基盤の型や API に直接書き込まない
- 不変条件はブロックの間に課す。ブロックの内側の更新手法は自由に選べる。BP のような非局所的な手法も、1 つのブロックの内側に閉じていれば取り込める（[ブロック](blocks.md#bp-の取り込み)）

## 既定の更新手法: PC-ALM

### 位置づけ

PC-ALM は、**現時点の既定の更新手法として暫定的に** 採用したものであり、mujou の本質ではない。局所的な更新で BP に近い性能を出せると報告されていることが、既定に選んだ理由である。

- 出典: Sakana AI, "PC-ALM: Augmented Lagrangian Predictive Coding" <https://pub.sakana.ai/pc-alm/>
- 式・平衡点の性質・ハイパーパラメータ・実装上の落とし穴は skill `pc-alm` にまとめてある

### 検証済みの事項

skill `pc-alm` の 1〜6 節は、記事の定義を勾配まで展開したものである。2026-10-11 に次を数値で確認した。

- 勾配式が有限差分と一致する（tanh、4 層、誤差 3e-9）
- 不動点で、重みの更新が BP の勾配と一致する。非線形でも成立する。ただし不動点への収束が保証されるのは線形の場合だけである

### 記事が触れていない点

- 双対変数の初期化・リセット方針
- 非同期スケジューリング
- ペナルティ係数の調整（記事では ½ に固定）

### PC-ALM の連続時間形

> この節は記事の範囲外であり、mujou の研究課題である。確立した理論ではなく、仮説として扱う。

mujou のブロックは独自の周期で非同期に動く（[実行モデル](execution-model.md)）。そのため記事の離散更新を、グローバルな時間 $t$ に対する微分方程式として扱い直す。時定数 $\tau_h, \tau_\lambda, \tau_\theta$ を導入する。

$$\tau_h \frac{dh_i}{dt} = -\nabla_{h_i}\mathcal{L}, \qquad \tau_\lambda \frac{d\lambda_i}{dt} = r_i, \qquad \tau_\theta \frac{dW_i}{dt} = \varepsilon_i\, h_{i-1}^\top$$

（出力層の重みは $e_L h_{L-1}^\top$ で更新する。記号の定義は skill `pc-alm` を参照）

- 活動は拡張ラグランジアンの勾配流、双対変数はその上昇流、重みは勾配流に従う。入力 $x(t)$ と教師 $y(t)$ は時間とともに変わるストリームとして与える
- 陽的 Euler 法で離散化すると $h_i \leftarrow h_i - \frac{\Delta t}{\tau_h}\nabla_{h_i}\mathcal{L}$ となる
- 離散パラメータとの対応は $\eta_h = \Delta t/\tau_h$、$\alpha = \Delta t/\tau_\lambda$、$\eta_\theta = \Delta t/\tau_\theta$。全ブロックを固定の $\Delta t$ で同期的に回すと、記事の離散更新に一致する（テストのオラクル）
- 記事の「推論 $T$ ステップ → 学習 1 ステップ」は、$\tau_\theta \gg T\,\tau_h$ という時間スケールの分離として近似する。フェーズの切り替えは持たず、推論と学習は同時に進む
- 陽的 Euler 法は $\Delta t/\tau$ が大きいと発散する。記事の $\alpha$ の上限は $\Delta t/\tau_\lambda$ の上限として読み替える。ブロックが遅れて $\Delta t$ が大きくなる場合に備え、$\Delta t$ の上限か刻みの分割を持つ

### 未解決の問い

- 時定数どうしの比の選び方
- 各ブロックが隣接ブロックの古い値で更新しても収束・安定するか。$\Delta t$ の揺らぎ・遅延と $\alpha$ の関係
- 非定常なストリームで $\lambda$ を持ち越す（warm start）か、dual leak で忘却させるか
- ラベルの無いステップ（自己教師・予測タスク）で出力側をどう扱うか
- 時間方向の credit assignment
