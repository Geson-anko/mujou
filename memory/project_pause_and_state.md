2026-10-14 決定。詳細は `docs/execution-model.md` の停止と状態の保存・復元の節。参考は pamiq-core の `ThreadController` / `StateStore`。

- **停止:** 停止要求フラグを立て、続けてすぐにグローバルタイマーを時刻 T で凍結する → 各ブロックは実行中の `on_update` を終え、ループの区切りで止まって `on_pause()` → スケジューラが全ブロックの停止を確認 → 制御側が全状態を lock なしで読む
- **pamiq-core と順序が逆。** pamiq は全スレッド停止後にタイマーを止めるが、mujou では先に凍結する。待ってから凍結すると、早く止まったブロックの待ち時間が再開後の Δt に混ざる。凍結後は全ブロックの最後の更新時刻と全スロットの時刻が T 以下になり、時刻 T の一貫したスナップショットになる
- **再開:** タイマーを再開し、続けてすぐにフラグを下ろす（最初の Δt が 0 にならない）。各ブロックは `on_resume()` の後に `on_update` へ進む
- **保存対象:** ブロックの `state_dict()`、全スロットの最新値と時刻（ホストの入力スロットも）、各ブロックの最後の更新時刻、グローバルタイマー。フレームワークが 1 つの木にまとめて pickle する。ブロックはネットワーク木の属性パス（`body.l1`）で識別。バッファプールは保存しない
- **スロットも保存する理由:** 系の状態はブロック状態 + スロットの中身。スロットを初期値に戻すと再開直後に平衡から外れる
- **復元:** 構築 → `on_start()` → `load_state_dict()` → スロット・最後の更新時刻・タイマーを戻し、時刻 T から開始
- **タイムアウト:** 停止が時間内に終わらなければ保存を中止し、止まらなかったブロックをログに出す

**Why（バリアの例外）:** 停止はシステム全体のバリアだが、停止中はグローバル時間が進まないので、系のダイナミクスからは存在しないのと同じ。ユーザーが提案し、2026-10-14 に例外として認めた。

**How to apply:** 停止を使ってよいのは保存・復元・観測などの制御のための操作だけ。定期的に止めて重みを平均するなど、停止を学習アルゴリズムの一部に使う実装は不変条件違反として扱う。タイムアウトの既定値・保存ファイルの置き場所と命名・スロットの識別名は未決定（[[project-open-decisions]]）。
