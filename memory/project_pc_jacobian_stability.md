2026-10-24〜26、`examples/cifar10/` で測った（記録は `memory/agents/orchestrator/cifar10-resnet-example.md`）。

- `h` の緩和の線形化は `-(I + J^T J)/τ_h`（J は次のノードのモジュールのヤコビアン）。Δt = τ_h/4 の陽的 Euler では `1 + σ² < 8`、σ < 約 2.65。遅れや古い値では 1.2〜1.8
- ResNet-20（GroupNorm）を BP で学習すると、ブロックの σ は 2〜9（block2 で J^T J の最大固有値 77、block3 31）、3 ブロックのステージは 5〜12。固定刻みの緩和は、BP の重みでは λ が発散（cos 0〜0.2）、PC で 3 epoch 学習した重みでは最初の 5 ノードで cos 0.5〜0.7（比 1.8〜2.0）のまま、後ろの 4 ノードは 0.8 以上
- **それでも学べる**（2026-10-26 訂正）: 以前は「ブロックやステージごとのノードは発散する」と書いたが、PC 自身が学習する間は発散せず、遅延なしの手動実行では 3 epoch で BP と同じ（53.45% / 53.65%）。非同期・倍率 1.0 でブロックごとの 11 ノードは、1 バッチを S=128 周期見せれば 3 epoch で BP に近い（prequential 50〜52.5% / BP 53〜54%）。S=64 では遅れた（43% / 53%）。サンプルが 10 ホップ進むのに約 12 周期かかり、実効の緩和時間が減るため。10 epoch では PC が BP に約 4 ポイント遅れる（main.py の既定: prequential 68.73% / 73.27%、test 68.95% / 72.61%。S=64 では 51% / 72% で大きく遅れた）
- ノードの更新は B=1 でも 128 でも約 1.2 ms（CPU 律速）。倍率 1.0 で追いつく周期は約 5 ms（τ_h=20 ms、ワーカー 11 本で 99% 点 2 周期以内）。τ_h=12 ms・8 ワーカーは追いつかない
- **AdaptiveStep（却下）**: 次のノードの J^T J の最大固有値 c をサンプルごとにべき乗法（二重 backward）で見積もり、前のノードへ別ポートで送り、h と λ の刻みを dt·min(1, margin·τ_h/(dt(1+c))) に縮める案を実装して試した。凍結した重みでは λ が BP の credit に収束（cos 0.97〜0.99、固定刻みは 0.5）。しかし学習では悪化: 600 バッチの test が固定 46.5%、下限 0.25 で 42.2%、0.1 で 27.9%、下限なしで 19.6%（BP 47.8%）。縮めた行は前のバッチの λ を長く引きずり、学習中の credit が崩れる（cos 0）。非同期でも崩れた。べき乗法の見積もりは 20 ステップでも 10〜20% 低い。コードは戻した
- 2 ノード（stage1+2 / stage3+head）は次が Output で CE の曲率が掛かり、σ(stage3∘head) が 1.2〜2.0 で安定。10 epoch で BP と並ぶ（74.0% / 73.3%）

**Why:** 更新手法が「どこでノードを切れるか」と「1 サンプルに何周期要るか」を制約する。ノードの粒度はクラスで決まる（[[project-compute-granularity]]）。

**How to apply:**

- ノードを細かく切るときは、1 バッチを見せる周期 S をノード数に比例して増やす（目安: ホップ数の 10 倍以上）。倍率 1.0 で追いつく周期は測る
- 長く学ぶと credit が落ちる。精度が要るなら次のノードのヤコビアンが小さいところで切る
- 刻みを縮める方向（AdaptiveStep）は試して悪かった。やるなら前のバッチの λ を捨てる仕組み（行ごとのリセット）と一緒に考える。src の pc の変更はユーザーに確認する
- 関連: [[project-pc-module]], [[reference-pc-alm]], [[project-gpu-policy]]

**2026-10-26 追記（h の慣性を採用。のちに `pc.HeavyBall` に載せ替え、[[project-pc-relaxer]]）**

- 最初は `TimeConstants.momentum`、いまは `Layer(relaxer=pc.HeavyBall(tau=...))`: h の heavy ball。`v <- exp(-dt/tau) v + (r+λ+g)`、`h -= dt/τ_h v`、新しいサンプルか h_in の跳びで v を 0 に（`reset_`）。不動点は不変、局所、メッセージは増えない。状態は `Layer.relaxer` の `velocity`
- 効果: ResNet の 11 ノード・実時間で、64 周期 + `HeavyBall(tau=τ_h/4)` が 3 epoch 目で慣性なしの 128 周期と並ぶ（実時間は半分）。10 epoch では 62.8%（128 周期・慣性なしは 68.7%、BP は 73.3%）。128 周期に足しても変わらない。`τ_h/3` は 3 回に 1 回崩れた。1 更新あたりの係数 0.8 は発散、32 周期は学べない
- algorithm-reviewer（承認）: 線形の鎖の安定境界は 0.78（実測と一致）、非同期のジッタで約 0.75。速くなるのは過渡だけで、漸近の速さは良くならない。力の重みは dt に比例しない（周期に依存）
- 却下: AdaptiveStep、新しいサンプルで λ と r を捨てる設定（prequential が 27% のまま）

**2026-10-27 追記（周期 τ_h/16 と r の減衰。正本は specs/pc.md「ResNet のブロックごとのノード」）**

- 問題 1（σ）は離散化が原因と確定: 凍結した重みの同期の緩和で τ_h/4 は cos 0.06〜0.3、τ_h/16 と τ_h/64 は 0.95〜0.99。上の「BP の重みで λ が発散」「PC の重みで cos 0.5〜0.7」は τ_h/4 の話
- τ_h/4 で学ぶとブロックの σ が 1.0〜1.7 にとどまる（学びが少ない）。τ_h/16 では BP 並みに育つ
- 採った構成: 周期 τ_h/16（max_dt 2 周期）、τ_λ=τ_h/4、新設の `TimeConstants.r` = τ_h/3、24 τ_h（384 周期）、学習 0.9、time scale 0.25。10 epoch で例が 73.35% / 73.79%、別の実行が 71.56% / 71.41%（BP 73.27% / 72.61%）
- 残差の枝を小さく始める案は不採用（AdamW で GroupNorm の γ が育ち σ は下がらず、BP も 72.6% → 69% に下がった）
- 未解明: 非同期で λ をリセットすると遅れる、PC の head の重みが BP の 20 倍以上に育つ（specs/open-decisions.md）
