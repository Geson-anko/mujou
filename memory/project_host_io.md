2026-10-14 決定（暫定）。ユーザーが方針（バックグラウンド実行、run 前の初期値書き込み、複数 Port の同時書き込み、read と subscribe）を決め、細部はユーザーの指示で Claude が暫定案として考案した。詳細は `docs/network.md` のネットワークの入力と出力の節。

- **2026-10-16 に実装（名前は推奨案、ユーザー確認待ち）。** `mujou.run(network)` は未 build なら build して run し、同じ network を返す。`run()` は全ノードの `on_start`（と復元）が終わり、タイマーが動き出してから戻る（起動中の例外を `run()` が送出するため。当初の「すぐ戻る」から変更）。`state_dict()` は実行中だけ（run 前・正常終了後は `RuntimeError`、例外終了後は `NetworkError`）。`subscribe` は呼んだ後に書かれた値だけを返す。`send_to` だけの Port の `read` は初期値を返す。詳細は `docs/network.md` の実装の節
- **`run()` は常にバックグラウンドで実行する（ユーザーの決定）。** ホストは公開インターフェイスだけでやり取りする。インターフェイスは `build()` を呼んだルートのインスタンスが持つ（インスタンスが定義と実行を兼ねる方針、[[project-node-lifecycle]]）
- **操作:** `build()`、`write(...)`、`load_state_dict(state)`（run 前）、`run()`、`read(port)`、`subscribe(port)`、`state_dict()`、`shutdown()`、`join()`
- **paused 起動は持たない。run 前に `write` した値がそのスロットの初期値になる（ユーザーの決定）。** `load_state_dict` の後に書いた値が優先
- **書く値・読む値は `torch.Tensor`（2026-10-15）。** `read` / `subscribe` は CPU 上の値を返す。`write` は値を `detach()` し、GPU 上の値はホストへコピーしてから受け取る（[[project-message-types]]）
- **入力はグローバル時間上の信号（ユーザー了承）。** スロットは最新値なので sample-and-hold。データセットでは提示時間をユーザーが決め、ホストはグローバル時間で待つ（`mujou.time.sleep`、名前は暫定）。速くしたいときはタイマーを加速
- **複数 Port への同時書き込みは必要（ユーザーの決定）。** 1 回の `write` の値はどのノードからも一斉に切り替わり、同じ時刻が付く。暫定の方式は版番号: ネットワークが atomic な版番号 V を持ち、外から書けるスロットは「現在の値 + 版番号付きの次の値」を持つ。write は次の値（版 V+1）を全部置いてから V を進める。読み手は次の値の版が V 以下なら次の値を読む。書き手も読み手も待たない。停止してから書く方式は、書くたびに最も遅い `on_update` を待つので採らない
- **読み出しは `read`（最新値と時刻）と `subscribe`（新しい値ごとに最新値を返すイテレータ）（ユーザーの決定）。** 消費者だけが待ち、書き手は通知するだけ。途中の値は飛ばす。正常終了でイテレータが終わる。`subscribe` は呼んだ時点の最新値を最初に 1 つ待たずに返し、その後は新しい値ごとに返す（2026-10-16、ユーザーの決定）
- **持たないもの:** 書き込みごとのコールバック（消費者の遅さが書き手に伝わる）、全値の記録（future work）、外部プロセスへの転送（ユーザーがホストのスレッドか出力ノードで書く）、サンプル ID の伝搬（全ノードに負担）。入力と出力の対応は提示時間の終わりに読んで取る

**Why:** 外の消費者や生産者の速さがノードの歩調に影響しないこと（非同期性）を、入出力の境界でも守るため。

**How to apply:** 実装中に問題が出たら見直してよい暫定案として扱い、変える場合はユーザーに確認する。名前は推奨案で実装済みで、ユーザー確認待ち。
