2026-10-19、`on_thread_start` を廃止するときに「サブクラスが定義していたら TypeError で案内する」と提案したところ、ユーザーが「まだ pypi 等に正式に公開してないので、単に消して良い」と指示した。

同日、続けて「破壊的変更で互換のために実装した機能があれば、複雑さを減少させるためにすべて廃止して」と指示され、既存の互換の仕組みを洗い出して消した（ブランチ refactor/2026-10-19/drop-compat-shims）。

**Why:** 公開前は利用者がいないので、互換のための検査や移行の案内はコードを増やすだけになる。

**How to apply:** 正式公開（PyPI へのリリース）までは、API を消すとき・名前を変えるときに、古い名前を検出するコードや deprecation の警告を足さない。docs・specs・テストからも古い名前を消すだけにする。公開した後は改めて方針を確かめる。
