# docs/network.md 理解度テスト

## 対象

- ファイル: `docs/network.md`（主に「ネットワークの入力と出力」の書き込み・読み出しと「実装」の節）
- 読者と用途: mujou の開発者と利用者。この文書だけを読んで、ネットワークの宣言・接続・実行・ホストからの読み書きの仕組みと制約（一斉切り替えの保証範囲、スロット名、hook から呼べないもの、復元の制約、終了の扱い）を正しく説明できる。
- 根拠: `src/mujou/_session.py`・`_network.py`・`_port.py`、`crates/mujou-core/src/slot.rs`（`InputGroup`・スロット名）、`crates/mujou-core/src/runtime.rs`（`freeze_for_startup` の復元時の `InvalidArgument`）

## 評価用問題

### Q1 ノードの `on_update` の中から `net.write(...)` を呼んで、ネットワークの別の Port に値を流したい。できるか。できないなら、代わりにどう書くか。

- 要点: できない（`RuntimeError`）
- 要点: ノードは自分の Port（`send`）だけでやり取りする。外との橋渡しはホストのスレッドか I/O のノードとして書く

### Q2 ホストが `net.write({net.prev: x, net.teacher: y})` を繰り返し呼んでいる。ノードが 1 回の `on_update` の中で prev を `recv` し、続けて teacher を `recv` した。2 つの値が別々の `write` に由来することはあるか。あるなら、ノードはどう見分けるか。

- 要点: ある（2 つの読みの間に次の `write` が終わることがある）
- 要点: `recv_with_time` の時刻を比べる。同じ `write` の値には同じ時刻が付く

### Q3 ルートの属性 `body` の中の属性 `l1` にあるノードが、送る型と受ける型の両方を持つ `NextPort` を属性 `next` に持ち、Channel 2 本に接続されている。状態の木の `"slots"` に、この Port のスロットとして現れるキーをすべて答えよ。

- 要点: `"body.l1.next/out"`、`"body.l1.next/ch0"`、`"body.l1.next/ch1"`
- 要点: 接続済みなので `/in` は無い

### Q4 `state_dict()` で保存した木を、ノードの属性名を `l1` から `layer1` に変えただけの同じ構造のネットワークに `load_state_dict` した。どうなるか。理由も答えよ。

- 要点: `ValueError`
- 要点: ノードのパスとスロット名が木と一致しなければならず、属性名を変えるとそれらが変わる

### Q5 保存した木から復元し、最初の入力を復元した時刻 T のものとして与えたい。`load_state_dict`・`write`・`run` をどの順に呼ぶか。また、`load_state_dict` より前に `write` した値はどうなるか。

- 要点: `load_state_dict` → `write` → `run`（その `write` の値に時刻 T が付く）
- 要点: 前に書いた値は木の値で置き換わる

### Q6 あるノードは Port の値を `send_to(channel, msg)` だけで送っている。ホストがこの Port を `net.read(port)` で読むと、どんな値が返るか。理由も答えよ。

- 要点: 初期値（ゼロ。復元したなら木の値）
- 要点: `read` は外向きのスロットを読み、外向きのスロットを更新するのは `send` だけ

### Q7 ホストは次の 2 つの Port に `write` できるか。(a) ルートが属性として公開していない内側のノードの、未接続で相手 1 つで受ける型を持つ `PrevPort`。(b) 未接続の `NextPort`（既定の宣言、受ける型あり）。

- 要点: (a) 書ける（木の中の Port なら公開していなくてよい）
- 要点: (b) 書けない（`NextPort` は既定で相手を複数取る → `ValueError`）

### Q8 あるノードの `on_update` が例外を投げてネットワークが止まった後、ホストが `net.read(port)` を呼んだ。何が起きるか。ノードが投げた元の例外はどこから取れるか。

- 要点: `NetworkError` が送出される
- 要点: `__cause__` が最初にノードが投げた例外

### Q9 ホストのプログラムが、`subscribe` を回すスレッドを残したまま、`shutdown()` を呼ばずにメインの処理を終えた。プロセスは終われるか。ネットワークはいつ止まるか。

- 要点: 終われる
- 要点: インタプリタの終了時（non-daemon スレッドの join より前）にフレームワークが終了させて `on_stop` を待ち、イテレータが終わる

### Q10 独立した 2 つのネットワーク `net1` と `net2` に、ホストが続けて `write` した。2 つの書き込みが、ノードから見て一斉に切り替わると期待してよいか。理由も答えよ。

- 要点: 期待してはいけない
- 要点: 版番号はネットワークごとに 1 つで、一斉の切り替えは同じネットワークの中だけ

### Q11 `net.read(port)` が返す時刻と、ノードの `recv_with_time()` が返す時刻の単位をそれぞれ答えよ。

- 要点: `read` は秒（`time_ns / 1e9`）
- 要点: `recv_with_time` はナノ秒

## 保留問題

### H1 ネットワークが正常に終了した後、ホストが `state_dict()` を呼んだ。どうなるか。

- 要点: `RuntimeError`（実行中だけ呼べる）

### H2 ネットワーク `net1` が走っている同じプロセスで、保存した木から `net2` を `load_state_dict` して `run()` した。どうなるか。どう対処するか。

- 要点: `run()` が `ValueError` になり、何も起動しない
- 要点: `net1` を終了させてから `net2.run()` をやり直す

### H3 ホストのスレッドから中間層のノードの Port の `recv()` を直接呼んで、その値を観測したい。できるか。できないなら、代わりに何を使うか。

- 要点: できない（所有ノードのスレッドだけが呼べる、`RuntimeError`）
- 要点: `net.read(port)`（送る型を持つ Port の外向きの値）を使う
