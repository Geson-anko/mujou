# docs/ja のホーム・はじめに・サンプル 理解度テスト

## 対象

- ファイル（`docs/ja/` 配下）: `index.md`、`getting-started/index.md`・`installation.md`・`quickstart.md`、`examples/index.md`。生徒は加えて `examples/quickstart.py` を読む
- 読者と用途: mujou を初めて触る利用者（Python と PyTorch は使える）。これらのページだけで mujou が何かを理解し、インストールし、最初のネットワークを走らせて出力を読み、サンプルの一覧から目的のサンプルを選ぶ

## 確かめた事実（R1）

- `examples/quickstart.py` を実行して `y = tensor([3., 5., 7.]) at t = 0.106 s` を得た
- `mujou.__version__` は `0.0.1`。`rust-version = "1.85"`（Cargo.toml）。`.python-version` は `3.14t`
- Linux の CPU 版 torch は `[tool.uv.sources]` によるもので、ソースからの `uv sync` だけに効く（PyPI 経由では利用者の index による）
- グローバル時間はプロセスが初めて使った時点で 0（`mujou/time.py` の docstring）
- `recv` は待たず最新値、未着ならゼロ。`Run.read` は送った値と時刻。`mujou.run` は全ノードの `on_start` 後に戻る
- `super().__init__()` は任意で、呼ばないと周期なし（全力で回る）
- `uv run python examples/leaky_chain/main.py` はルートから動く（スクリプトのディレクトリが sys.path に入る）
- 見出し `## ソースからビルドする` の id は `_3` になる（toc の slugify が日本語を落とす）。日本語見出しへのアンカーリンクは使わない
- 近く入る API（`Run.write` が時刻を返す、`mujou.run(node)`）には本文では触れていない

## 評価用問題

### Q1 mujou をいますぐ自分のマシンに入れたい。PyPI から入れる方法とソースからビルドする方法のどちらを使うか。理由も答えよ。

- 要点: ソースからビルドする
- 要点: PyPI にはまだ公開していないため

### Q2 ソースからビルドする前に、Python のほかに用意しておくツールを 2 つ答えよ。

- 要点: Rust のツールチェーン（rustup で入れる、1.85 以上）
- 要点: uv

### Q3 手元に GIL ありの通常版 Python 3.14 しかない。mujou は使えるか。ソースから入れる場合、環境を作るコマンドは何か。

- 要点: 使える（free-threaded 版 3.14t が推奨だが通常版でも動く）
- 要点: `uv sync --python 3.14`

### Q4 Linux でソースからビルドした。ノードの中で GPU を使いたい。何をする必要があるか。理由も答えよ。

- 要点: PyTorch を CUDA 版に入れ替える
- 要点: Linux の `uv sync` は CPU 版の PyTorch を入れるため

### Q5 クイックスタートのプログラムで、`mujou.time.sleep(0.1)` の行を消し、`write` の直後に `read` した。`y` は必ず `[3., 5., 7.]` になるか。理由も答えよ。

- 要点: ならないことがある
- 要点: 書いた値が scale と shift を通って届くまで時間がかかり、届く前の shift は前の入力（最初はゼロ）から計算した値を送っている

### Q6 ホストのプログラムで、ある入力を 0.5 秒間ネットワークに見せたい。標準ライブラリの `time.sleep(0.5)` で待ってよいか。使うべきものと理由を答えよ。

- 要点: よくない。`mujou.time.sleep(0.5)` を使う
- 要点: mujou のグローバル時間で待つので、時間の速さを変えたときや一時停止に合う

### Q7 クイックスタートの出力 `y = tensor([3., 5., 7.]) at t = 0.106 s` の `t` は何を表すか。何を 0 とした時刻か。

- 要点: shift（出力の Port）が `y` を送った時刻（グローバル時間、秒）
- 要点: プロセスがグローバル時間を初めて使った時点を 0 とする

### Q8 自分のノードで、前のノードから新しい値が届くまで `on_update` の中で `while` ループを回して待つように書きたい。そう書いてよいか。理由も答えよ。

- 要点: よくない（ループを書かない）
- 要点: ループは mujou が回し、`on_update` には 1 回分の処理を書く。`recv` は待たずに最新の値を返す

### Q9 クイックスタートと同じ書き方のノードを走らせたら、CPU のコアが 1 つ使い切られた。原因と、一定間隔で更新させる直し方を答えよ。

- 要点: 原因はノードに実行周期が無いこと（待たずに `on_update` を繰り返す）
- 要点: `__init__` で `super().__init__(period=秒)` を渡す

### Q10 走っている途中でノードの 1 つが例外を投げた。その後ホストで `run.read(...)` を呼ぶと何が起きるか。ノードが投げた元の例外はどこで分かるか。

- 要点: `mujou.NetworkError` が送出される（ネットワーク全体が止まっている）
- 要点: その `__cause__` が元の例外

### Q11 学習させた状態を保存して、後日その続きから走らせるプログラムを書きたい。どのサンプルを見るか。そのサンプルで状態を取るメソッドと、復元に使う引数も答えよ。

- 要点: `save_and_restore.py`
- 要点: `run.state_dict()` で取り、`mujou.run(..., state=...)` で復元する

### Q12 自作ノードを、毎回同じ結果が出るように決まった `dt` で動かしてテストしたい。どのサンプルを見るか。どのモジュールの何を使うか。

- 要点: `testing_a_node.py`
- 要点: `mujou.testing` の仮想タイマー（と手動の更新）

### Q13 mujou のネットワークで、学習を終えたあと推論モードに切り替えるにはどうするか。

- 要点: 切り替えるモードは無い
- 要点: ネットワークは走っている間ずっと入力を受けて出力を出し、同時に学び続ける
