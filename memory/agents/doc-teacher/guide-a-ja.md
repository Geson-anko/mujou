# docs/ja/user-guide（index・writing-a-node・building-a-network・running・compose）理解度テスト

## 対象

- ファイル: `docs/ja/user-guide/index.md`、`writing-a-node.md`、`building-a-network.md`、`running.md`、`compose.md`
- 取り込むサンプル（生徒も読む）: `examples/leaky_chain/leaky.py`、`examples/quickstart.py`、`examples/branching.py`、`examples/subscribe.py`、`examples/compose.py`
- 読者と用途: Concepts の章を読んだ利用者が、自分のノードのクラスを書き（Port、hook、`dt` に比例した更新、`period`、状態の確保）、ネットワークに組み（接続、分岐と合流、入れ子、公開する Port）、`mujou.run` で走らせてホストから読み書きし（`inputs`・`write`・`read`・`subscribe`・`shutdown`/`join`・with 文・`Timestamp`）、`Compose` で束ねる

## 前提にした近く入る API（別ブランチ）

- `Run.write` が書いた時刻（`Timestamp`）を返す
- `mujou.run(node)` がノード 1 つを受け付ける（単独のノードのパスは未確認なので書いていない）

## 確かめたこと

- `period=0.01` のノードが 0.5 秒で約 50 回更新する。ネットワークの入れ子で `graph.nodes` が `body.c`、`head`、公開した `Port` の `port_path` が持ち主の名前（`head.teacher`）
- `connect` が返す `Channel` をノードの属性に代入し、`send_to` で送り分けられる（building-a-network の `RoutedSplit` の例を branching.py の定義と合わせて実行した）。`send_to` だけの Port の `Run.read` はゼロ
- 日本語の見出しのアンカー（`#分岐と合流`）は toc の既定の slugify で `_1` などになり、リンクが切れる。ページ内アンカーへのリンクは使わず「〜の「分岐と合流」」と書いた

## 評価用問題

### Q1 センサーの値を 20 ms に 1 回だけ読むノードを書きたい。実行の周期をどこでどう指定するか。クラス属性 `period = 0.02` で既定値を置いてよいか

- 要点: `__init__` で `super().__init__(period=0.02)` を呼ぶ
- 要点: クラス属性で置いてはいけない。実行の開始で `TypeError` になる

### Q2 `period=0.01` のノードの `on_update(dt)` で、`dt` の代わりに定数 0.01 を掛けて更新してよいか。理由も

- 要点: よくない。`dt` は実際の経過時間で、`period` ちょうどにはならない
- 要点: 遅れると `period` より長く、その次は短くなる。周期があっても `dt` に比例して更新する

### Q3 `period=0.01` のノードが、ある更新で目標より 35 ms 遅れた。遅れを取り戻すために続けて何回か更新されるか。次の目標はどう決まるか

- 要点: 続けて何回も更新されない。1 回だけ更新する
- 要点: その更新から数え直す（`period` 以上遅れたとき）

### Q4 マシンが混んで `dt` が大きくなると更新が発散しそうだ。`on_update` の先頭で `dt = min(dt, 0.01)` と切り捨ててよいか。代わりにどうするか

- 要点: 切り捨てない。切り捨てた分の経過時間が失われ、連続時間の解からずれる
- 要点: 1 回の `on_update` の中で刻みを分割する（`dt` を n 個に分けて n 回更新）

### Q5 ノードの状態 `w` を `on_start` で作り、`on_update` で `self.w = self.w + dt * g` と書いた。どう直すべきか。理由も

- 要点: その場で更新する（`self.w += dt * g` や `copy_`）
- 要点: 代入し直すとエラーにはならないが、ほかの場所（optimizer や別の属性）からの参照が古いテンソルを指したまま残り、更新が届かない（R1 で改訂。旧要点「復元で on_start のテンソルに書き戻すから」は理由として不正確だった。R1 の採点は旧要点で行った）

### Q6 ノードの初期化を再現できるようにしたい。ノードの `on_start` で `torch.manual_seed(0)` を呼んでよいか。代わりにどうするか

- 要点: 呼ばない。全ノードが共有する乱数生成器を変えてしまう
- 要点: `super().__init__(seed=0)` で渡し、`self.generator` から乱数を引く

### Q7 分岐で、1 つの `NextPort` から 2 つの相手へ別々の値を `send_to` で送る。送り先の `Channel` をどうやって手に入れるのが安全か。`self.next.channels` の並びを使う方法の問題は何か

- 要点: ネットワークで `connect` が返す `Channel` を、送る側のノードの属性に代入して渡す
- 要点: `channels` はつないだ順に並ぶので、`connect` を書く順を変えると送り先が黙って入れ替わる

### Q8 `branching.py` の `Diamond` を走らせ、ホストが `run.read(net.split.next)` を読んだ。何が返るか。各枝に送られた値を見たいときはどこを読むか

- 要点: 初期値（ゼロ）が返る。`send_to` は `Run.read` の値を更新しない
- 要点: 受け取る側のノードの Port（例: `net.double.next`、`net.square.next`、あるいは受け手の出力）を読む

### Q9 `PrevPort(multi=True)` の `recv()` は何を返すか。どの相手もまだ送っていない Channel の値は何か

- 要点: `Channel` をキーにした dict を、つないだ順に返す
- 要点: まだ送っていない Channel の値はゼロ

### Q10 building-a-network の `Classifier` の例で、ノード `l2` のパスは何か。後で属性名 `body` を `trunk` に変えたら、変える前に保存した状態から復元できるか

- 要点: `"body.l2"`
- 要点: できない。パスが変わるから

### Q11 最初の `on_update` から入力 `x0` を見せたい。どう渡すか。`mujou.run(net)` の直後に `run.write({net.prev: x0})` とするのでは何が違うか

- 要点: `mujou.run(net, inputs={net.prev: x0})` で渡す
- 要点: `mujou.run` が戻った時点でノードはすでに回っており、`write` までの間はゼロ（入力の初期値）を読んで更新してしまう

### Q12 入力 `x` を順に見せ、各 `x` に対する出力を記録したい。`write`・待つ・`read` をどの順にするか。`write` の直後に `read` してはいけないのはなぜか

- 要点: `write` → 見せる時間だけ `mujou.time.sleep` で待つ → `read`（見せ終わる時点の出力を応答とみなす）
- 要点: 出力は遅れて追いつくので、直後に読むと前の入力に対する出力が返る

### Q13 入力と教師信号を同時に切り替えたい。`run.write({net.prev: x})` と `run.write({net.teacher: y})` の 2 回に分けてよいか。理由も（R1 で「理由も」を足した）

- 要点: 1 回の `write` にまとめる（`run.write({net.prev: x, net.teacher: y})`）
- 要点: 1 回の `write` で書いた値は同時に切り替わる。分けると、ノードが片方だけ新しい値を読むことがある

### Q14 グローバルタイマーで走らせている実行で、入力を 0.1 秒見せるために標準の `time.sleep(0.1)` を使ってよいか。何を使うか。理由も（R1 で「理由も」を足した）

- 要点: 使わない。`mujou.time.sleep(0.1)` を使う
- 要点: 標準の `time.sleep` は実時間で待つので、時間の速さの変更と、状態の取得による停止に合わない

### Q15 ロボットを制御するネットワーク A と、別のネットワーク B を同じプロセスで動かす。B の状態を定期的に取るとき、A を止めたくない。A と B をどう走らせるか（2 つは Port でつながっていない）

- 要点: 束ねず（`Compose` や `mujou.run(a, b)` にせず）、別々の実行にする
- 要点: それぞれに別の `mujou.time.Timer()` を `timer=` で渡す。渡さないと両方がグローバルタイマーを共有し、B の状態の取得で A の時間も止まる

## 保留問題

### H1 `run.subscribe(net.next)` を `for` で回して出力を処理している。この反復はどうすれば終わるか。処理が遅いとき、送られた値はすべて受け取れるか

- 要点: 実行が正常に終了すると終わる。別のスレッドから `run.shutdown()` を呼んで止める
- 要点: すべては受け取れない。間の値は飛ばされ、その時点の最新の値を受け取る

### H2 ネットワーク `a` を `mujou.run(a)` で単独で走らせて終えた。同じインスタンスの `a` を `mujou.run(a, b)` に渡すとどうなるか。どうすれば一緒に走らせられるか

- 要点: `RuntimeError` になる（1 つのネットワークは 1 回だけ走る／単独で構築済み）
- 要点: ノードも含めて新しいインスタンスを作り、最初から一緒に渡す

### H3 `run.shutdown(timeout=1.0)` が `TimeoutError` を送出した。実行はどうなっているか。終了を待つには何を呼ぶか

- 要点: 終了の要求は取り消されず、バックグラウンドで終了が進んでいる
- 要点: `run.join()` で終了を待つ
