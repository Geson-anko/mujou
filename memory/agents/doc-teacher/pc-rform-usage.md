# docs/en/topics/pc.md 理解度テスト（r 形）

## 対象
- ファイル: docs/en/topics/pc.md（同じ内容を docs/ja/topics/pc.md に反映）
- 読者と用途: mujou.pc で PC-ALM のネットワークを組んで学習させる利用者。時定数（tau.h, tau.lam, tau.r）・period・max_dt・relaxer・learn_interval の選び方と落とし穴を読み、自分の設定を決める
- 正本: src/mujou/pc/*.py の docstring、specs/pc.md（「減衰が要る理由と限界」「時定数」「dt の打ち切り」）、specs/open-decisions.md

## 評価用問題
### Q1 `pc.Chain` に `tau = pc.TimeConstants(h=4e-3, lam=8e-3, r=4e-3 / 3)` を渡し、`period` は渡さなかった。何が起き、どう直すか。直した後の `period` の上限を `tau.h` で答えよ。
- 要点: 既定の周期 tau.h/4 が既定の max_dt より長いので ValueError になる
- 要点: tau.max_dt 以下の period を渡す。上限は tau.h / 8（tau.h/(2*(1+3))）

### Q2 MNIST のような浅い鎖を組む。`tau.r` は何にするか。省略してよいか。
- 要点: 推奨は tau.h
- 要点: 省略できない（必須）。減衰を切るなら math.inf（浅い鎖向け）

### Q3 ゲインが約 1.25 の線形ノードを 16 段つないだ鎖で、`lam` が credit に届かない。同僚が「周期を tau.h/16 にし、tau.r を tau.h/7 まで縮めれば直る」と言う。直るか。理由も。
- 要点: 直らない
- 要点: 原因は連続時間のダイナミクスで、陽的な歩み（周期）ではない。tau.r を tau.h/7 まで縮めても発散した
- 要点: 直す設定は mujou.pc にはまだ無い

### Q4 学習中のネットワークで、`lam` が BP の credit からずれていないかを確かめたい。何をするか。いつ行うか。
- 要点: 重みを固定（learn_interval=math.inf）して 1 バッチ緩和させ、各ノードの lam を autograd の -∂ℓ/∂h と比べる
- 要点: 学んだ重みで行い、学習が進むたびに繰り返す（ゲインが育つため）

### Q5 確かめた結果 `lam` がずれていた。原因が周期（硬さ）か、鎖の増幅かを見分けるにはどうするか。
- 要点: 周期を半分にして同じ確かめ方をする
- 要点: 半分の周期と同じ lam なら周期は十分短い／半分の周期でもずれたままなら原因は周期ではない（増幅）

### Q6 examples/cifar10 の構成で 10 epoch 以上学習させる。r を状態に持つ今、この長さで安定に学べることは確かめられているか。
- 要点: 確かめられていない（r 形では 3 epoch より先は未測定）
- 要点: 学習でブロックのゲインが育ち、長い学習で崩れるかは未解明

### Q7 `pc.Chain` に `relaxer=` を渡さないと、r はどう動くか。別の動かし方にしたいとき、何を用意するか。
- 要点: 既定の pc.relax.Euler()（r -= (dt / tau.h) * F）
- 要点: 自作の relaxer（pc.relax.Relaxer と pc.relax.BoundRelaxer を継承し、F = 0 を不動点に持つ）

### Q8 周期 1 ms、各バッチを 32 周期見せ、Input から Output まで接続が 3 本の鎖。`learn_interval` をどの範囲から選ぶか。理由も。
- 要点: 16 ms より長く 32 ms より短い（半分より短いと 1 バッチで 2 回以上学ぶ、見せる時間以上だと学ばない）
- 要点: credit の往復 2*3*1 ms = 6 ms より長い

### Q9 マシンが混んでいて更新が遅れ、ネットワークが発散した。`max_dt` を短くすれば防げるか。
- 要点: 防げない。max_dt は 1 回の更新で数える時間の上限で、超えた分は捨てるだけ
- 要点: 時間スケールを下げる／他のプロセスの無いマシンで走らせる

## 保留問題
### H1 既定の初期化の残差ブロックを 8 段つないだ鎖を tau.r = tau.h で学ばせる。lam が credit に届くと見込めるか。根拠も。
- 要点: 届くと見込める。既定の初期化（ゲイン 2.7〜5.7、8〜32 段）で届いた／8 段の残差の鎖で tau.r が 2 tau.h〜tau.h/3 なら届いた

### H2 深い残差の鎖で tau.r = math.inf にすると何が起きるか。なぜか。
- 要点: 発散する（8 段の残差の鎖で発散）
- 要点: h = mu + r が下のすべての r と一緒に動き、credit がヤコビアンを通って戻ってくるため

### H3 `tau.lam = tau.h / 16` にして `pc.Chain` を既定の周期で作った。どうなるか、どうするか。
- 要点: ValueError（tau.lam < tau.h/12 で既定の max_dt = 3*tau.lam が周期 tau.h/4 より短い）
- 要点: tau.max_dt 以下の period を渡す
