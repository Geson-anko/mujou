# docs/en/user-guide/pc.md 理解度テスト

## 対象

- ファイル: `docs/en/user-guide/pc.md`（ほかに `docs/en/api/pc.md`、`mkdocs.yml` の nav、`docs/en/user-guide/index.md`・`docs/en/api/index.md` の一覧、`examples/mnist/main.py` の snippet マーカー）
- 読者と用途: PyTorch を使える ML の利用者が、`mujou.pc` で層ごとのノードを組み、MNIST のようなデータをストリームで流して PC-ALM で学習させ、精度を測る。BP との違い、時定数・周期・`learn_interval`・`max_dt` の決め方、ハマりどころがわかる

## 事実確認（R1）

- `examples/mnist/main.py --epochs 1` を worktree で実行（2026-10-20、32 コア、3.14t、スケール 1）: prequential PC 91.75% / BP 91.78%、test PC 96.39% / BP 96.22%、1 バッチ PC 33.02 ms / BP 0.81 ms（約 40 倍）、dt は 99% 点まで 1.25 周期
- `run.read(layer.next)` は `ValueError: cannot read the port 'l.next': it sends carried data, which the host cannot read`
- `pc.Output(..., loss=nn.MSELoss())`（float の target）は構築時に `ValueError`
- 最初の書き込み前の `run.read(out.next)` は `y_hat` ゼロ、`mask` すべて False、`time` 0
- `run.write` は `Timestamp` を返し `.ns` を持つ。`Layer`/`Output` の周期の既定は `tau.h / 4`
- `learn_interval` が見せる時間以上だと、`_tick` が新しい入力で `_learn_at` を引き直し、学習しないまま `_elapsed` を捨てる（`src/mujou/_core/pc/learner.py`）
- `max_dt` の既定 `min(tau.h / 2, 3 * tau.lam)`、学習率 `elapsed / tau.theta * g / B`（B は mask False を含む）
- 安定な範囲の数値は `specs/pc-module.md` の「時定数」節（relu は `period / tau.h <= 0.5`、最良帯 `period / tau.lam` 0.1〜0.3）。`S` の下限は未測定（同「未決定事項」）

## 評価用問題

### Q1 10 クラスの分類器をバッチサイズ 32 で学習させる。ラベルを入力とともに運ぶため、各ノードの `carry` に何を渡すか。どう作り、どのノードに渡すか。

- 要点:
    - `pc.carry_spec(TensorSpec((32,), torch.int64), batch=32)` で作る
    - 同じ spec を `Input`・`Layer`・`Output` のすべてに `carry` として渡す

### Q2 回帰のために `pc.Output(..., loss=nn.MSELoss())` と書いた。これでよいか。よくなければどうするか。

- 要点:
    - よくない。`nn.MSELoss()` は平均を返すので、`pc.Output` が（構築時に）`ValueError` を出す
    - サンプルごとの損失 `(B,)` を返す関数を渡す。`pc.mse`（またはその形の自作関数）を使う

### Q3 各バッチを 40 ms 見せる設定で、`learn_interval=50e-3` にした。何が起きるか。どう直すか。

- 要点:
    - ノードは学習しない（重みが更新されない）。学習の時刻より先に次のバッチが書かれ、数えた時間は捨てられる
    - `learn_interval` を見せる時間より短く、半分より長くする（20〜40 ms の間。例は 3/4 の 30 ms）

### Q4 各バッチを 32 ms 見せ、1 バッチに 1 回学習させる。1 バッチあたりの学習率を 0.05 にしたい。`tau.theta` をいくつにするか。

- 要点:
    - `tau.theta = 見せる時間 / 学習率 = 0.032 / 0.05 = 0.64` 秒

### Q5 学習を続けながら、テストデータでの精度を測りたい。テストデータで学習させないために、ホストは何をするか。

- 要点:
    - テストのバッチを `mask` すべて False にして、同じ（走っている）ネットワークの `Input` に書く。推論モードへの切り替えは無い
    - 見せる時間の後に `out.next` の最新の予測を読む（`run.read(out.next)`）
    - 正誤は元のラベルで、元の `mask` が True のサンプルだけ数える（パディングを除く）

### Q6 隠れ層 `l1` の出力をホストから見たくて `run.read(l1.next)` と書いた。どうなるか。代わりにどうするか。

- 要点:
    - `ValueError` になる（`Layer` の `next` は付随データを中継するので、ホストは読めない）
    - `h`・`lam` は `run.state_dict()["nodes"][path]` から読む（`l1.h` を直接読むと更新と競合する）
    - 予測を読むのは `out.next`

### Q7 書き込んだバッチに対する最初の予測（prequential 精度用）を得たい。`run.write` の直後に `run.read(out.next)` で読むのが正しくないのはなぜか。代わりにどう取得するか。

- 要点:
    - `read` は今の最新の予測を返し、それはまだ前のバッチ（最初ならゼロで `mask` すべて False、`time` 0）から作られたものでありうる
    - `t = run.write(...)` の時刻と、予測の `time` が一致するもの（`int(p["time"]) == t.ns`）を `run.wait_for` で待つ

### Q8 速く回すために timer の時間のスケールを 2 にしたら、数百バッチで予測が NaN になった。何をするか。`max_dt` で防げるか。

- 要点:
    - 時間のスケールを下げる（`dt` の警告が出ず発散しない最大の値を、1 epoch 回して選ぶ）。他のプロセスがコアを使っていない機械で回す
    - `max_dt` では防げない

### Q9 入力がフレームごとに変わる動画のストリームで学習させる。`learn_interval` をどうするか。そのとき `tau.theta` は何を表すか。

- 要点:
    - `learn_interval=None`（入力が変わったかによらず、毎回の更新で学習する）
    - 1 秒あたりの学習率は `1 / tau.theta`（`tau.theta` は時定数。更新量は `dt / tau.theta` × 勾配）

## 保留問題

### H2 `pc.Input` を作ったら引数が足りないと言われた。`period` を何にするか。`Layer` と `Output` の周期は何もしないとどうなるか。

- 要点:
    - `Input` は `period` が必須。`Layer`/`Output` と同じ値（`tau.h / 4`）を渡す
    - `Layer`/`Output` の周期の既定は `tau.h / 4`

### H3 `nn.Sequential(nn.Linear(784, 256), nn.BatchNorm1d(256), nn.ReLU(), nn.Dropout(0.1))` を 1 つの `pc.Layer` に入れてよいか。

- 要点:
    - よくない。モジュールはバッチの各サンプルを独立に扱わなければならず、学習モードの `BatchNorm` と `Dropout` は使えない
