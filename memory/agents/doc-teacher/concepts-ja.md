## 評価用問題
### Q1 PyTorch では `model.train()` / `model.eval()` で学習と推論を切り替える。mujou には、ネットワークを学習のモードと推論のモードで切り替える仕組みがあるか。mujou がそう設計されている理由も答えよ。
- R1 で改題（問題不良）: 旧題「推論専用のモードに切り替えたい。どうすればよいか」は、方法があることを前提にしていて、生徒が「方法は判断できない」と答える余地があった
- 要点: mujou にはモードの切り替えが無い（ノードは走っている間、更新を続ける）
- 要点: 理由: ストリームから学び続ける機械が対象で、学習と推論を分けると推論している間は学べないから

### Q2 2 つのノード A と B があり、B の損失から A の重みへ勾配を流すため、A の出力を B に渡して B の中で `loss.backward()` を呼びたい。これはできるか、理由も答えよ。A と B を BP で一緒に学習させたいなら、どうすればよいか。
- R1 で改題（問題不良）: 旧題は要点 3（1 つのノードにまとめる）を問うていなかった
- 要点: できない（ノードをまたぐ backward は禁止）
- 要点: 送る値は送るときに計算グラフから切り離されるので、勾配は Port を通らない
- 要点: A と B を同期的に BP で学習させたいなら、1 つのノードのクラスにまとめる（ノードの内側に閉じた BP は使える）

### Q3 ノード B の `on_update` で `self.prev.recv()` を呼んだ。前のノード A は、B が前回読んでから一度も書いていない。B は何を受け取るか。A が一度も書いていない場合はどうか。
- 要点: 待たずに、前回と同じ（最新の）値を受け取る
- 要点: 一度も書いていなければ初期値（既定はゼロ）

### Q4 あるノードが重い計算のせいで、ほかのノードより更新の頻度が低い。このノードの更新量の大きさは、頻度の高いノードと比べてどう扱えばよいか。`on_update` の引数を使って答えよ。
- 要点: 更新量を `dt`（前回の更新からの経過時間、秒）に比例させる（例: `x = x + dt * f(x)`）
- 要点: 頻度が低いと `dt` が大きくなるだけで、同じ時間の上で同じダイナミクスを近似できる（反復回数あたりで決めない）

### Q5 ホストのコードで、1 つのサンプルを 0.1 秒だけネットワークに見せてから次のサンプルを書きたい。ネットワークは `timer` を渡さずに `mujou.run(net)` で走らせている。待つのに何を使うか。標準の `time.sleep(0.1)` ではいけない理由も答えよ。
- 要点: `mujou.time.sleep(0.1)`（グローバルタイマーで待つ）
- 要点: `time.sleep` は実時間で待つので、時間の速さ（スケール）の変更や停止と合わない

### Q6 ノードの `on_update` の中で `mujou.time.set_time_scale(0.5)` を呼んで、そのノードの時間をゆっくりにしたい。できるか。
- 要点: できない。hook の中で呼ぶと `RuntimeError`
- 要点: 理由として「時間を動かすのはホストだけ」か「ノードが速さを変えると同じ実行のほかのノードの `dt` も変わる」のどちらかを挙げる（R1 で、同じ理由の 2 つの言い方を 1 つの要点にまとめた）

### Q7 実行中に `run.state_dict()` を呼んで状態を取った。取得のために止まっていた時間は、再開後の各ノードの `dt` に含まれるか。理由も答えよ。
- 要点: 含まれない
- 要点: 止めている間は実行のタイマーも止まるから（ダイナミクスから見ると停止は無かったのと同じ）

### Q8 ネットワークのあるノードが `on_update` で例外を投げて実行が終わった。その後、ホストが `run.state_dict()` で状態を保存しようとした。どうなるか。状態を保存したいならいつ取ればよいか。
- 要点: 取得できず `NetworkError` になる
- 要点: 実行中か、正常に終了した後に取る

### Q9 ノードの `on_start` で `self.w = torch.randn(256, 256)`、`self.lr = 0.01`、`self._h = torch.zeros(32, 256)` を代入した。`state_dict` を override していないとき、既定でノードの状態に入るのはどれか。
- 要点: `self.w` と `self._h`（Tensor は名前の `_` に関係なく入る）
- 要点: `self.lr`（数値）は入らない

### Q10 ノードの `on_stop` で GPU メモリを返すために `self.w = None` とした。正常に終了した後に `run.state_dict()` を取ると何が問題になるか。
- 要点: `w` が状態から消える（`None` を代入すると状態から外れる）
- 要点: `on_stop` は `state_dict` が返す状態を変えてはならない

### Q11 ネットワーク `Classifier` のルートの属性 `body` が `Stack` で、`Stack` の属性 `l2` がノードである。このノードのパスは何か。また、`mujou.run(Compose(cls=Classifier()))` で走らせたときのパスは何か。
- 要点: `"body.l2"`
- 要点: `"cls.body.l2"`

### Q12 `class Pair(mujou.Network)` の中でノード `a` と `b` を属性に持たせた。ネットワークで囲めば `a` と `b` は互いを待って同期的に更新されるか。同期させたいならどうするか。
- 要点: 同期しない。ネットワークは構築時だけの構造で、中のノードはそれぞれ独立に互いを待たずに動く
- 要点: 同期させたいなら、それらの計算を 1 つのノードのクラスにまとめる

### Q13 ノード `head` が `NextPort` を持ち、`head.connect(x)`、`head.connect(y)` と 2 つの相手につないだ。`head` が `self.next.recv()` で受け取る値の形と、2 つの相手の値の合計を使いたいとき誰が足すかを答えよ。
- 要点: Channel をキーにした dict（接続した順）
- 要点: 足すのはノード自身（mujou は束ね方を決めない）

## 保留問題
### H1 ホストが、すでに隣のノードとつながっている Port に `run.write` で値を書こうとした。書けるか、理由も答えよ。
- 要点: 書けない（ホストが書けるのはつながっていない Port だけ）
- 要点: 各値の置き場所の書き手を 1 つに保つため

### H2 グローバルタイマーで走る実行 X と Y がある。X で `run.state_dict()` を呼んだとき Y の時間はどうなるか。Y を止めたくないならどうするか。
- 要点: Y の時間も止まる（停止は同じタイマーを使うすべての実行に及ぶ）
- 要点: Y に（または X に）別の `mujou.time.Timer()` を `timer=` で渡して走らせる

### H3 保存した状態の木を `mujou.run(net, state=tree)` で復元するとき、`on_start` と `load_state_dict` はどちらが先に呼ばれるか。また、木を取った後にノードの属性名を変えたネットワークに渡すとどうなるか。
- 要点: `on_start` が先、その後最初の `on_update` の前に `load_state_dict`
- 要点: パスが変わるので `mujou.run` が `ValueError` を送出し、何も起動しない
