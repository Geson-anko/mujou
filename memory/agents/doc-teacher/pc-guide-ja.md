## 事実確認（R1、2026-10-20）

- 英語版の事実確認（pc-guide-en.md）を引き継ぐ。数値・既定値は英語版と同じ
- `max_dt` が周期より短くても `ValueError` にならない（`pc.Layer(..., max_dt=0.5e-3)` が通る。`learner.py` は `max_dt` が有限で正かだけを見る）。英語版の表の「A `max_dt` shorter than the period raises `ValueError`」は今のコードでは誤りなので、ja には書かなかった
- `pc.Input` は `period` が必須（`TypeError: missing 1 required keyword-only argument: 'period'`）
- `pc.Output(..., loss=nn.MSELoss())` は構築時に `ValueError`（float の目標で確認）
- `learn_` は `elapsed / tau.theta / B` で、`B` は mask False を含むバッチの大きさ。mask False のサンプルは損失に足されない（`functional.loss_vjp`）
- `docs/ja/api/` は無く、ja の API ページは en にフォールバックする（`mkdocs.yml` の i18n、`memory/project_docs_site.md`）。en の `api/index.md` に足した行がそのまま ja のサイトにも出るので、ja 側に足す行は無い
- アンカー: `building-a-network.md#経路に沿ってデータを運ぶ`、`torch.md#内部のスレッド数` を percent-encode して張り、`uv run mkdocs build --strict` が通った

## 評価用問題

### Q1 10 クラスの分類器をバッチサイズ 32 で学習させる。ラベルを入力と一緒に運ぶため、各ノードの `carry` に何を渡すか。どう作り、どのノードに渡すか。

- 要点:
    - `pc.carry_spec(TensorSpec((32,), torch.int64), batch=32)` で作る
    - 同じ spec を `Input`・`Layer`・`Output` のすべてに `carry` として渡す

### Q2 回帰のために `pc.Output(..., loss=nn.MSELoss())` と書いた。これでよいか。よくなければどうするか。

- 要点:
    - よくない。`nn.MSELoss()` は平均を返すので、`pc.Output` が `ValueError` を送出する
    - サンプルごとの損失 `(B,)` を返す関数を渡す。`pc.mse`（またはその形の自作関数）を使う

### Q3 各バッチを 40 ms 見せる設定で、`learn_interval=50e-3` にした。何が起きるか。どう直すか。

- 要点:
    - ノードは学習しない（重みが更新されない）。学習の時刻より先に次のバッチが書かれ、数えた時間は捨てられる
    - `learn_interval` を見せる時間より短く、半分より長くする（20〜40 ms の間。例にならえば 3/4 の 30 ms）

### Q4 各バッチを 32 ms 見せ、1 バッチに 1 回学習させる。1 バッチあたりの学習率を 0.05 にしたい。`tau.theta` をいくつにするか。

- 要点:
    - `tau.theta = 見せる時間 / 学習率 = 0.032 / 0.05 = 0.64` 秒

### Q5 学習を続けながら、テストデータでの精度を測りたい。テストデータで学習させないために、ホストは何をするか。精度はどう数えるか。

- 要点:
    - テストのバッチを `mask` すべて False にして、走っている同じネットワークの `Input` に書く。推論モードへの切り替えは無い
    - 見せる時間の後に `run.read(out.next)` で最新の予測を読む
    - 正誤は元のラベル `y` で、元の `mask` が True のサンプルだけ数える（パディングを除く）

### Q6 隠れ層 `l1` の出力をホストから見たくて `run.read(l1.next)` と書いた。どうなるか。代わりにどうするか。

- 要点:
    - `ValueError` になる（`Layer` の `next` は付随データを中継するので、ホストは読めない）
    - `h`・`lam` は `run.state_dict()["nodes"]["l1"]["h"]` / `["lam"]` から読む（`l1.h` を直接読むと更新と競合する）
    - 予測を読むのは `out.next`

### Q7 書き込んだバッチに対する最初の予測（prequential 精度用）を得たい。`run.write` の直後に `run.read(out.next)` で読むのが正しくないのはなぜか。代わりにどう取得するか。

- 要点:
    - 新しい入力はまだノードを通っておらず、`read` は前のバッチの予測（最初ならゼロで `mask` すべて False、`time` 0）を返しうる
    - `t = run.write(...)` の時刻と予測の `time` が一致するもの（`int(p["time"]) == t.ns`）を `run.wait_for` で待つ

### Q8 速く回すために時間の速さ（time scale）を 2 にしたら、数百バッチで予測が NaN になった。何をするか。`max_dt` を変えれば防げるか。

- 要点:
    - 時間の速さを下げる（1 epoch 回し、`dt` の警告が出ず発散もしない最も速い値を選ぶ）。ほかのプロセスがコアを使っていない機械で回す
    - `max_dt` では防げない

### Q9 入力がフレームごとに変わる動画のストリームで学習させる。`learn_interval` をどうするか。そのとき `tau.theta` は何を表すか。

- 要点:
    - `learn_interval=None`（入力が変わったかどうかによらず、毎回の更新で学習する）
    - 1 秒あたりの学習率は `1 / tau.theta`（`tau.theta` は重みの時定数）

### Q10 `learn_interval=24e-3` のノードが、ホストの書き込みから 3 ms 後に新しい入力を初めて受け取った。このノードが初めて重みを更新するのは、ホストの書き込みから何 ms 後か（その時刻以降の最初の更新）。

日本語の「書き込みから」の読み取りを測る。

- 要点:
    - 書き込みから 24 ms 後（受け取ってから 24 ms 後の 27 ms ではない）。`learn_interval` はノードが受け取った時刻でなく、書き込みの時刻から数える

### Q11 バッチサイズ 64 で、最後のバッチは本物のサンプルが 16 個、残り 48 個が `mask` False の埋め草だった。`tau.theta` はほかのバッチと同じ。このバッチでの重みの更新の大きさは、本物 16 個だけの勾配の平均で更新した場合と比べてどうなるか。

日本語の「平均の分母の `B` には `mask` が False のサンプルも入る」の読み取りを測る。

- 要点:
    - 小さくなる。勾配の和を 64 で割るので、16 個の平均で割った場合の 16/64 = 1/4
    - 埋め草のサンプルは勾配に何も足さない（`mask` False から学習しない）が、分母 `B` には数えられる

## 保留問題

### H1 `pc.Input` を作ったら引数が足りないと言われた。`period` を何にするか。`Layer` と `Output` の周期は何も渡さないとどうなるか。

- 要点:
    - `Input` は `period` が必須。`Layer`/`Output` と同じ値（`tau.h / 4`）を渡す
    - `Layer`/`Output` の周期の既定は `tau.h / 4`

### H2 `nn.Sequential(nn.Linear(784, 256), nn.BatchNorm1d(256), nn.ReLU(), nn.Dropout(0.1))` を 1 つの `pc.Layer` に入れてよいか。

- 要点:
    - よくない。モジュールはバッチの各サンプルを独立に扱わなければならず、PyTorch の学習モードの `BatchNorm` と `Dropout` はサンプルを混ぜたり落としたりするので使えない（`LayerNorm` は可）

### H3 `tau.h = 4 ms`、`tau.lam = 8 ms` で `max_dt` は既定のまま。負荷のせいで、あるノードの 1 回の更新の `dt` が 5 ms になった。この更新が緩和と重みの学習の時間として数えるのは何 ms か。残りはどうなるか。

- 要点:
    - 2 ms（`max_dt = min(4 / 2, 3 * 8) = 2` ms）
    - 超えた 3 ms は捨てられる（緩和からも次の重みの更新からも）
