## 評価用問題
### Q1 層 A と層 B を別々のノードにした。B の損失から A の重みへ勾配を流すため、A が送った値を B で受け取り、B の中で `loss.backward()` を呼びたい。これで A に勾配が届くか、理由も答えよ。A と B を BP で一緒に学習させたいなら、どうすればよいか。
- R1 で改題（問題不良）: 旧題は理由を問うていないのに、要点 2（理由）を求めていた
- 要点: 届かない（ノードをまたいで計算グラフをつなげない）
- 要点: 送った値は送るときに計算グラフから切り離されるので、勾配はノードの間を通らない
- 要点: A と B を 1 つのノードのクラスにまとめる（ノードの内側に閉じた BP は使える）

### Q2 ノード B が、ノード A とつながった Port から値を読んだ。A は実行が始まってからまだ一度も値を書いていない。B は何を受け取るか。B が「A はまだ書いていない」と判断するには何を使うか。
- 要点: A の Port の初期値（既定はゼロ）を受け取る。待たない
- 要点: `has_received()` を使う

### Q3 ノード B は、隣のノード A から新しい値が届いたときだけ重い処理をしたい。A は B より更新が遅い。B は `on_update` の中で、値が新しいかどうかをどう判断するか。
- R1 で要点を削った（問題不良）: 旧要点 2「同じ値を何度も読むことがある」は問いが求めていなかった
- 要点: 値を時刻と一緒に読み（`recv_with_time()`）、前回読んだ値の時刻と比べる（進んでいれば新しい）

### Q4 あるノードの `on_update` で、負荷が高いときに `dt` が 0.5 秒まで伸び、更新が不安定になった。`dt = min(dt, 0.05)` と上限を設けてよいか。代わりにどうするか。
- 要点: 上限を設けてはならない（実際に経った時間が失われる）
- 要点: 1 回の `on_update` の中で刻みを分割する（更新量は `dt` に比例させたまま）

### Q5 ホストのコードで、ある入力を 2 秒だけネットワークに見せてから次の入力を書きたい。待つのに何を使うか。標準の `time.sleep(2)` を使わない理由も答えよ。
- 要点: `mujou.time.sleep`（実行のタイマーの時間で待つ）
- 要点: `time.sleep` は実時間で待つ。ホストは時間を実時間より速くも遅くも進められるので、実時間で待つとネットワークの時間とずれる

### Q6 `class Pair(mujou.Network)` の中で、ノード `a` と `b` を属性に持たせた。実行中、`a` と `b` は互いを待って同期的に更新されるか。同期的に計算させたいならどうするか。
- 要点: 同期しない。ネットワークは組み立てるときにだけ使い、中のノードはそれぞれ独立に動く
- 要点: 同期させたいなら、2 つの計算を 1 つのノードのクラスにまとめる

### Q7 あるノードが `on_update` で例外を投げた。ホストはその後で状態を取って保存しようとした。どうなるか。状態を確実に残したいなら、いつ取ればよいか。
- 要点: 取れず `NetworkError` になる（例外で実行全体が止まっている）
- 要点: 実行中に取っておく

### Q8 ノードの `on_stop` で、メモリを返すために `self.w = None` とした（`w` は重みのテンソル）。正常に終了した後に状態を取ると、何が起きるか。`on_stop` では何をしてよいか。
- 要点: 終了後の木は `on_stop` の後に取るので、木から `w` が消える
- 要点: `on_stop` では状態を変えず、I/O などの資源だけを解放する

## 保留問題
### H1 ホストが、すでに隣のノードとつながっている入力の Port に値を書こうとした。書けるか。ホストが値を書ける Port はどれか。
- 要点: 書けない（つながっている Port の置き場所に書くのは、その向きの送り手だけ）
- 要点: ホストが書けるのは、つながっていない入力の Port

### H2 プロセスのグローバルタイマーで、実行 X と実行 Y を同時に走らせている。ホストが X の状態を取ったとき、Y の時間はどうなるか。Y の時間を止めたくないならどうするか。
- 要点: Y の時間も止まる（一時停止は同じタイマーを使うすべての実行の時間を止める）
- 要点: どちらかの実行に専用のタイマーを持たせる

### H3 ノードの 1 つの Port を 3 つの相手につないだ。このノードは値をいくつ受け取るか。3 つの値の平均を使いたいとき、平均を取るのは誰か。
- 要点: Channel ごとに 1 つずつ、3 つ受け取る
- 要点: ノード自身が平均を取る（束ね方はノードが決める）
