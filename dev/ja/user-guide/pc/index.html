    🧠 PC-ALM で学習する¶

    mujou.pc は PyTorch のモデルをノードに分け、PC-ALM（Augmented Lagrangian Predictive Coding、https://pub.sakana.ai/pc-alm/）で学習させるモジュール。このページではノードの組み方、データセットをストリームで流す方法、精度の測り方、時定数の決め方を説明する。例は examples/mnist/ の 784-256-256-10 の ReLU ネットワークで、MNIST を学習し BP と比べる。

    先にネットワークを組む（特に経路に沿ってデータを運ぶ）とネットワークを走らせるを読んでおくこと。

    BP との違い¶

    項目 普通の PyTorch の BP mujou.pc
    推論と学習 forward、backward、optimizer.step() を順に 同時に進む。各ノードが自分の周期で更新し、入力を見せている間に学習する
    1 回の学習 1 バッチ ホストがバッチを一定の時間（S 周期）見せる。ノードは目標に向かって緩和し、その後に重みを更新する
    目標 バッチと一緒に損失関数に渡す 入力と一緒に書き込み、活動と組にしてノードからノードへ出力ノードまで運ぶ
    学習とテスト model.train() / model.eval() mujou には学習と推論を切り替えるモードが無い。mask が False のサンプルからは学習しないので、テストのバッチも走っている同じノードに流す
    損失 普通はバッチの平均 サンプルごとの損失で、shape は (B,)。出力ノードが合計する
    勾配を取る範囲 モデル全体を通して .backward() 各ノードの内側だけ。隣のノードとは活動とエネルギーの勾配をメッセージでやり取りする
    計算量 1 バッチに forward と backward が 1 回ずつ 1 周期にノードごとに forward と VJP が 1 回なので、1 バッチで S 回。例では CPU 上で 1 バッチに BP の約 40 倍の時間がかかる

    精度は BP に近い。例の既定の 3 epoch では、同じ初期重みと同じバッチでテスト精度が PC-ALM 97.82%、BP 97.54% だった（seed 0。seed 1 では 97.59% と 97.45%）。

    ノード¶

    ノード 持つもの Port
    pc.Input なし prev: ホストが pc.Sample（{"x": ..., "y": ..., "mask": ...}）を書く。next: x を pc.Activity の h として送り、y・mask・書き込みの時刻を付随データで運ぶ
    pc.Layer モジュール f、活動 h、双対変数 lam prev で前のノードの pc.Activity を受け取る。next は自分の h を pc.Activity で送り、入力と一緒に届いた付随データを中継する
    pc.Output 最後のモジュールと損失 prev で pc.Activity を受け取る。next はホストが読む pc.Prediction（y_hat、y、mask、time）を送る

    モデルは Input → Layer → ... → Output の鎖にする。Layer にはバッチの各サンプルを独立に扱う nn.Module なら何でも入れられる。1 層でも、層を重ねたものでも、残差ブロックでもよい。Dropout と BatchNorm は PyTorch の training mode（model.train()）でサンプルを落としたり混ぜたりするので使わない。LayerNorm は使える。ノードの内側では BP と同じくモジュールを autograd で微分する。

    ネットワークを組む¶

    def build(
    modules: Sequence[nn.Module], batch: int, tau: pc.TimeConstants, learn: float
) -> tuple[pc.Input, WatchedOutput, mujou.Group]:
    """Wrap the three modules in nodes and connect them."""
    carry = pc.carry_spec(TensorSpec((batch,), torch.int64), batch=batch)
    inp = pc.Input((batch, 784), carry=carry, period=tau.h / 4)
    l1 = WatchedLayer(
        modules[0], input_shape=(batch, 784), carry=carry, tau=tau, learn_interval=learn
    )
    l2 = WatchedLayer(
        modules[1], input_shape=(batch, 256), carry=carry, tau=tau, learn_interval=learn
    )
    out = WatchedOutput(
        modules[2],
        loss=pc.cross_entropy,
        input_shape=(batch, 256),
        carry=carry,
        tau=tau,
        learn_interval=learn,
    )
    inp.next.connect(l1.prev)
    l1.next.connect(l2.prev)
    l2.next.connect(out.prev)
    return inp, out, mujou.Group(inp=inp, l1=l1, l2=l2, out=out)
    1. 付随データの spec を pc.carry_spec(target_spec, batch=B) で 1 回作り、すべてのノードに carry として渡す。目標の spec はクラスラベルなら TensorSpec((B,), torch.int64)、D 個の実数（pc.mse で学習するとき）なら TensorSpec((B, D))
    2. 各ノードには受け取るものの shape をバッチを先頭にして渡す（pc.Input((B, 784), ...)、pc.Layer(module, input_shape=(B, 784), ...)）。送るものの shape は、ノードがモジュールをゼロで 1 回呼んで決める
    3. 鎖に沿って next を prev につなぐ
    4. ノードをネットワークに入れて走らせる。例では mujou.Group を使う

    WatchedLayer と WatchedOutput は pc.Layer と pc.Output に dt を数える機能を足したもの。自分のコードでは pc.Layer と pc.Output を使う。

    重みはモジュールを作るときに初期化しておく。ノードは初期化しない。requires_grad=False のパラメータは学習しない。

    時定数を決める¶

    mujou.pc の速さはすべて実行のタイマーでの秒数で指定する。次の表の順に決める。

    period = args.tau_h / 4
shown = args.steps * period  # how long the host shows each batch
# The learning rate of one batch is sum_dt / tau.theta = S * period / tau.theta.
tau = pc.TimeConstants(h=args.tau_h, lam=2 * args.tau_h, theta=shown / args.lr)
learn = 0.75 * shown  # learn once, 3/4 of the way through each batch
inp, out, net = build(modules, args.batch, tau, learn)
timer = mujou.time.Timer()
timer.set_time_scale(args.time_scale)
    値 決めるもの 決め方 例
    tau.h 各活動 h が緩和する速さ 最初に決める。ほかの値はここから決まる 4 ms
    ノードの周期 各ノードが更新する間隔 Layer・Output は既定で tau.h / 4。Input は period= が必須で、同じ値を渡す 1 ms
    tau.lam 双対変数 lam が追従する速さ 2 * tau.h 8 ms
    見せる時間 ホストが各バッチを見せる長さ S 周期。S = 32 32 ms
    learn_interval ホストの書き込みから重みを更新するまでの時間 見せる時間の半分と 2 × 深さ × 周期 の両方より長く、見せる時間より短くする。例では見せる時間の 3/4 24 ms
    tau.theta 重みの時定数（学習率はその逆数） 見せる時間を、1 バッチあたりの学習率で割る 0.32 s
    max_dt 1 回の更新で数える dt の上限 既定の min(tau.h / 2, 3 * tau.lam) のままにする（ここでは 2 周期）。周期が max_dt より長いと構築時に ValueError になる。tau.lam < tau.h / 12 なら既定でもそうなるので、period か max_dt を渡す 2 ms
    • 学習率: 1 回の重みの更新で、重みは「そのノードが前に重みを更新してからの時間 / tau.theta」に勾配の平均を掛けた分だけ動く。1 バッチに 1 回更新するならその時間は見せる時間なので、tau.theta = 見せる時間 / lr とすれば 1 バッチあたりの学習率が lr になる
    • 前に重みを更新してからの時間: その間の各更新が数えた dt（1 回ごとに max_dt で打ち切ったもの）の和。周期どおりの更新なら dt は 1 周期で max_dt より短いので、例の見せる時間 32 ms は 32 回の更新でそのまま数えられる
    • 勾配の平均: サンプルごとの勾配の和をバッチの大きさ B で割ったもの。mask が False のサンプルは和に何も足さないが、B には数える
    • learn_interval を見せる時間の半分から全体の間にする理由: learn_interval はホストが書き込んだ時刻（付随データの time）から数え、ノードが入力を受け取った時刻からは数えない。起点はノードの深さによらず同じ。ノードは書き込みから learn_interval 経った後の更新で学習し、バッチを見せている間は以後 learn_interval ごとに学習する。半分より短いと 1 バッチで 2 回以上学習する。ノードは入力を初めて見た更新では学習せず、目標から来る credit が経路を往復する時間も要るので、少なくとも 2 × 深さ × 周期 程度は空ける（深さは経路上のノードの数。例では 4 ノードで 8 ms）。これは安定の条件で、短くすると深い鎖は発散しうる。見せる時間以上だと先に次のバッチが書かれるので、ノードは一度も学習せず、数えた時間も捨てる
    • 入力がフレームごとに変わるストリーム: learn_interval=None を渡す。ノードは入力が変わったかどうかによらず毎回の更新で学習し、1 秒あたりの学習率は 1 / tau.theta になる。ストリームに適した値はまだ測っていない
    • 安定性: tau.h に対して周期が短いほど安定する。設計時の測定では、ReLU で period / tau.h が 0.5 までは安定し、period / tau.lam は 0.1〜0.3 が最もよかった。S = 32 で BP と同じ精度が出た。それより短い見せる時間は確かめていない

    学習させて測る¶

    ホストは各バッチを inp.prev に書き、予測を out.next から読む。

    def show(run: mujou.Run, sample: pc.Sample) -> pc.Prediction:
    """Write ``sample``, return the first prediction made from it, and return
    once it has been shown for ``shown`` seconds of the run's time."""
    t = run.write({inp.prev: sample})
    first, _ = run.wait_for(out.next, lambda p: int(p["time"]) == t.ns, timeout=10)
    if not torch.isfinite(first["y_hat"]).all():
        raise SystemExit("PC-ALM diverged: lower --time-scale (see the docstring)")
    timer.sleep(max(0.0, shown - (float(timer.now()) - float(t))))
    return first

    run.write は書き込みの時刻を Timestamp t で返す（t.ns が ns 単位の値）。新しい入力はまだノードを通っていないので、書いた直後に out.next を読むと前のバッチの予測が返る（最初のバッチより前ならゼロ）。予測が運ぶ time は、その予測の元になった書き込みの時刻（ns）である。そこで wait_for で int(p["time"]) == t.ns となる予測を待てば、このバッチから作った最初の予測が得られる。その後ホストは、見せる時間が経つまで実行のタイマーで待つ。

    with mujou.run(net, timer=timer, workers=args.workers) as run:
    for epoch in range(args.epochs):
        right = total = 0
        start = time.perf_counter()
        train = batches(data.train_x, data.train_y, args.batch, shuffle(epoch))
        for i, sample in enumerate(train):
            first = show(run, sample)
            right += correct(first["y_hat"], first["y"], first["mask"])
            total += int(sample["mask"].sum())
            if epoch == 0 and i == 100:  # a pause to look, not to synchronize
                check_dt(run.state_dict()["nodes"])
        seconds = time.perf_counter() - start
        # Test: the same nodes, with no label to learn from.
        test_right = test_total = 0
        for sample in batches(data.test_x, data.test_y, args.batch):
            unlabeled: pc.Sample = {
                **sample,
                "mask": torch.zeros_like(sample["mask"]),
            }
            show(run, unlabeled)
            last = run.read(out.next)  # the latest prediction, after S periods
            test_right += correct(last["y_hat"], sample["y"], sample["mask"])
            test_total += int(sample["mask"].sum())
        results.append(Epoch(right / total, test_right / test_total, seconds))
        print(
            f"PC-ALM epoch {epoch + 1}: prequential {right / total:.2%}, "
            f"test {test_right / test_total:.2%}, {seconds:.1f} s"
        )
    • prequential 精度（学習中）: 各バッチへの最初の予測で測る。この予測はどのノードもまだそのバッチから学習していない時点のもので、まだ見ていないデータをどれだけ当てられるかを表す
    • テスト精度: ホストはテストのバッチを mask をすべて False にして書くので、どのノードもそこから学習しない（y は採点に使うので残す）。見せる時間の後に run.read(out.next) で最新の予測を読む。mujou に推論モードは無い
    • data.batches は最後のバッチの不足分を mask が False のゼロで埋める。正解を数えるのは、元の mask が True のサンプルだけ。テストでは書く mask をすべて False にするので、元の mask を取っておく

    ノードはすでに実行のワーカーの上で並列に計算するので、例では torch.set_num_threads(1) にしている（ノードの中の PyTorch の内部のスレッド数）。

    落とし穴¶

    損失関数はサンプルごとの損失を返す

    pc.cross_entropy、pc.mse、または (y_hat, y) -> (B,) の自作の関数を渡す。nn.MSELoss() のように平均を返す損失を渡すと、pc.Output が ValueError を送出する。pc.mse は特徴について合計した 0.5 * ||y - y_hat||^2 で、平均ではない。

    予測は Output の next から読む

    予測とターゲットを読めるのは out.next だけ。Layer の next は y・mask・time を付随データで中継し、ホストには付随データが届かない。run.read(layer.next)["h"] で読めるのは、その層の活動 h だけである。Layer の lam を見るときは run.state_dict()["nodes"][path]["lam"] を読む。path はネットワークでのノードの属性名（例では "l1"）。ホストが layer.lam を直接読むと、ノードの更新と競合する。

    最初のサンプルが届くまで付随データはゼロ

    ホストの最初の書き込みがノードに届くまで、付随データはゼロ（mask はすべて False、time は 0）。このとき run.read(out.next) は mask がすべて False の予測を返し、ノードは学習しない。書いたバッチの予測を得るには、show のように wait_for で time を照合する。

    負荷が高いとネットワークが発散する

    ノードはそれぞれ更新しながらメッセージをやり取りする。あるノードが遅れると、隣のノードはその古いメッセージから学習し続け、ネットワークが発散するか精度が落ちる。例の show は y_hat が有限でない（torch.isfinite）と止まる。予測が有限のまま発散したときは止まらず、精度の低下としてしか見えない。安全に回せる速さは機械によって違う。わかっている原因は 2 つ。

    • 時間の速さが速すぎる: 例は set_time_scale で実行のタイマーを速めている。1 でなく 2 にすると、最も遅いノードが周期の大半を計算に使い、その更新の 1% が 2 周期より遅れた（1 epoch は完走した）。例はノードの dt を表示し、更新が中央値で 1.5 周期、99% 点で 2 周期より遅れると警告する。1 epoch 回して、警告が出ず発散もしない最も速い時間の速さを選ぶ
    • ほかのプロセスがコアを使っている: コアを待つノードがあると、隣のノードが先に進む。32 コアの機械で時間の速さ 1 なら、busy loop 26 本と並べて 1 epoch を完走し、32 本では発散した。0.5 なら 32 本でも完走した。ほかに何も動いていない機械で回すか、時間の速さを下げる

    max_dt ではこれを防げない。max_dt は 1 回の更新で数える時間の上限で、超えた分は緩和からも次の重みの更新からも捨てられる。

    自分のノードを書く¶

    mujou.pc.functional に、ノードを構成する計算がある。vjp と loss_vjp（ノードのエネルギーの勾配）、relax_（h と lam の 1 ステップ）、learn_（重みの更新）。複数の入力を持つノードのように pc.Layer で書けないノードは、これらを使って書く。そのノードを mujou.pc のノードとつなぐには、pc.Activity（DictSpec(pc.Activity, h=..., epoch=TensorSpec((), torch.int64))）を受け取り、送る。詳しくは API リファレンスを参照。
