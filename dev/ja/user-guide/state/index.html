    💾 状態の保存と復元¶

    実行中のネットワークの状態を取得・保存し、後でその状態から再開する手順を説明する。

    状態の木の中身と、取得中に時間が止まる仕組みは状態を参照。

    基本の手順¶

    次のサンプルは、ネットワークを 0.2 秒走らせて状態を取得し、torch.save で保存してから、新しいインスタンスに復元して続きを走らせる。

    """Save the state of a run, and restore it in a new run that goes on from there.

A node collects its state by itself: every attribute that holds a
``torch.Tensor`` or an ``nn.Module``. ``Run.state_dict`` gathers the states of all
nodes, the latest messages and the time into one tree, a ``mujou.StateDict``.
Save it with ``torch.save`` (or pickle), and read it back with ``torch.load``.
"""

import io
from typing import override

import torch
from torch import nn

import mujou
from mujou import NextPort, Node, PrevPort, TensorSpec

VECTOR1 = TensorSpec((1,))


class Integrator(Node):
    """Integrates its input over time (dx/dt = u) and sends ``readout(x)``."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=VECTOR1)
        self.next = NextPort(send=VECTOR1)

    @override
    def on_start(self) -> None:
        super().on_start()
        self.x = VECTOR1.zeros()  # a tensor: part of the state
        # A module: part of the state.
        self.readout = nn.Linear(1, 1, device=self.device)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        self.x += dt * self.prev.recv()  # in place, so that a restore copies into it
        self.next.send(self.readout(self.x))


class Model(mujou.Network):
    def __init__(self) -> None:
        super().__init__()
        self.integrator = Integrator()
        self.prev = self.integrator.prev
        self.next = self.integrator.next


one = torch.ones(1)

# Run for a while, then stop and take the state at the end.
net = Model()
with mujou.run(net, inputs={net.prev: one}) as run:
    mujou.time.sleep(0.2)
tree = run.state_dict()  # after a normal end: the state at the stop
saved = tree["nodes"]["integrator"]  # this node's state_dict()
print("state of the node:", {k: type(v).__name__ for k, v in saved.items()})
file = io.BytesIO()  # or a path, such as "state.pt"
# .cpu(): every tensor on the CPU, so that a machine without the GPU reads it too.
torch.save(tree.cpu(), file)

# A new instance of the same network goes on from the saved state and time.
restored = Model()
file.seek(0)
loaded = torch.load(file)  # the default weights_only=True reads a StateDict
with mujou.run(restored, inputs={restored.prev: one}, state=loaded) as run:
    mujou.time.sleep(0.1)
after = run.state_dict()["nodes"]["integrator"]

x0, x1 = saved["x"].item(), after["x"].item()
print(f"x = {x0:.3f} at the save, {x1:.3f} after 0.1 s more")
# The integral went on from the saved value: from 0, it would be about 0.1. (How
# far it gets in 0.2 s and 0.1 s depends on when the last update falls.)
assert x1 > x0 > 0
# The module was restored too: the new instance had other random weights.
assert torch.equal(after["readout"]["weight"], saved["readout"]["weight"])

    手順は次のとおり。

    1. ノードは状態にする値を torch.Tensor か nn.Module の属性に持つ。mujou.Node が自動で状態に集める（サンプルの self.x と self.readout）
    2. 状態のテンソルは on_start で作り、on_update ではその場で更新する（+=、add_、copy_ など）
    3. ホストが run.state_dict() で状態の木を取得する。実行中でも、with 文を抜けた後（正常に終了した後）でも取得できる
    4. 木を torch.save などで保存する。保存方法はホストが決める
    5. 復元するときは同じ構成の新しいインスタンスを作り、mujou.run(net, state=tree) に渡す

    既定の load_state_dict は on_start で作ったテンソルへその場でコピーして状態を戻すので、手順 2 では更新もその場で行う。そうすれば、ほかの属性やローカル変数に取っておいた同じテンソルへの参照も復元した値を指す。

    1 つのネットワークは 1 回しか走らせられないので、手順 5 では新しいインスタンスを作る。木を取得したネットワークをもう一度 mujou.run に渡すと RuntimeError になる。

    復元するときの注意¶

    • タイマーの時刻が木の時刻に戻る。 既定のグローバルタイマーで走らせた場合、復元するとグローバル時刻（mujou.time.now()）が木を取得した時刻に戻る。mujou.run(..., state=tree) が戻った時点で時刻はすでに戻っている。復元前に読んだ mujou.time.now() の値と復元後の時刻を比べてはならない。経過時間は復元後に読んだ時刻同士の差で測る
    • 同じタイマーでほかの実行が走っている間は復元できない。 このとき mujou.run は何も起動せずに ValueError を送出する。先にほかの実行を終了させるか、復元する実行に専用の mujou.time.Timer() を渡す（時間の制御）
    • 復元するネットワークは、ノードのパスと接続が木を取得したネットワークと同じでなければならない。違えば mujou.run は ValueError を送出する
    • state= と inputs= を両方渡すと、inputs の値が木の中の入力の値を上書きする
    • 経路に沿って運ぶ付随データ（経路に沿ってデータを運ぶ）も木に入る。それを運ぶメッセージと一緒に入り、recv_carry を持つ Port ごとに、最後に受け取ったメッセージの付随データも入る。復元したノードは、止めずに回した場合と同じデータを中継する

    複数の実行の状態を同じ時刻で取る¶

    run.state_dict() は 1 つの実行の状態を 1 つの時刻で取得する。複数の実行が 1 つのタイマーを共有しているとき（既定ではどの実行もグローバルタイマーで走る）、状態を 1 つずつ取得するとその間にも時間が進むので、後で取得した状態ほど時刻が遅れる。

    すべてを同じ時刻で取得するには、先にタイマーを止めて状態を取得し、それから再開する。

    # Two runs on the global timer, such as two agents that should be saved together.
a, b = Clock(), Clock()
with mujou.run(a) as run_a, mujou.run(b) as run_b:
    mujou.time.sleep(0.1)
    mujou.time.pause()  # the global time stops at one time T
    try:
        tree_a = run_a.state_dict()  # still works while paused
        tree_b = run_b.state_dict()
    finally:
        mujou.time.resume()  # the time goes on from T
    mujou.time.sleep(0.05)

# Both trees are of T, and no update in them is later than T.
t_ns = tree_a["timer"]["time_ns"]
assert tree_b["timer"]["time_ns"] == t_ns
assert tree_a["last_update_ns"][""] <= t_ns and tree_b["last_update_ns"][""] <= t_ns
data = pickle.dumps({"a": tree_a, "b": tree_b})  # save them together

    タイマーが止まっている間も run.state_dict() は取得でき、どの木も止めた時刻を持つ。止まっている間はノードが更新せず、止まっていた時間は resume 後の dt に入らない（時間を止める）。

    resume は finally に書く

    例外で時間が止まったままにならないよう resume は finally に書く。

    同じタイマーでほかの実行が走っている間は木を復元できない点に注意する。前の実行が終わってから 1 つずつ復元するか、復元する実行それぞれに専用のタイマーを渡す。どのタイマーも木の同じ時刻から始まる。

    例外で終了したときは保存できない¶

    例外で終了した実行では run.state_dict() は NetworkError を送出し、状態を返さない（例外と終了）。

    長い実行では定期的に保存する

    長く走らせる実行で状態を失いたくなければ、実行中に定期的に run.state_dict() で取得して保存する。

    自動で集まらないものを状態に入れる¶

    自動で集まるのは属性に直接代入した torch.Tensor と nn.Module だけである（Mujou の仕組み）。次のものは自動では集まらない。

    • 数値の属性（ステップ数のカウンタなど）
    • テンソルのリストや dict
    • 乱数生成器 self.generator の状態
    • optimizer の状態（モーメントなど）と、.grad に溜めた勾配

    数値・文字列・None とそのリストや dict は、属性に代入してから register_state で名前を登録すれば状態に入る。後で何を代入しても del するまで状態に残る。

    self.elapsed = 0.0
self.register_state("elapsed")

    既定の load_state_dict は保存した値のコピーを属性に代入する。登録できるのは代入済みの属性だけで、登録は __init__ か on_start で行う。復元では新しいインスタンスを使うので、それより後（on_update の中など）で初めて登録した名前は復元先でまだ登録されておらず、復元が失敗する。既定の torch.load で読むなら値は基本的な型に限る（保存の形式）。

    それ以外のものは state_dict と load_state_dict の両方を override する。super() を呼べば、自動で集めた分と登録した分はそのまま扱える。

    次の例では乱数生成器の状態を足す。復元では新しいインスタンスを使い生成器も seed から作り直すので、生成器の状態を足さないと、復元後の乱数列が止めずに続けたときと違う列になる。

    from typing import Any, override

from mujou import Node


class Noisy(Node):
    @override
    def state_dict(self) -> Any:
        state = super().state_dict()
        state["generator"] = self.generator.get_state()
        return state

    @override
    def load_state_dict(self, state: Any) -> None:
        state = dict(state)  # 渡された木を書き換えないよう、写してから取り出す
        self.generator.set_state(state.pop("generator"))
        super().load_state_dict(state)

    override するときは次を守る。

    hook 守ること
    state_dict() pickle できるオブジェクトを返す。この中で Port の recv と send を呼ばない（RuntimeError になる）。更新中のテンソルをそのまま入れてよい（mujou が木をコピーする）
    load_state_dict(state) state は state_dict() が返したもののコピー。on_start の後、最初の on_update の前に呼ばれる

    on_stop で状態を変えない

    on_stop では状態を変えない。正常に終了した後の run.state_dict() は on_stop の後にノードが残した状態を写し、時刻は shutdown が終了を求めた時点にする。on_stop で変えた値は木に入ってしまう（理由は状態）。

    保存の形式¶

    run.state_dict() が返す木は mujou.StateDict である。dict の派生なので dict と同じようにキーで引け、pickle でも torch.save でも保存できる。読み込んだ木も mujou.StateDict に戻る。

    自分で使うファイルならどちらでもよい。木を他人と共有するなら torch.save で保存し、相手が既定の torch.load で読めるようにする。mujou.run(..., state=) には mujou.StateDict のほか、同じ中身の素の dict も渡せる。

    読むときは保存時と同じ方法を使う（pickle.dumps なら pickle.loads、torch.save なら torch.load）。保存方法が分からないファイルは、まず既定の torch.load で読む。それが失敗したら、送り手を信頼できるときだけ pickle で読む。

    • torch.load は既定（weights_only=True）で、テンソル・数値・文字列・dict・list・tuple だけからなる木を読める。mujou.StateDict も import mujou した後なら読める。登録した属性や state_dict の override から独自クラスのオブジェクトが木に入ると、既定の torch.load では読めない
    • pickle.load と torch.load(..., weights_only=False) は、読むときにファイルの中のコードを実行できる。信頼できないファイルをこれらで読まない
    • CUDA で計算するノードの状態は CUDA のテンソルのまま木に入る。tree.cpu() は木の中のテンソルをすべて CPU に移した新しい木を返す（元の木は変えない）。保存前に CPU に移せば GPU の無いマシンでも読める。CUDA のまま保存したファイルは torch.load(..., map_location="cpu") で読む。既定の load_state_dict はノードのデバイスへコピーするので、CPU のテンソルのまま state= に渡してよい
    torch.save(run.state_dict().cpu(), "state.pt")  # GPU のノードの状態も CPU のテンソルで保存する
tree = torch.load("state.pt")  # mujou.StateDict

    tree.to(device) は木のテンソルをすべて device に移す。cpu() は to("cpu") と同じ。

    辿るのは木の中の dict（nn.Module の state_dict の OrderedDict も含む）・list・tuple で、これらの入れ物は新しく作る。テンソル以外の値は元の木と共有する。torch.Tensor.to と同じく、すでに device にあるテンソルはコピーせず元の木と共有する。
