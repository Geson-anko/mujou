    ネットワークを束ねる¶

    複数のネットワークを 1 つの実行で走らせるには、mujou.run(a, b) に並べて渡すか、mujou.Group で束ねる。このページは、その書き方と、束ねずに別々の実行に分けるべき場面を説明する。

    書き方¶

    # By keyword: two networks connected before they are grouped.
enc, dec = Stage(2.0), Stage(3.0)
enc.next.connect(dec.prev)  # the ports a network exposes, as for nodes
x = torch.tensor([1.0, -1.0])
with mujou.run(Group(enc=enc, dec=dec), inputs={enc.prev: x}) as run:
    # x takes a few updates to pass through the nodes, and how many fit in a given
    # time depends on how the threads get scheduled: follow the output until y
    # arrives (TimeoutError after 5 s).
    # The ports are those of the networks given.
    y, _ = run.wait_for(dec.next, lambda y: torch.equal(y, 6 * x), timeout=5.0)
    nodes = list(run.state_dict()["nodes"])
print(f"keyword: nodes {nodes}, y = {y}")
assert nodes == ["enc.scale", "dec.scale"]
assert torch.equal(y, 6 * x)

# By position: two independent networks in one run.
first, second = Stage(2.0), Stage(3.0)
with mujou.run(first, second, inputs={first.prev: x, second.prev: x}) as run:
    y1, _ = run.wait_for(first.next, lambda y: torch.equal(y, 2 * x), timeout=5.0)
    y2, _ = run.wait_for(second.next, lambda y: torch.equal(y, 3 * x), timeout=5.0)
    nodes = list(run.state_dict()["nodes"])
print(f"position: nodes {nodes}, y1 = {y1}, y2 = {y2}")
assert nodes == ["0.scale", "1.scale"]
assert torch.equal(y1, 2 * x) and torch.equal(y2, 3 * x)

    mujou.run(a, b) は mujou.run(Group(a, b)) と同じである。名前を付けたいときは Group をキーワード引数で使う。

    束ねたネットワークは、Group が付けた名前の下にパスを持つ。

    書き方 a の中のノード l1 のパス
    mujou.run(a) "l1"
    mujou.run(a, b) "0.l1"
    Group(a, b) "0.l1"
    Group(enc=a, dec=b) "enc.l1"

    パスは状態の木のキーになる。位置で渡すかキーワードで渡すかでパスは変わる。保存した状態を復元するときは、保存したときと同じ形で束ねる。順を同じにし、キーワードは保存したときに使ったところでだけ使う。形が違うとパスが合わず、mujou.run(..., state=tree) が ValueError になる（状態の保存と復元）。

    ノード 1 つを渡す mujou.run(node) も、ネットワーク 1 つのときと同じく名前を足さない。ノードのパスは ""、その Port のパスは "prev" などになる。Group(node) は名前を足すので、ノードのパスは "0" になる。

    空の名前や . を含む名前など、使えない名前をキーワードにすると ValueError になる。

    束ねる前につなぐ¶

    束ねたネットワーク同士は、束ねる前に Port を connect でつないでおけば、つながったまま走る。Group 自体は何もつながない。上の例では enc.next.connect(dec.prev) の後に Group(enc=enc, dec=dec) で束ねている。

    入力を書く Port と出力を読む Port は、渡したネットワークの Port をそのまま使う（enc.prev、dec.next）。Group の属性を経由しなくてよい。

    1 つのネットワークを mujou.run(a) で単独で走らせると、そのネットワークは単独で構築される。その後で同じネットワークを mujou.run(a, b) に渡すと、最初の実行が走っている間でも終わった後でも RuntimeError になる。最初からまとめて走らせるか、新しいインスタンスを作る。

    束ねるか、別々に走らせるか¶

    束ねたネットワークは 1 つの実行になる。1 つの実行は、1 本のタイマー、1 つの状態の木、1 つの終了を共有する。束ねるか分けるかは、これを共有したいかで決める。

    共有されるもの 束ねたとき 別々の実行で、別々の Timer を渡したとき
    つなぐこと できる できない。別の実行の Port はつなげない
    状態の取得 全ノードを同時に止め、同じ時刻の状態を 1 つの木で取る 実行ごとに取る。取得で止まるのはその実行だけ
    時間の速さ 全ノードで同じ 実行ごとに変えられる
    例外 1 つのノードの例外で、全ネットワークが終了する 例外を投げたノードの実行だけが終了する

    次の場面では、束ねずに別々の実行にし、それぞれに mujou.time.Timer() を渡す。

    • 一方の状態を取るときに、もう一方を止めたくない
    • 一方の時間を速めたり遅めたりしたい
    • 一方が例外で止まっても、もう一方を動かし続けたい

    別々の実行でも、timer を渡さなければ、どちらもグローバルタイマーを共有する。その場合、一方で状態を取るともう一方の時間も止まる。止め合いたくないなら、別々の Timer を渡す。

    timer_a, timer_b = mujou.time.Timer(), mujou.time.Timer()
with mujou.run(a, timer=timer_a) as run_a, mujou.run(b, timer=timer_b) as run_b:
    timer_a.sleep(2.0)   # a の実行のタイマーで待つ

    Timer の使い方は時間の制御にある。
