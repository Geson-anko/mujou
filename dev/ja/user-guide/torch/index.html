    🔥 ノードの中の PyTorch¶

    ノード内の計算には PyTorch を使う。このページでは更新手法、デバイスと乱数、ノード内での誤差逆伝播（BP）、CUDA の扱い、プロセス全体に効く設定を説明する。

    更新手法¶

    on_update(dt) に書く更新が、そのノードの更新手法（学習則）である。mujou はノード・Port・実行の基盤に更新手法を組み込まないので、ノードごとに選んで差し替えられる。

    • 既定の更新手法は PC-ALM（Augmented Lagrangian Predictive Coding、https://pub.sakana.ai/pc-alm/）。局所的な更新で BP に近い性能を出せると報告されている。ただし暫定的な選択である
    • BP も 1 つのノードの内側に閉じていれば、更新手法の 1 つとして使える（下の「ノードの中の BP」）

    PC-ALM のノードは未実装

    PC-ALM のノードはモジュール mujou.pc から提供する予定。それまでは mujou.Node を継承し、on_update(dt) に更新式を自分で書く（ノードを書く）。

    例¶

    次のノードは入力から目標への線形写像をオンラインで学び、予測を送る。BP はこのノードの中に閉じている。

    BATCH, N_IN, N_OUT = 16, 4, 2
INPUT, OUTPUT = TensorSpec((BATCH, N_IN)), TensorSpec((BATCH, N_OUT))
MAX_STEP = 0.01  # seconds: a longer explicit Euler step could diverge


class Regressor(Node):
    """Learns to map its input to the target online, and sends its prediction."""

    def __init__(self, rate: float) -> None:
        super().__init__(seed=0)  # the seed of self.generator; computes on the CPU
        self.rate = rate
        self.prev = PrevPort(recv=INPUT)
        self.target = Port(recv=OUTPUT)
        self.next = NextPort(send=OUTPUT)

    @override
    def on_start(self) -> None:
        super().on_start()
        self.model = nn.Linear(N_IN, N_OUT, device=self.device)
        # The node's own generator, not the global one that all nodes share.
        nn.init.normal_(self.model.weight, std=0.1, generator=self.generator)
        nn.init.zeros_(self.model.bias)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x, y = self.prev.recv(), self.target.recv()
        params = list(self.model.parameters())
        # Split a long dt into n equal steps instead of clipping it: none of the
        # elapsed time is lost.
        n = max(1, math.ceil(dt / MAX_STEP))
        h = dt / n
        for _ in range(n):
            with torch.enable_grad():  # mujou: local-autograd
                loss = nn.functional.mse_loss(self.model(x), y)
                grads = torch.autograd.grad(loss, params)
            for p, g in zip(params, grads, strict=True):
                p -= h * self.rate * g  # in place, outside the block: not recorded
        self.next.send(self.model(x))

    サンプルの online_learning.py では、同様のノードが実行中に目標の変わるストリームから学び、その変化に追従する。

    デバイスと seed¶

    デバイスと乱数の seed は __init__ で super().__init__(device=..., seed=...) に渡す。

    • device は CPU（既定の "cpu"）か CUDA のデバイスで、mujou はこの 2 つだけをサポートする。それ以外のデバイス（"mps" や "meta" など）は ValueError になる。CUDA が使えない環境で CUDA を渡しても ValueError になる
    • 受け取ったメッセージ（recv() の値）はノードのデバイスに届く
    • テンソルは device=self.device を付けて確保する

    乱数生成器¶

    乱数はノード自身の生成器 self.generator から引く。生成器は seed から作られ、ノードのデバイス上にある。

    nn.init.normal_(self.model.weight, std=0.1, generator=self.generator)
noise = torch.randn(4, generator=self.generator, device=self.device)
    • self.generator はノードのスレッドで作られるので、on_start から使える。__init__ の中で使うと RuntimeError になる
    • ノードの中で torch.manual_seed を呼ばない。既定の生成器はプロセス全体で共有されるので、ほかのノードの乱数まで変わる
    • 生成器は起動のたびに seed から作り直される。状態から復元した後も同じ乱数列を続けたいときは、生成器の状態を状態の木に入れる（状態の保存と復元）

    ノードの中の BP¶

    既定の更新手法 PC-ALM は更新式を直接計算し、autograd のグラフを必要としない。そのため mujou はノードのスレッドで勾配の記録を切っている（torch.set_grad_enabled(False)）。

    ノードの中で autograd を使うときは次のように書く。

    1. 順伝播と勾配の計算（torch.autograd.grad か .backward()）の両方を with torch.enable_grad(): で囲む
    2. その with の行に、BP がこのノードの中に閉じていることを示す印 # mujou: local-autograd を付ける
    3. パラメータはブロックの外でその場で更新する（例の p -= h * self.rate * g）。ブロックの外では勾配を記録しないので、更新が autograd のグラフに入らない

    BP はノードの中に閉じ、ほかのノードへ勾配を流すことはできない。recv() が返す値はコピーで、send() は値を detach() してから送る。

    • torch.inference_mode() は使わない。その中で作ったテンソルは backward に使えない
    • .backward() で .grad に溜めた勾配と optimizer の状態は、状態の木に自動では入らない。復元後も同じように続けたいときは state_dict を override して足す（状態の保存と復元）
    • 更新量は dt に比例させる。例では dt を長さ MAX_STEP 以下の n 個の刻み h = dt / n に分け、刻みごとに勾配を計算し直して n 回更新する。こうすると dt が長くても陽的 Euler 法が発散せず、経過時間も失われない

    CUDA¶

    device に CUDA を渡したノードには mujou が次を設定する。

    • ノードのスレッドの現在のデバイスをノードのデバイスにする
    • ノード専用の CUDA ストリームを作り、そのスレッドの現在のストリームにする。ノードの演算はすべてこのストリームに積まれる
    • 各 on_update の後と状態の取得・復元の前後に、ノードのストリームを同期する

    そのためノードの作者は同期を書かなくてよい。自分で同期するときは自分のストリーム（torch.cuda.current_stream().synchronize()）だけを同期する。

    __init__ はホストのスレッドで動きノードのストリームの外にあるので、テンソルや nn.Module は on_start 以降で作る。

    デバイス全体を待たない

    デバイス全体を待つ torch.cuda.synchronize() はほかのノードの仕事まで待つので使わない。

    device="cuda" のように番号を付けないと、ノード作成時のホストの現在のデバイスになる。

    run.state_dict() が返す木では、CUDA のノードの状態は CUDA のテンソルのまま。保存前に cpu() で木のテンソルをすべて CPU に移せば、GPU の無いマシンでも読める。復元時は既定の load_state_dict がノードのデバイスへコピーし直す（状態の保存と復元）。

    torch.save(run.state_dict().cpu(), "state.pt")

    プロセス全体に効く設定¶

    次の設定はプロセス全体で共有されるので、ノードの中では変えない。必要ならホストが mujou.run の前に 1 回だけ設定する。

    • torch.manual_seed と既定の乱数生成器
    • torch.set_num_threads、torch.use_deterministic_algorithms、torch.backends.* のフラグ
    • torch.cuda.synchronize()、torch.cuda.empty_cache() などデバイス全体に効く操作

    ノードの中で変えてよいのはスレッドごとの設定だけで、on_thread_start に書く。on_thread_start はノードのスレッドで on_start の直前に 1 回呼ばれる hook である。

    内部のスレッド数¶

    各ノードは自分のスレッドで計算し、CPU 上の torch の演算はそのスレッドごとにさらに内部のスレッドを使う。内部のスレッドが多いとノード同士で CPU を取り合い、全体が遅くなる。

    mujou は内部のスレッド数を設定しないので、ホストが mujou.run の前に決める。

    # Each node computes on its own thread, and torch adds threads of its own for
# each: keep those few (a setting of the whole process, made by the host).
torch.set_num_threads(1)

    スレッド数の目安

    CPU で計算するノードの数と torch.set_num_threads(n) の n の積が、物理コア数を超えないようにする。小さな行列を扱うノードが多いときは n = 1 でよい。
