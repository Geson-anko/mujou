    🕸️ ネットワークを組む¶

    ネットワークは mujou.Network を継承したクラスとして書く。このページでは次のことを説明する。

    • ノードのつなぎ方
    • 外に公開する Port
    • 入れ子
    • 分岐と合流
    • 経路に沿ったデータの運び方
    • 構築した構造の確かめ方

    ネットワークの考え方はネットワークと Port と Channel を参照。

    基本の形¶

    __init__ では次の 3 つを順に書く。

    1. ノード（または別のネットワーク）を属性に代入する
    2. それらの Port を connect でつなぐ
    3. 外からつなぎたい Port や読み書きしたい Port をネットワークの属性に代入して公開する
    class Affine(mujou.Network):
    """``x -> scale -> shift ->``: y = 2 x + 1."""

    def __init__(self) -> None:
        super().__init__()
        self.scale = Scale(2.0)
        self.shift = Shift(1.0)
        self.scale.next.connect(self.shift.prev)
        self.prev = self.scale.prev  # the input of the network
        self.next = self.shift.next  # the output of the network

    super().__init__() は最初に呼ぶ。nn.Module がサブモジュールを登録するのと同じく、ネットワークは属性に代入されたノード・ネットワーク・Port をその時点で登録する。そのため super().__init__() より前に代入すると AttributeError になる。

    ノードは 1 つずつ属性に代入する

    ノードをリストや dict に入れて持たせても登録されず、ネットワークの一部にならない。ノードは 1 つずつ属性に代入する。

    つなぐ¶

    2 つの Port は a.next.connect(b.prev) のように Port.connect でつなぐ。ノードとネットワークは connect を持たない。ノードの入出力は複数ありうるので、Port を 2 つとも書くことでどの経路をつなぐかが常に読み取れる。

    慣習では前のノード側の Port を PrevPort にして prev、次のノード側の Port を NextPort にして next と名付ける。こうするとつないだ列が a.next.connect(b.prev) と読める。

    名前と種類は向きを読みやすくするためだけのもの。PrevPort と NextPort が Port と違うのは既定で取る相手の数（PrevPort は 1 つ、NextPort は複数）だけで、1 つのノードがそれぞれをいくつ持ってもよい。

    接続できるのは、片方の send の spec がもう片方の recv の spec と一致し、逆向きも一致するときだけ。一致しなければ connect を呼んだ時点で TypeError になる。相手を 1 つしか取らない Port に 2 本目の Channel をつなぐと ValueError になる。

    connect は作った接続（Channel）を返す。これは分岐で相手ごとに違う値を送るときに使う（このページの分岐と合流）。

    Port を公開する¶

    子の Port をネットワークの属性に代入すると、その Port を公開できる。

    公開すると外から短い名前で Port を指せる。慣習では最初のノードの Port を prev、最後のノードの Port を next として公開する（self.prev = self.l1.prev）。するとネットワークもノードと同じように x.next.connect(net.prev)、net.next.connect(y.prev) とつなげる。ほかの Port は net.teacher のようにそれぞれの名前で公開する。

    公開できるのはそのネットワークの中のノードが持つ Port だけ。

    ホストは run.write で、受け取る Port のうちつながっていないものに値を書ける。公開しているかどうかは問わず、run.write({net.head.teacher: y}) のように子の属性をたどって Port を指せばよい。公開は指す名前を短くするだけ。

    入れ子にする¶

    ネットワークは別のネットワークを属性に持てる。子のネットワークが prev と next を公開していれば、ノードの Port と同じようにつなぐ。

    class Stack(mujou.Network):
    def __init__(self) -> None:
        super().__init__()
        self.l1 = Hidden(784, 256)
        self.l2 = Hidden(256, 256)
        self.l1.next.connect(self.l2.prev)
        self.prev = self.l1.prev
        self.next = self.l2.next


class Classifier(mujou.Network):
    def __init__(self) -> None:
        super().__init__()
        self.body = Stack()
        self.head = Head()
        self.body.next.connect(self.head.prev)  # body.next の実体は l2.next
        self.prev = self.body.prev     # 子が公開した Port を、さらに公開する
        self.teacher = self.head.teacher

    Hidden と Head はそれぞれ PrevPort と NextPort を持つノードとする。Head は教師信号を受け取る Port（teacher）も持つ。

    ノードはルートからの属性名を . でつないだパスで区別される。この例のノードのパスは "body.l1"、"body.l2"、"head" になる。

    属性名を変えるとパスが変わる

    属性名を変えるとパスが変わり、変える前に保存した状態を復元できなくなる（状態の保存と復元）。

    ノードはほかのノードやネットワークを属性に持てず、代入すると ValueError になる。並べたいノードはネットワークの属性に並べる。

    分岐と合流¶

    1 つの Port に複数の Channel をつなぐと分岐と合流になる。次の例では split の出力を 2 つに分け、sum で合わせる。

    class Split(Node):
    """Sends ``x`` on the channel ``plus`` and ``-x`` on the channel ``minus``."""

    # Channels of self.next, set by the network to the ones connect returned.
    plus: Channel
    minus: Channel

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=VECTOR)
        self.next = NextPort(send=VECTOR)  # many peers by default

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x = self.prev.recv()
        self.next.send_to(self.plus, x)
        self.next.send_to(self.minus, -x)


class Apply(Node):
    """Sends ``fn(x)``."""

    def __init__(self, fn: Callable[[torch.Tensor], torch.Tensor]) -> None:
        super().__init__()
        self.fn = fn
        self.prev = PrevPort(recv=VECTOR)
        self.next = NextPort(send=VECTOR, multi=False)  # exactly one peer here

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x = self.prev.recv()
        self.next.send(self.fn(x))


class Sum(Node):
    """Sends the sum of the messages of all its peers."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=VECTOR, multi=True)  # merges any number of peers
        self.next = NextPort(send=VECTOR)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        received = self.prev.recv()  # dict[Channel, torch.Tensor]
        self.next.send(torch.stack(list(received.values())).sum(dim=0))


class Diamond(mujou.Network):
    """``split -> (double, square) -> sum``: y = 2 x + (-x)^2."""

    def __init__(self) -> None:
        super().__init__()
        self.split = Split()
        self.double = Apply(lambda x: 2 * x)
        self.square = Apply(lambda x: x**2)
        self.sum = Sum()
        # Hand split the channels it sends on: the order of connect does not matter.
        self.split.plus = self.split.next.connect(self.double.prev)
        self.split.minus = self.split.next.connect(self.square.prev)
        self.double.next.connect(self.sum.prev)
        self.square.next.connect(self.sum.prev)
        self.prev = self.split.prev
        self.next = self.sum.next

    分岐: 送る側¶

    NextPort は既定で複数の相手を取れるので、a.next.connect(b.prev) と a.next.connect(c.prev) を続けて書けば分岐する。送り方は 2 つある。

    送り方 送り先 Run.read で読める値
    send(value) すべての相手に同じ値 更新される
    send_to(channel, value) channel の先の相手だけ 更新されない

    send_to だけを使う Port をホストが Run.read で読むと、その Port の初期値（initial。無ければゼロ）が返る。send_to で送った値をホストが読む方法は無い。

    Run.read は送る型を持つ Port しか読まないので、受け取るだけの Port（各枝の prev）も読めない。ホストが読めるのは、枝のノードが受け取った値から計算して send した結果（上の例なら net.double.next の 2 x）になる。

    send_to に渡す Channel は送り先ごとに区別して持つ。上の例のように、ネットワークで connect が返す Channel を送る側のノードの属性に代入する（self.split.plus = self.split.next.connect(self.double.prev)）。

    Channel を順番で取り出さない

    self.next.channels（つないだ順に並ぶ）から取り出すと、connect を書く順を入れ替えたときにエラーも出ずに値の送り先が入れ替わってしまう。

    Channel を代入した属性は状態に集まらない。

    合流: 受け取る側¶

    PrevPort(multi=True) は複数の相手から受け取る。相手が複数の Port の recv() は Channel をキーにした dict をつないだ順に返す。まだ一度も送っていない相手の Channel の値は、相手の Port の初期値になる（initial を宣言していなければゼロ）。

    複数の値をどう束ねるか（足す、平均する、相手ごとに重みを掛ける）は受け取るノードが決め、mujou は束ねない。上の例の Sum は足している。

    相手ごとに扱いを変えるときは、send_to と同じく相手ごとの Channel を受け取るノードに持たせる。self.sum.from_double = self.double.next.connect(self.sum.prev) とし、ノードの中で self.prev.recv()[self.from_double] と読む。

    NextPort も既定で複数の相手を取るので、その recv() は dict を返す。次のノードが 1 つだけと決まっているなら、NextPort(send=..., multi=False) にすると recv() が dict ではなく値を返す。

    経路に沿ってデータを運ぶ¶

    メッセージは、値と一緒に付随データ（サンプルの ID やターゲットなど）を運べる。経路の先のどのノードも、値を、その値の元になったサンプルの付随データと組で受け取る。付随データを別の Port で運ばずに同じメッセージに入れるのは、このためである。2 つの Port を読むノードは、それぞれを別々の瞬間に読むので、値を別のサンプルのデータと組んでしまうことがある。

    付随データは Port で向きごとに宣言する。

    引数 意味
    recv_carry=spec 受け取るメッセージに載る付随データ。相手を 1 つしか取らない Port だけが持てる
    send_carry=spec 送るメッセージに載せる付随データ。send(value, carry=data) で渡し、値と同じくコピーされる
    send_carry=port 同じノードの Port port（recv_carry を持つ）が最後に受け取ったメッセージの付随データを中継する。send は carry を取らない。データはコピーせずに共有する

    port.carried() は、recv で最後に受け取ったメッセージの付随データのコピーを返す（port.carried("key") は DictSpec のそのフィールドだけ）。最初の recv の前と、相手がまだ送っていない間はゼロである（復元した実行では、状態の木の "carries" の値）。このゼロは、実際に送られたゼロと区別できない。区別したいときは、データが有効かどうかを表すフィールド（真偽値のマスクなど）を付随データに入れる。

    次の例では、Stamp が各サンプルに ID を付け、Double がそれを中継し、Report が値と組にする。

    class Stamp(Node):
    """Sends the input with the time it was written at as its ID."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=SAMPLE)  # the host writes it
        self.next = NextPort(send=SAMPLE, send_carry=SAMPLE_ID)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x, written_at = self.prev.recv_with_time()
        self.next.send(x, carry=torch.tensor(written_at.ns))


class Double(Node):
    """Sends ``2 x``, carrying on what came with ``x``."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=SAMPLE, recv_carry=SAMPLE_ID)
        self.next = NextPort(send=SAMPLE, send_carry=self.prev)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        self.next.send(2 * self.prev.recv())


class Report(Node):
    """Sends each value with the ID it carries, for the host to read."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=SAMPLE, recv_carry=SAMPLE_ID)
        self.next = NextPort(send=REPORTED)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        value = self.prev.recv()
        self.next.send({"value": value, "id": self.prev.carried()})

    ホストは各サンプルを書き込み、その ID を運んできた報告を待つ。

    def main() -> None:
    net = Pipeline()
    with mujou.run(net) as run:
        for k in range(3):
            written_at = run.write({net.prev: torch.full((2,), float(k))})
            report, _ = run.wait_for(
                net.next, lambda r: r["id"].item() == written_at.ns, timeout=5.0
            )
            print(k, report["value"])  # 2 k, never the value of another sample
    • connect は付随データが向きごとに一致するかも確かめ、一致しなければ TypeError を送出する
    • 中継できるのは同じノードの Port の付随データだけ。違えばネットワークの構築で ValueError になる
    • send_carry を持つ Port をホストが読むと、値だけが返る。run.read（とほかの読み方）は付随データを捨てる。付随データのうちホストに見せたいものは、Report のように普通のメッセージで送る
    • recv_carry を持つ Port には、ホストは書けない。書き込みは値しか渡さず、付随データを作れないので、run.write は ValueError を送出する

    構築した構造を確かめる¶

    net.build() は構造と型を検査して凍結し、構築した構造（Graph）を返す。mujou.run も内部で build() を呼ぶので、走らせるだけなら呼ぶ必要はない。走らせる前に構造を確かめたいときに呼ぶ。

    net = Diamond()
graph = net.build()  # what mujou.run runs; mujou.run(net) builds the same graph
print("nodes:", [path for path, _ in graph.nodes])
print("output port:", graph.port_path(net.next))

    build() はネットワークを凍結する

    build() の後は次のことができない。

    • 木の中のどの Port にも connect する
    • 木のノードとネットワークに Port・ノード・ネットワークを代入する、または削除する（どちらも RuntimeError）
    • より大きなネットワークの一部にする

    そのため build() を呼ぶのは走らせるネットワークだけにする。

    構造が不正なら build() が理由を添えて ValueError を送出する。Graph と不正の原因の一覧は API リファレンスを参照。
