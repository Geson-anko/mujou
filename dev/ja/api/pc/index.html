    PC-ALM¶

    mujou.pc ¶

    PC-ALM (augmented Lagrangian predictive coding) as nodes of mujou.

    Each node holds a part of the model and learns from its neighbors' messages only: Input takes the samples the host writes, each Layer wraps a module as one constraint h = f(h_in), and Output holds the last module and the loss. Inside a node, the module is differentiated by autograd; between nodes, activities (Activity) flow to the next node and gradients of the energy to the previous one. The target of each sample travels with its input in the Activity, so the output node pairs every prediction with its own target. Chain connects the nodes for a sequence of modules, and show shows it a sample. Each node gives the spec of what it sends as act_spec, which the next node takes, to build other shapes by hand. MSELoss and CrossEntropyLoss give the loss of each sample. LearnClock and functional hold the parts the nodes are made of, for writing nodes of your own.

    The samples are independent and the shapes start with the batch, batch: () (the default) for one sample at a time, B for B samples, or a shape of several dimensions.

    Import it as a submodule::

    import mujou.pc as pc

B = 64
net = pc.Chain(
    nn.Sequential(nn.Linear(784, 256), nn.ReLU()),
    nn.Linear(256, 10),
    x=TensorSpec((B, 784)),
    y=TensorSpec((B,), torch.int64),
    batch=B,
    loss=pc.CrossEntropyLoss(B),
    tau=pc.TimeConstants(h=4e-3, lam=8e-3, theta=1.28),
    learn_interval=0.15,
)

    Bases: Network

    Input -> Layer -> ... -> Output: a network that learns modules in sequence by PC-ALM, as nn.Sequential(*modules) would compute them.

    modules[:-1] each become a Layer and modules[-1] the Output, after an Input of the samples x and targets y. Each node takes the act_spec of the one before and the nodes are connected in order. The children are input, layer0, ..., output (modules[i] is in layer{i}, also layers[i]), which are also their paths in Run.state_dict(). Every node runs with the period tau.period (tau.h / 4); for other periods, build the nodes one by one (show shows them samples too).

    The host writes a Sample to prev and reads a Prediction from next, or does both with show.

    Example::

    B = 64
net = pc.Chain(
    nn.Sequential(nn.Linear(784, 256), nn.ReLU()),
    nn.Linear(256, 10),
    x=TensorSpec((B, 784)),
    y=TensorSpec((B,), torch.int64),
    batch=B,
    loss=pc.CrossEntropyLoss(B),
    tau=pc.TimeConstants(h=4e-3, lam=8e-3, theta=1.28),
    learn_interval=0.15,
)
with mujou.run(net) as run:
    prediction = pc.show(run, net, sample, seconds=0.2)

    Bases: Node

    A node that takes the samples the host writes and sends them on as the Activity of the next node, with their targets.

    The host writes a Sample (x, y and mask) to prev with Run.write. In each on_update the node sends from next an Activity whose h is x, with y, mask and the time (ns) at which the host wrote them: the nodes on the path pass them on with the activity computed from x, so that the output node pairs each prediction with its own target. A new time tells them the input changed. jumps counts the writes the node has seen, so that the next node moves its h with a new x even when it was written at the same time as the zeros before it (time 0). x is clamped: what the next node sends back on next is not read.

    Before the host first writes, the node sends zeros with mask False, jumps 0 and time 0. The state holds "jumps" and the time (ns) of the last write seen ("seen_write", None before any). act_spec is the spec of what the node sends, for the next node.

    Example::

    B = 64
inp = pc.Input(
    x=TensorSpec((B, 784)),
    y=TensorSpec((B,), torch.int64),
    period=1e-3,
    batch=B,
)
...
mask = torch.ones(B, dtype=torch.bool)
with mujou.run(net) as run:
    run.write({inp.prev: {"x": x, "y": y, "mask": mask}})

    Layer ¶

    Layer(
    module: Module,
    *,
    act_spec: DictSpec[Activity],
    tau: TimeConstants,
    learn_interval: float | None,
    period: float | None = None,
    max_dt: float | None = None,

    Bases: Node

    A node that wraps module as one constraint h = f(h_in; theta) of PC-ALM.

    It predicts mu = module(h_in) from the activity h_in of the previous node, and holds its own activity h, which it sends to the next nodes, and the dual lam of the constraint. With \(r = h - \mu\), \(\delta = r + \lambda\) and the sum \(g\) of what the next nodes send back:

    \[ \tau_h \dot h = -(r + \lambda + g),\qquad \tau_\lambda \dot\lambda = r,\qquad \tau_\theta \dot\theta = -g_\theta / B, \]

    where \(B\) is the number of samples in the batch (1 without one), \(g_\theta = -J_\theta^\top \delta\) and the node sends \(g_{\mathrm{in}} = -J_h^\top \delta\) to the previous node (both from one vector-Jacobian product of module, functional.vjp). At a fixed point, \(r = 0\) (h is the forward pass) and lam is the credit \(-\partial\ell/\partial h\) of backpropagation. Inside the node, module is differentiated by autograd; between nodes, only these messages flow.

    h follows the gradient flow above, with the mu of the moment: when the nodes below relax, h_in and mu move continuously and h only relaxes towards them. Where mu jumps, h moves with it once, so that the deviation r = h - mu and lam are kept, and only they are:

    • With a new sample (the time of the activity changed), or when the h_in it reads jumped (its jumps changed), the node moves h <- mu + (h - mu_last) with the mu_last of its previous update. Without a target, h is thus the forward pass.
    • When it updates theta, it computes once more, without gradients, mu' = f(h_in; theta_new) at the same h_in, and moves h <- h + (mu' - mu) at the start of its next update, with mu_last <- mu'. Only the jump that theta makes moves h, not the drift of h_in. The move waits one update so that the next nodes, which may read h before they learn, see it as a jump (it is sent with new jumps) rather than learn from it.

    The node advances its jumps once in an update that moves h with a new sample or a jump of h_in, or by a jump of theta while learn_interval is set; the next node then moves with it in turn, so a jump runs up the path with r unchanged at every node, whenever each node learns. With learn_interval=None, theta moves by dt in every update, continuously: the node moves its own h but does not advance its jumps, as moving every node above in every update would hold r rather than h as the state, which diverges in deep chains.

    Each on_update(dt):

    1. reads the activity and ticks its clock, which caps dt at max_dt;
    2. moves h by the jump of theta of the previous update, if any;
    3. computes mu, g_in and, when it learns, g_theta with the delta before this update, zero for the samples whose mask is False, and sends g_in;
    4. with a new input or new jumps of h_in, moves h with mu; then moves h and then lam by dt with the g the next nodes sent (functional.relax_);
    5. sends h with its jumps, and the y, mask and time that came with h_in;
    6. when it learns, moves theta by the time since its last update (functional.learn_) and computes the jump of mu it made.

    Its clock (a LearnClock) tells when it learns: in its first update once learn_interval seconds have passed since the host wrote the input (its time, on the run's time), and then every learn_interval seconds while the input stays, but never in the update that first sees an input (its delta is still that of the input before); with learn_interval=None, in every update; with tau.theta infinite, never (LearnClock.of). The nodes read the one timer of the run, so the nodes on a path learn at about the same time, however deep they are, and each from the relaxed delta of the same input. A learn_interval longer than the round trip of the credit down the path and back (2 * hops * period, with hops the number of connections from the Input to the Output) is recommended: with intervals of a few periods, every node learns, and so advances its jumps, in almost every update, the nodes above move h with every change of mu, and deep chains have been seen to diverge however slowly theta moves. The node does not learn when no sample of the input has a target (every mask is False): that time is dropped from the next update, which would otherwise learn from the delta left over from an earlier input. Nor does it keep the time of an input that changed before the node learned from it. Until the first sample reaches the node, the activity is zeros (mask all False, time 0), so it does not learn then.

    dt is capped because the nodes are coupled explicitly: g was made from h as it was when the next node last updated. After a long stall (a loaded machine), the step dt / tau.h of every node grows at once and the coupling makes the network diverge, which no split of the step inside the node prevents. The time beyond max_dt is dropped, from the relaxation and from the weight of the next update of theta alike. The default tau.max_dt, min(tau.h / 2, 3 * tau.lam), keeps the step of h and lam stable in the node itself.

    module must treat the samples of the batch independently (no BatchNorm in training mode): the gradient of each sample must be its own. It must also be deterministic and keep no state of its own (no Dropout, no BatchNorm in training mode): an update that learns calls it once more on the same h_in to find the jump of theta, which would otherwise add noise, or update running statistics a second time. Its parameters that require gradients learn; set requires_grad to False to freeze one. It is called once on zeros when the node is made, to find the shape and dtype of h.

    The state (Run.state_dict()["nodes"][path]["state"]) holds "generator" (the state of the node's generator), "module" (its state_dict), "h" and "lam" ((*batch, *out)), the prediction of the last update ("mu"), the jump of theta still to add to h ("jump", and "jumped" whether there is one), the jumps it sends and the last ones it read ("jumps", "seen_jumps") and when to learn ("clock", the state of the LearnClock). To watch the node while it runs, read them there: Run.state_dict() pauses the run, whereas reading module, h or lam from the host's thread races with the node's updates in place. act_spec is the spec of what the node sends, for the next node.

    Example::

    B = 64
tau = pc.TimeConstants(h=4e-3, lam=8e-3, theta=1.28)
inp = pc.Input(
    x=TensorSpec((B, 784)),
    y=TensorSpec((B,), torch.int64),
    period=tau.period,
    batch=B,
)
hidden = pc.Layer(
    nn.Sequential(nn.Linear(784, 256), nn.ReLU()),
    act_spec=inp.act_spec,
    tau=tau,
    learn_interval=24e-3,
)
inp.next.connect(hidden.prev)
hidden.next.connect(out.prev)  # out: a pc.Output, or another pc.Layer

    Bases: Node

    A node that predicts y_hat = module(h_in) and whose energy is the loss of the samples that have a target.

    It pairs h_in with the target y and mask of the same Activity, so the prediction always meets the target of the very input it was computed from, however fast the host writes. With

    \[ \ell = \sum_b \mathrm{mask}_b\, \ell_b(\hat y_b, y_b),\qquad \tau_\theta \dot\theta = -\frac{1}{B}\frac{\partial\ell}{\partial\theta}, \]

    where \(B\) is the number of samples in the batch (1 without one), it sends \(g_{\mathrm{in}} = \partial\ell/\partial h_{\mathrm{in}}\) to the previous node (functional.loss_vjp): zero for a sample without a target while its y_hat is finite. Each on_update(dt) caps dt at max_dt as Layer does, reads the Activity, sends g_in, sends a Prediction (y_hat with the y, mask and time it was paired with) for the host to read, and updates theta when it learns. It does not read the jumps: a jump of h_in needs no move here, as the node holds no activity of its own.

    It learns as Layer does, by its clock: once learn_interval seconds have passed since the host wrote the input, but not in the update that first sees it, or in every update with None. When no sample has a target, it does not learn and drops the time since the last update; so too before the first sample arrives, while the activity is zeros (mask all False), and when the input changes before it has learned from it. B is the number of samples in the batch, not the number of samples with a target: a sample without one adds zero.

    loss returns the loss of each sample, of the shape of the batch (that of mask), such as MSELoss(batch) or CrossEntropyLoss(batch), and the node sums them. A loss that averages over the batch (such as nn.MSELoss()) would scale the gradient that flows back by 1 / B, so the node refuses it when it is made: it calls module and loss once on zeros then (functional.loss_vjp), which also finds the shape of y_hat. module must treat the samples independently, as in Layer.

    The state holds "generator", "module" and when to learn ("clock"). Read it with Run.state_dict(), as for Layer.

    Example::

    out = pc.Output(
    nn.Linear(256, 10),
    act_spec=hidden.act_spec,  # hidden: a pc.Layer
    loss=pc.CrossEntropyLoss(B),
    tau=tau,
    learn_interval=24e-3,
)
hidden.next.connect(out.prev)
# The host: prediction = run.read(out.next); prediction["y_hat"], ...

    TimeConstants dataclass ¶

    TimeConstants(*, h: float, lam: float, theta: float)

    The time constants of the continuous-time PC-ALM, in seconds.

    A node relaxes its activity h, its dual lam and its parameters theta with

    \[ \tau_h \dot h = -(r + \lambda + g),\qquad \tau_\lambda \dot\lambda = r,\qquad \tau_\theta \dot\theta = -g_\theta / B \]

    (\(r = h - \mu\)), and a step of dt seconds moves them by dt / tau of the right-hand side (the discrete step sizes are eta_h = dt / h, alpha = dt / lam and eta_theta = dt / theta). One update of theta that weighs elapsed seconds is thus one step of SGD on the mean gradient of the batch with the learning rate elapsed / theta.

    lam=math.inf makes the dual stay at zero (alpha = 0, plain predictive coding), and theta=math.inf makes the parameters stay where they are (no learning). h must be finite.

    The fields are keyword-only: all three are floats, and a swap by position could not be caught by the type checker.

    Example::

    tau = TimeConstants(h=4e-3, lam=8e-3, theta=1.28)
pc_only = TimeConstants(h=4e-3, lam=math.inf, theta=1.28)
    RAISES DESCRIPTION
    ValueError

    h is not finite and > 0, or lam or theta is not

    0 (NaN is not).

    period property ¶

    period: float

    The default period of a node, h / 4: a step of h of eta_h = 0.25 per update, about that of the official implementation of PC-ALM, and well within the measured stable range eta_h <= 0.5 (specs/pc.md).

    max_dt property ¶

    max_dt: float

    The default longest dt an update counts, min(h / 2, 3 * lam): the explicit Euler step of h then lam is stable for dt / h <= 1/2 and dt / lam <= 3 (specs/pc.md, "dt の打ち切り"). Every node of a chain caps at the same time, so that they weigh their updates of theta alike.

    LearnClock ¶

    LearnClock(*, period: float, learn_interval: float | None, max_dt: float)

    Decides, update by update, when a node updates its parameters, from the time the host wrote the node's input.

    The node calls tick(dt, time_ns, now_ns) once in each update, with the dt of the update, the time (ns) the input it received was written at, and the time now (ns) on the run's timer. The clock learns in the first update at or after time_ns + k * learn_interval (k = 1, 2, ...), but never in the update that first sees an input: its gradient is still that of the input before. The nodes on a path read the one timer of the run, so they learn at about the same time, however deep they are. With learn_interval=None, it learns in every update, a new input or not; with math.inf, never.

    A Tick with learn counts as learned: the next interval starts there, whether the node updates its parameters or skips them for want of a target. elapsed sums the capped dt since then; an input that changes before the clock learned from it drops that sum, as an input without a target does, or inputs that change faster than learn_interval would pile the time up into one large update. dt is capped at max_dt, and the time beyond it is dropped from elapsed too.

    The clock starts as if it had seen no input (no time a host writes at): the first update sees a new input, also one written at time 0.

    The state (state_dict()) holds the time of the input seen last ("seen_ns", None before any), the time from which the next update learns ("learn_at_ns"), "elapsed", and whether the clock has learned since the input changed ("learned_input"). An attribute of a node that holds a LearnClock is in the node's state by itself.

    It is not tied to PC-ALM: any node that learns from inputs the host writes can use it. LearnClock.of makes the clock of a node of PC-ALM from its time constants.

    Example::

    self.clock = pc.LearnClock(period=self.period, learn_interval=24e-3,
                           max_dt=2e-3)
# In on_update(dt):
tick = self.clock.tick(dt, int(activity["time"]), self.timer.now().ns)
# ... move by tick.dt; if tick.learn, learn weighted by tick.elapsed.
    PARAMETER DESCRIPTION
    period

    The period of the node, in seconds.

    TYPE: float

    learn_interval

    The time in seconds from the write of an input to the first update of the parameters, and between the updates while the input stays. None learns in every update, math.inf never.

    TYPE: float | None

    max_dt

    The longest dt an update counts, in seconds.

    TYPE: float

    RAISES DESCRIPTION

    learn_interval is neither None nor > 0, max_dt is not > 0, or period is longer than max_dt.

    Whether the clock learns at intervals (learn_interval is not None), so that each update of the parameters is a jump rather than a step of a continuous flow.

    Activity ¶

    Bases: TypedDict

    The activity a node sends to the next nodes, with the target of each of its samples.

    The shapes start with the batch, batch: () for one sample, (B,) for B samples, or more dimensions (see activity_spec).

    • h: the activity, (*batch, *out).
    • jumps: () int64, the number of times the sender's h has jumped rather than relaxed continuously: an Input counts the writes of the host, and a Layer counts its moves with a new sample and with a jump of the h it receives, and the jumps of its own theta when it learns at intervals (learn_interval not None). A change tells the receiver to move its own h with its prediction, so that the jump does not enter its deviation h - mu (Layer).
    • y: the target of each sample, (*batch, *target).
    • mask: batch bool, whether each sample has a target. A sample whose mask is False adds nothing to the loss, whatever its y is.
    • time: () int64, the time in nanoseconds that Run.write returned for the input h was computed from; 0 before the host first writes.

    y, mask and time come from the Sample the host wrote, and every node passes them on with the h it computed from it, in the same message: the output node pairs each prediction with its own target, however fast the host writes.

    show ¶

    show(run: Run, chain: _Shown, sample: Sample, *, seconds: float) -> Prediction

    Return the prediction chain makes for sample before it learns from it (a prequential prediction), after showing it seconds long.

    chain is a Chain, or any network of the nodes of mujou.pc that exposes the prev of its Input and the next of its Output. Writes sample to chain.prev, waits for the first prediction the host reads for that write, and returns it once seconds (of run.timer) have passed since the write, while the nodes learn from the sample (Sample.mask True) or only relax towards it (every mask False, as to evaluate, where a seconds that lets the input reach the output is enough). A node learns from a sample from its second update with it on (learn_interval after the write, when set), and the first prediction of the sample is made of the first activities with it, so the prediction comes before learning unless the host reads it later than that.

    Nothing moves the timer of a ManualRun, so there it does not return.

    Example::

    mask = torch.ones(B, dtype=torch.bool)
p = pc.show(run, net, pc.Sample(x=x, y=y, mask=mask), seconds=0.2)
correct = int((p["y_hat"].argmax(1) == y).sum())
    RAISES DESCRIPTION

    TypeError

    sample lacks a key, or has one too many.
    RuntimeError

    The run shut down normally before the prediction.
    NetworkError

    activity_spec ¶

    activity_spec(h: TensorSpec, y: TensorSpec, batch: Size = ()) -> DictSpec[Activity]

    Return the spec of an Activity whose h is of the spec h, whose targets are of the spec y and whose samples are batch.

    mujou.pc.functional ¶

    The stateless computations of PC-ALM that the nodes of mujou.pc are made of, for writing nodes of your own (such as one with several inputs).

    A node i predicts mu = f(h_in; theta) from the activity h_in of the previous node, and keeps its activity h and the dual lam of the constraint h = mu. Its energy is E = 0.5 * ||h - mu + lam||^2 (r = h - mu, delta = r + lam).

    • vjp gives the gradients of E with respect to h_in and theta (one vector-Jacobian product inside the node). The node sends the one of h_in to the previous node, which adds the values it receives into its g.
    • loss_vjp does the same for an output node, whose energy is the loss.
    • relax_ moves h and lam by dt seconds; learn_ moves theta.
    • mse and cross_entropy are losses of each sample, for loss_vjp (MSELoss and CrossEntropyLoss hold their batch).

    Every g here is a gradient of an energy; the update subtracts it. Gradients are summed over the batch, and the 1 / B (B the number of samples) is applied to theta only (in learn_), so lam holds the credit of each sample. The shapes start with the batch, batch (see activity_spec).

    vjp ¶

    vjp(
    module: Callable[[Tensor], Tensor],
    h_in: Tensor,
    delta: Callable[[Tensor], Tensor],
    params: Sequence[Tensor] = (),
) -> tuple[torch.Tensor, torch.Tensor, list[torch.Tensor]]

    Predict mu = module(h_in) and the gradients of the node's energy.

    With the activity \(h\) held fixed, the energy \(E = \tfrac12\|h - \mu + \lambda\|^2\) has the gradients

    \[ g_{\mathrm{in}} = \frac{\partial E}{\partial h_{\mathrm{in}}} = -J_h^\top \delta,\qquad g_\theta = \frac{\partial E}{\partial \theta} = -J_\theta^\top \delta, \]

    where \(\delta = h - \mu + \lambda\) and \(J\) are the Jacobians of module at h_in. Both are summed over the batch. h_in is detached first, so no graph reaches the node that sent it.

    PARAMETER DESCRIPTION
    module

    The function f of the node, (*batch, *in) -> (*batch, *out). It must treat the samples independently.

    TYPE: Callable[[Tensor], Tensor]

    h_in

    The activity of the previous node, (*batch, *in).

    TYPE: Tensor

    delta

    Makes \(\delta\) of the node, (*batch, *out), from mu (detached, without gradients), such as lambda mu: h - mu + lam.

    TYPE: Callable[[Tensor], Tensor]

    params

    The parameters to get the gradients of, usually those of module that require gradients.

    TYPE: Sequence[Tensor] DEFAULT: ()

    RETURNS DESCRIPTION
    Tensor

    (mu, g_in, g_theta): mu ((*batch, *out), detached), g_in
    Tensor

    ((*batch, *in)) and g_theta (one tensor per parameter, in the order of
    list[Tensor]

    params; a parameter that module does not use gets zeros).
    RAISES DESCRIPTION
    ValueError

    delta does not make a tensor of the shape of mu.

    loss_vjp ¶

    loss_vjp(
    module: Callable[[Tensor], Tensor],
    h_in: Tensor,
    y: Tensor,
    mask: Tensor,
    loss: Callable[[Tensor, Tensor], Tensor],
    params: Sequence[Tensor] = (),
) -> tuple[torch.Tensor, torch.Tensor, list[torch.Tensor]]

    Predict y_hat = module(h_in) and the gradients of the masked loss.

    The energy of an output node is the loss of the samples that have a target,

    \[ \ell = \sum_b \mathrm{mask}_b\, \ell_b(\hat y_b, y_b),\qquad g_{\mathrm{in}} = \frac{\partial \ell}{\partial h_{\mathrm{in}}},\qquad g_\theta = \frac{\partial \ell}{\partial \theta}. \]

    A sample whose mask is False adds nothing, whatever its y is (NaN too): its y is replaced by zeros before loss sees it, and its g_in is \(J^\top 0\), zero as long as its y_hat is finite (NaN where it is not). With every mask False, g_in is thus zeros. h_in is detached first.

    module

    The function f of the node, (*batch, *in) -> (*batch, *out).

    TYPE: Callable[[Tensor], Tensor]

    h_in

    The activity of the previous node, (*batch, *in).

    TYPE: Tensor

    y

    The target, (*batch, *target).

    TYPE: Tensor

    mask

    Whether each sample has a target, batch bool.

    TYPE: Tensor

    loss

    The loss of each sample, (y_hat, y) -> batch, such as MSELoss(batch) or CrossEntropyLoss(batch).

    TYPE: Callable[[Tensor, Tensor], Tensor]

    params

    The parameters to get the gradients of.

    TYPE: Sequence[Tensor] DEFAULT: ()

    RETURNS DESCRIPTION

    (y_hat, g_in, g_theta) as vjp returns (mu, g_in, g_theta).

    relax_ ¶

    relax_(
    h: Tensor, lam: Tensor, mu: Tensor, g: Tensor, dt: float, tau: TimeConstants
) -> None

    Move h and lam in place by one explicit Euler step of dt seconds of

    \[ \tau_h \dot h = -(r + \lambda + g),\qquad \tau_\lambda \dot\lambda = r,\qquad r = h - \mu. \]

    The step moves h first and then lam with the r of the moved h. mu and g are held fixed. The step is not split: g comes from the next nodes and stays as it was over dt, so the coupling between the nodes is explicit however finely the step is split. Keep dt short instead (Layer caps it at max_dt). tau.lam = inf leaves lam exactly as it is.

    PARAMETER DESCRIPTION
    h

    The activity of the node, (*batch, *out).

    TYPE: Tensor

    lam

    The dual of the node's activity, (*batch, *out).

    TYPE: Tensor

    mu

    The prediction f(h_in) of the node, (*batch, *out).

    TYPE: Tensor

    g

    The sum of the gradients the next nodes sent, (*batch, *out).

    TYPE: Tensor

    dt

    The time to move by, in seconds.

    TYPE: float

    tau

    The time constants; tau.h and tau.lam are used.

    TYPE: TimeConstants

    learn_ ¶

    learn_(
    params: Sequence[Tensor],
    g_theta: Sequence[Tensor],
    elapsed: float,
    tau: TimeConstants,
    batch: Size,
) -> None

    Move params in place by elapsed seconds of tau_theta * dtheta/dt = -g_theta / B.

    That is one gradient step on the mean loss of the batch with the learning rate elapsed / tau.theta: p -= (elapsed / tau.theta) * g / B, where B is the number of samples in batch (1 for ()). tau.theta = inf makes the rate 0, which leaves params as they are while the gradients are finite; the nodes of mujou.pc do not call it then (LearnClock.of never learns).

    The parameters of the node.

    g_theta

    TYPE: Sequence[Tensor]

    elapsed

    The time since the last update of params, in seconds.

    TYPE: float

    tau

    The time constants; tau.theta is used.

    mse ¶

    mse(y_hat: Tensor, y: Tensor, batch: Size = ()) -> torch.Tensor

    Return the mean squared error of each sample of batch.

    The squared error is averaged over the dimensions of a sample, as nn.MSELoss averages it, but not over the batch: the mean of the result is nn.MSELoss()(y_hat, y), and with the 1 / B of learn_, theta follows its gradient.

    With d values in a sample, its gradient with respect to y_hat is (2 / d) * (y_hat - y): that of 0.5 * ||y - y_hat||^2 for d = 2, twice it for d = 1. The larger it is, the more strongly the output pulls on the activities, and the shorter the period that keeps their explicit steps stable; for a scalar target, a loss of your own such as 0.5 * mse(y_hat, y, batch) keeps the pull of the half.

    PARAMETER DESCRIPTION
    y_hat

    The prediction, (*batch, *out).

    TYPE: Tensor

    y

    The target, of the same shape as y_hat.

    TYPE: Tensor

    batch

    The batch that the shapes start with; () for one sample.

    TYPE: Size DEFAULT: ()

    RETURNS DESCRIPTION
    Tensor

    The loss of each sample, batch.
    RAISES DESCRIPTION

    The shapes differ (a broadcast would silently give another shape), or they do not start with batch.

    cross_entropy ¶

    cross_entropy(y_hat: Tensor, y: Tensor, batch: Size = ()) -> torch.Tensor
