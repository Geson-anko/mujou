    💾 Saving and Restoring State¶

    This page shows how to take the state of a running network, save it, and later run the network again from that state.

    What the state tree holds, and how time stops while the state is taken, is in State.

    The basic steps¶

    The following example runs a network for 0.2 seconds, takes its state, saves it with torch.save, restores it into a new instance, and goes on running.

    """Save the state of a run, and restore it in a new run that goes on from there.

A node collects its state by itself: every attribute that holds a
``torch.Tensor`` or an ``nn.Module``. ``Run.state_dict`` gathers the states of all
nodes, the latest messages and the time into one tree, a ``mujou.StateDict``.
Save it with ``torch.save`` (or pickle), and read it back with ``torch.load``.
"""

import io
from typing import override

import torch
from torch import nn

import mujou
from mujou import NextPort, Node, PrevPort, TensorSpec

VECTOR1 = TensorSpec((1,))


class Integrator(Node):
    """Integrates its input over time (dx/dt = u) and sends ``readout(x)``."""

    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=VECTOR1)
        self.next = NextPort(send=VECTOR1)

    @override
    def on_start(self) -> None:
        super().on_start()
        self.x = VECTOR1.zeros()  # a tensor: part of the state
        # A module: part of the state.
        self.readout = nn.Linear(1, 1, device=self.device)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        self.x += dt * self.prev.recv()  # in place, so that a restore copies into it
        self.next.send(self.readout(self.x))


class Model(mujou.Network):
    def __init__(self) -> None:
        super().__init__()
        self.integrator = Integrator()
        self.prev = self.integrator.prev
        self.next = self.integrator.next


one = torch.ones(1)

# Run for a while, then stop and take the state at the end.
net = Model()
with mujou.run(net, inputs={net.prev: one}) as run:
    mujou.time.sleep(0.2)
tree = run.state_dict()  # after a normal end: the state at the stop
saved = tree["nodes"]["integrator"]  # this node's state_dict()
print("state of the node:", {k: type(v).__name__ for k, v in saved.items()})
file = io.BytesIO()  # or a path, such as "state.pt"
# .cpu(): every tensor on the CPU, so that a machine without the GPU reads it too.
torch.save(tree.cpu(), file)

# A new instance of the same network goes on from the saved state and time.
restored = Model()
file.seek(0)
loaded = torch.load(file)  # the default weights_only=True reads a StateDict
with mujou.run(restored, inputs={restored.prev: one}, state=loaded) as run:
    mujou.time.sleep(0.1)
after = run.state_dict()["nodes"]["integrator"]

x0, x1 = saved["x"].item(), after["x"].item()
print(f"x = {x0:.3f} at the save, {x1:.3f} after 0.1 s more")
# The integral went on from the saved value: from 0, it would be about 0.1. (How
# far it gets in 0.2 s and 0.1 s depends on when the last update falls.)
assert x1 > x0 > 0
# The module was restored too: the new instance had other random weights.
assert torch.equal(after["readout"]["weight"], saved["readout"]["weight"])

    The steps are as follows.

    1. The node keeps the values of its state in attributes that hold a torch.Tensor or an nn.Module. mujou.Node collects them into the state automatically (self.x and self.readout in the example)
    2. The node creates the state tensors in on_start, and updates them in place in on_update (+=, add_, copy_, ...)
    3. The host takes the state tree with run.state_dict(). It works while the network runs, and also after the with statement exits (after a normal end)
    4. The host saves the tree with torch.save or the like. How to save it is up to the host
    5. To restore, create a new instance of the same network and pass it as mujou.run(net, state=tree)

    Step 2 updates in place because the default load_state_dict restores the state by copying into the tensors created in on_start. With in-place updates, any other attribute or local variable that refers to the same tensor also sees the restored values.

    Step 5 needs a new instance because a network can run only once. Passing the network the tree was taken from to mujou.run again raises RuntimeError.

    When you restore¶

    • The timer goes back to the time of the tree. On the default global timer, restoring sets the global time (mujou.time.now()) back to the time the tree was taken. When mujou.run(..., state=tree) returns, the time has already gone back. Do not compare a mujou.time.now() read before the restore with a time read after it. Measure elapsed time as the difference between two times read after the restore
    • You cannot restore while another run is running on the same timer. In that case mujou.run raises ValueError and starts nothing. End the other run first, or give the restored run a timer of its own, mujou.time.Timer() (see Controlling time)
    • The restored network must have the same node paths and connections as the network the tree was taken from. Otherwise mujou.run raises ValueError
    • If you pass both state= and inputs=, the values in inputs override the input values in the tree

    Taking the states of several runs at one time¶

    run.state_dict() takes the state of one run at one time. When several runs share a timer (by default, all of them run on the global timer) and you take their states one after another, each state is of a later time than the one before, because the time goes on in between.

    To take them all at one time, pause the timer first, take the states, and resume it.

    # Two runs on the global timer, such as two agents that should be saved together.
a, b = Clock(), Clock()
with mujou.run(a) as run_a, mujou.run(b) as run_b:
    mujou.time.sleep(0.1)
    mujou.time.pause()  # the global time stops at one time T
    try:
        tree_a = run_a.state_dict()  # still works while paused
        tree_b = run_b.state_dict()
    finally:
        mujou.time.resume()  # the time goes on from T
    mujou.time.sleep(0.05)

# Both trees are of T, and no update in them is later than T.
t_ns = tree_a["timer"]["time_ns"]
assert tree_b["timer"]["time_ns"] == t_ns
assert tree_a["last_update_ns"][""] <= t_ns and tree_b["last_update_ns"][""] <= t_ns
data = pickle.dumps({"a": tree_a, "b": tree_b})  # save them together

    run.state_dict() works while the timer is paused, and every tree then holds the time of the pause. While paused, the nodes do not update, and the paused time does not enter the dt after resume (see Pausing the time).

    Put resume in finally

    Put the resume in finally, so that an exception does not leave the time stopped.

    To restore the trees, note that a run cannot restore while another run is running on the same timer. Restore them one after another once the previous run has ended, or give each restored run a timer of its own; each timer then starts from the same time of the trees.

    The state is not saved after an exception¶

    When a run ends with an exception, run.state_dict() raises NetworkError and returns no state (see Errors and shutdown).

    Save regularly during a long run

    If you do not want to lose the state of a long run, take run.state_dict() regularly while it runs and save it.

    Putting other values in the state¶

    Only torch.Tensor and nn.Module values assigned directly to attributes are collected (see How Mujou works). The following are not collected.

    • Number attributes (such as a step counter)
    • Lists and dicts of tensors
    • The state of the random number generator self.generator
    • The state of an optimizer (such as moments) and the gradients accumulated in .grad

    To put these in the state, override both state_dict and load_state_dict. Call super(), and the automatically collected part is handled as before.

    For a number, you can instead keep it as a 0-dimensional tensor created in on_start (self.count = torch.zeros((), device=self.device)) and update it in place (self.count += 1), without overriding anything. It is then collected automatically.

    The following example adds the state of the random number generator. The generator is created again from seed every time the run starts. Without its state, the random numbers after a restore differ from those of a run that went on without stopping.

    from typing import Any, override

from mujou import Node


class Noisy(Node):
    @override
    def state_dict(self) -> Any:
        state = super().state_dict()
        state["generator"] = self.generator.get_state()
        return state

    @override
    def load_state_dict(self, state: Any) -> None:
        state = dict(state)  # copy first, so the given tree is not modified
        self.generator.set_state(state.pop("generator"))
        super().load_state_dict(state)

    When you override them, follow these rules.

    Hook Rules
    state_dict() Return an object that pickles. Do not call recv or send on a port in it (that raises RuntimeError). You may put the live tensors in it; Mujou copies the tree
    load_state_dict(state) state is a copy of what state_dict() returned. It is called on the node's thread, after on_start and before the first on_update

    Do not change the state in on_stop

    Do not change the state in on_stop. After a normal end, run.state_dict() copies the state as the nodes left it, after on_stop, with the time at which shutdown asked the run to stop. A change made in on_stop would go into the tree (the reason is in State).

    Formats¶

    The tree run.state_dict() returns is a mujou.StateDict. It is a subclass of dict: you index it as a dict, and you can save it with pickle or with torch.save. A tree read back is a mujou.StateDict again.

    For your own files, either will do. To share a tree with others, save it with torch.save, so that they can read it with the default torch.load. mujou.run(..., state=) takes a mujou.StateDict, or a plain dict of the same items.

    Read a file back the same way it was saved (pickle.loads for pickle.dumps, torch.load for torch.save). If you do not know how a file was saved, read it first with the default torch.load. If that fails, read it with pickle only when you trust the sender.

    • torch.load with its default (weights_only=True) reads a tree made only of tensors, numbers, strings, dicts, lists and tuples. It reads a mujou.StateDict too, once mujou is imported. If you override state_dict to put objects of your own classes in the tree, the default torch.load cannot read it
    • pickle.load and torch.load(..., weights_only=False) can run code from the file while reading it. Do not read files you do not trust with them
    • The state of a node that computes on CUDA goes into the tree as CUDA tensors. tree.cpu() returns a new tree with every tensor of the tree on the CPU (the tree itself is not changed). Move the tree to the CPU before saving it, and a machine without a GPU can read it too. To read a file saved with CUDA tensors, use torch.load(..., map_location="cpu"). The default load_state_dict copies to the node's device, so you can pass the CPU tensors to state= as they are
    torch.save(run.state_dict().cpu(), "state.pt")  # the state of GPU nodes as CPU tensors
tree = torch.load("state.pt")  # a mujou.StateDict

    tree.to(device) moves every tensor of the tree to device, and cpu() is to("cpu").

    It looks into the dicts (including the OrderedDict of the state_dict of an nn.Module), lists and tuples of the tree, and makes these containers anew. Other values are shared with the original tree. As with torch.Tensor.to, a tensor already on device is not copied but shared with the original tree
