    Nodes¶

    mujou.Node ¶

    Node(
    *,
    device: device | str = "cpu",
    seed: int | None = None,
    period: float = 0.01,
    dedicated_thread: bool = False,
)

    Bases: Node, Component

    A unit of asynchronous computation: the leaf of a network.

    Declare the ports as instance attributes in __init__, after super().__init__() (build rejects ports declared on the class). The node registers them as they are assigned. A node must not hold other nodes or networks as attributes (assigning one raises ValueError); put them side by side in a Network instead.

    Override the lifecycle hooks below; each does nothing by default, except state_dict and load_state_dict. As in any subclass, call super().__init__() first in __init__ and the same hook of super() first in each override. The framework calls the hooks on the thread that runs the node (see "Threads" below), except state_dict:

    • on_start(): once, when the network runs (also when it was restored). Allocate and initialize the state here. A node with dedicated_thread=True gets it on its own thread, so it can also make its per-thread settings here.
    • load_state_dict(state): only when the network was restored, after on_start and before the first on_update. state is a copy of what this node's state_dict returned. By default it copies the state into the collected tensors and modules (see below). When device is CUDA, the framework waits for the node's stream after it.
    • on_update(dt): repeatedly, once every period on average (see below). dt is the time in seconds on the run's timer since the node's last update. Read the ports with recv, update in proportion to dt, and write the ports with send. It never waits for other nodes.
    • on_pause(): when the node has stopped for a pause of the network (as Run.state_dict does). on_resume(): when the pause ends, before the next on_update.
    • on_exception(): once on every node, when a hook of any node has raised, before on_stop.
    • on_stop(): once, when the network stops, also after an exception. It must not change what state_dict returns: the state taken after a normal end is the state at the stop.
    • state_dict(): when the network's state is taken, on the runtime's control thread while the node is paused (or, after a normal end, on the host's thread that called Run.state_dict), so recv and send raise RuntimeError there. Return the node's own state as a picklable object; it may hold the live tensors, because the framework copies it before the node resumes. By default it returns the collected tensors and modules (see below).

    The node collects its state by itself, as nn.Module does: every attribute assigned a torch.Tensor (nn.Parameter included) or an nn.Module, whether or not its name starts with _, is registered under its name. Assigning any other value (None too) under that name, or del, removes it. Ports, numbers, lists and dicts of tensors are not collected, and neither are properties (what a setter stores is, under its own name). The default state_dict and load_state_dict save and restore what is registered; override both to choose the state yourself (they may call super()). Allocate the tensors of the state by on_start and update them in place afterwards: the default load_state_dict copies into them in place.

    If any hook raises, the whole network stops. A hook must not call mujou.run or the methods of any Run (write, read, state_dict, ...): they raise RuntimeError there, because a node talks only through its own ports.

    Threads: by default the node runs on the workers, a pool of threads that the run shares among its nodes (mujou.run(..., workers=...)). Each hook may then run on a different thread from the previous one, but the hooks of a node never run at the same time, and each sees what the previous one wrote. Whether the next hook sees what a hook set per thread (threading.local, threading.current_thread(), settings of torch such as torch.autocast) depends on the schedule, and the next node on the same worker may see it too: set such settings back before the hook returns (inside a with, say). contextvars do carry over: each node runs its hooks in a contextvars.Context of its own, which starts empty (it does not inherit the host's) and does not hold for state_dict. A hook that blocks (time.sleep, waiting for I/O or a lock) holds its worker meanwhile, and the other nodes' dt grows; give such a node dedicated_thread=True, so that it runs on a thread of its own, with every hook on that thread.

    Before every hook but state_dict, the framework turns off gradient recording (to backpropagate inside the node, wrap the forward computation and backward in with torch.enable_grad(): marked # mujou: local-autograd). Whenever a thread switches to the node, when device is CUDA, it also makes the device and a stream of the node's own current. These are the only per-thread settings it sets back. On CUDA it also waits for that stream after on_update (holding its worker meanwhile), after load_state_dict and around state_dict. It does this in hooks of its own, whose names start with _: do not override those, and overriding a public hook never skips them.

    The node updates once every period (0.01 s by default) of the run's timer on average: the time an update takes counts toward the period, and a node that falls a whole period behind does not update several times in a row to catch up. A pause does not count. dt is still the time that actually passed since the last update, longer than period when the node is late, so keep updating in proportion to it and stay stable for the longest dt it can get. A manual run (ManualRun.step) ignores the period.

    period=0.0 updates as soon as any time has passed since the last update. Set it only when the node must: such a node keeps a CPU core busy, and takes time from the other nodes, whose dt it makes irregular.

    device, generator, period, dedicated_thread and timer (the reading side of the run's timer) are reserved names: do not assign attributes of those names (a class attribute period or dedicated_thread makes the run raise TypeError).

    Example::

    class Hidden(Node):
    def __init__(self, n_in: int, n_out: int) -> None:
        super().__init__(seed=0)
        x, h = TensorSpec((32, n_in)), TensorSpec((32, n_out))
        # Send W^T eps back and receive x from the previous side (one peer).
        self.prev = PrevPort(send=x, recv=x)
        # Send h forward and receive W^T eps from each next peer (many).
        self.next = NextPort(send=h, recv=h)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x = self.prev.recv()  # torch.Tensor
        feedback = self.next.recv()  # dict[Channel, torch.Tensor]
        ...
        self.next.send(h)
        self.prev.send(wt_eps)


l1, l2 = Hidden(784, 256), Hidden(256, 256)
l1.next.connect(l2.prev)
    PARAMETER DESCRIPTION
    device

    Where the node computes: the CPU or a CUDA device (no other device type is supported). Received messages arrive on it. "cuda" without an index is fixed to the host's current CUDA device.

    TYPE: device | str DEFAULT: 'cpu'

    seed

    The seed of generator. None seeds it nondeterministically.

    TYPE: int | None DEFAULT: None

    period

    The time between two updates on average, in seconds of the run's timer. 0.0 updates as soon as any time has passed.

    TYPE: float DEFAULT: 0.01

    dedicated_thread

    Run the node on a thread of its own instead of the run's workers: for a node whose hooks block, or that relies on per-thread state set once (in on_start).

    TYPE: bool DEFAULT: False

    RAISES DESCRIPTION
    TypeError

    period is a bool, or dedicated_thread is not a bool.
    ValueError

    device is neither the CPU nor a CUDA device, or is CUDA while CUDA is not available, or period is negative or not finite.

    device property ¶

    device: device

    The device the node computes on and receives messages on.

    Allocate with it (torch.zeros(..., device=self.device)): the current device in the hooks is this one, but an explicit device states the intent.

    period property ¶

    period: float

    The time between two updates on average, in seconds of the run's timer. 0.0 updates as soon as any time has passed.

    dedicated_thread property ¶

    dedicated_thread: bool

    Whether the node runs on a thread of its own instead of the run's workers.

    generator property ¶

    generator: Generator

    The node's own random generator on device, seeded with seed.

    Use it instead of the global generator, which all nodes share (do not call torch.manual_seed in a node). super().__init__ creates it, so it can be used in __init__ already (to initialize modules, say), and the hooks go on with the same sequence. A restored network runs new instances, whose generators start again from seed; to continue the same sequence after a restore, add self.generator.get_state() to what super().state_dict() returns, and in load_state_dict take it out and set_state it before passing the rest to super().

    RAISES DESCRIPTION
    RuntimeError

    super().__init__() has not been called (and the node has not started).

    timer property ¶

    timer: ReadOnlyTimer

    The reading side of the timer of the run this node is in, which measures its dt.

    Read the time with self.timer.now(). The timer is the one given to mujou.run(..., timer=...), or the global timer by default. A ReadOnlyTimer only reads and does not hold the timer: a node does not change the time of its run (Timer.sleep, set_time_scale and VirtualTimer.advance raise RuntimeError in a hook). timer is a reserved name: do not assign an attribute of that name.

    It can be read from the start of the run (also in on_start). Once the host has seen a normal end (e.g. after Run.shutdown returned), it is replaced by a ReadOnlyTimer that stays at the time of the state, also in the state_dict that the host takes then. A ReadOnlyTimer kept from before the end keeps reading the running timer.

    RAISES DESCRIPTION
    RuntimeError

    The node has not run: before its run starts the nodes, after a start that was refused, or once the host has seen an end by an exception.

    on_exception method descriptor ¶

    on_exception() -> None

    Called once on every node when a hook of any node has raised, before on_stop. What it raises is logged and ignored.

    on_pause method descriptor ¶

    on_pause() -> None

    Called when the node has stopped for a pause of the run (to take the state), at the end of its current on_update.

    on_resume method descriptor ¶

    on_resume() -> None

    Called when the pause ends, before the next on_update.

    on_start method descriptor ¶

    on_start() -> None

    Called once when the run starts (also when it is restored), before any other public hook. Allocate and initialize the state here.

    on_stop method descriptor ¶

    on_stop() -> None

    Called once when the run stops, also after an exception. It must not change what state_dict returns. What it raises is logged and ignored.

    on_update method descriptor ¶

    on_update(dt: float) -> None

    Called repeatedly with dt, the seconds on the run's timer since the node's last update (always > 0). Read the ports, update in proportion to dt and send.

    state_dict ¶

    state_dict() -> Any

    Return the collected state: a dict with, for each registered attribute in the order of registration, the tensor detach-ed or the module's state_dict(), under the attribute's name.

    The tensors share memory with the attributes (the framework copies the tree). requires_grad and .grad are not part of the state, as in nn.Module.state_dict: detaching also makes a tensor that is part of an autograd graph picklable.

    load_state_dict ¶

    load_state_dict(state: object) -> None

    Copy state (from the default state_dict) into the registered attributes in place: copy_ into each tensor and load_state_dict into each module, without recording gradients.

    The objects stay the same, so references taken in __init__ or on_start see the restored values, and a tensor that records gradients stays a leaf that does. copy_ casts the dtype and moves the device. A tensor in state whose name is not registered (one first assigned after on_start) is set as a new attribute, a copy of the value, and registered. Everything is checked before anything is copied, so on an error nothing has changed.

    RAISES DESCRIPTION
    TypeError

    state or the state of a module is not a mapping, or the value for a tensor is not a tensor.
    ValueError

    A registered attribute is missing from state, a key that is not registered holds no tensor, or a tensor's shape differs or the tensor has elements that share memory.
    RuntimeError

    A module's state does not have the keys or the shapes of the module's state_dict, as nn.Module.load_state_dict (strict) raises.
