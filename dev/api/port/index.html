    Ports and Channels¶

    mujou.Port ¶

    Port(
    send: MessageSpec[S] | None = None,
    recv: MessageSpec[R] | None = None,
    *,
    multi: bool = False,
    initial: S | None = None,
    send_carry: MessageSpec[CS] | _CarrySource[CS] | None = None,
    recv_carry: MessageSpec[CR] | None = None,
)

    A connection point that sends messages of type S and receives R, carrying data of type CS with what it sends and CR with what it receives.

    Declare ports as attributes of a node (or expose a port of a child as an attribute of a network). send is the spec of what this port sends and recv the spec of what it receives; either may be omitted for a one-way port (omit it: type checkers reject None and infer Never for an omitted spec). multi=True lets the port take any number of peers (Multi) and multi=False at most one (Single). The default is one peer for Port and PrevPort, and many for NextPort. multi fixes what recv returns: the message for one peer, a dict keyed by Channel for many.

    Two ports connect when the send of each equals the recv of the other (an omitted spec matches an omitted spec). A port may stay unconnected.

    initial is what the port has sent before its first send: what its peers receive and the host reads until then. It must match send exactly, and is copied when the port is made. Without it, that is the zeros() of send. A restored run takes the values from the state instead.

    A message may carry data along a path, such as the target of a sample or its ID, in the same message as the value, so that a reader never pairs a value with the data of another sample. recv_carry is the spec of the data carried with what this port receives; carried reads it. A single peer only: a port with multi=True takes no recv_carry. send_carry says what this port carries with what it sends: a spec, and send takes the data as carry; or another port of the same node with a recv_carry, and send passes on, without copying, the data of the message that port last received (recv). Until the first send, and before the first recv of the port it passes on from, the carried data is the zeros() of its spec (in a restored run, the values under "carries" in the state). These zeros cannot be told from zeros that were sent: to tell them apart, carry a field that says whether the data is valid. The host reads only the value of a port with a send_carry (Run.read), and cannot write to a port with a recv_carry.

    Once assigned as an attribute of a node, the port is named "<node class>.<attribute>" (e.g. "Shift.next") in errors and its repr; the first assignment names it.

    PrevPort and NextPort are ports with other defaults for the number of peers, for the previous and the next side of a node by convention.

    Example::

    class Sensor(Node):
    def __init__(self) -> None:
        super().__init__()
        self.out = Port(send=TensorSpec((3,)), initial=torch.ones(3))


class Monitor(Node):
    def __init__(self) -> None:
        super().__init__()
        self.inp = Port(recv=TensorSpec((3,)))

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x = self.inp.recv()  # torch.Tensor (one peer); ones until out sends


sensor, monitor = Sensor(), Monitor()
sensor.out.connect(monitor.inp)

    A node that passes the data its input carries on to its output::

    class Scale(Node):
    def __init__(self) -> None:
        super().__init__()
        self.prev = PrevPort(recv=TensorSpec((3,)), recv_carry=TensorSpec(()))
        self.next = NextPort(send=TensorSpec((3,)), send_carry=self.prev)

    @override
    def on_update(self, dt: float) -> None:
        super().on_update(dt)
        x = self.prev.recv()
        self.next.send(2 * x)  # carries what came with x
        sample_id = self.prev.carried()  # a copy, when the node needs it
    RAISES DESCRIPTION
    TypeError

    send or recv is not a TensorSpec, a DictSpec or None; initial is given to a port without send; or initial does not match send (as send raises). send_carry is not a spec, a port or None, or is given to a port without send; recv_carry is not a spec or None, or is given to a port without recv or with multi=True; or the port given as send_carry has no recv_carry.
    ValueError

    A shape, or the keys of a dict, in initial differ from send.

    connect ¶

    connect(other: Port[Any, Any, Any, Any, Any]) -> Channel

    Connect this port to other and return the new channel.

    The channel is registered at both ports, so each can send to and receive from the other. Connecting a to b and b to a are two different channels.

    RAISES DESCRIPTION
    TypeError

    The specs are not mutually reversed (self.send_spec != other.recv_spec or self.recv_spec != other.send_spec, and likewise for send_carry_spec and recv_carry_spec), or neither direction carries a message.
    ValueError

    other is this port, or a single-peer port is already connected.
    RuntimeError

    Either port belongs to a tree that is already built (by Network.build or mujou.run).

    recv ¶

    recv() -> Any

    Return the latest message received, without waiting for a new one.

    A single-peer port returns the message itself. A multi-peer port returns {channel: message}, one entry per channel in connection order ({} while unconnected).

    The message comes from the peer's send or send_to; an unconnected single-peer port reads what the host writes with Run.write instead. Until that writer first writes, the message (or that channel's entry) is the initial value: the peer port's initial, or else the recv spec's zeros(). For a port the host writes, it is the value in inputs of mujou.run, or else the zeros(). A restored run takes it from state. has_received tells whether the writer has written yet.

    Every call copies into new tensors on the owning node's device, without gradients, so changing them in place changes nothing else. The data the message carries is not copied: carried reads it, and a port with this one as its send_carry passes it on.

    Call it only from the owning node's hooks while the network runs.

    RAISES DESCRIPTION
    RuntimeError

    The network is not running, or the caller is not a hook of the owning node (only the owner reads its port; state_dict runs on another thread).
    TypeError

    The port receives no messages.

    recv_with_time ¶

    recv_with_time() -> Any

    Like recv, but each message comes as (message, time).

    time is the Timestamp on the run's timer at which the message was written. Raises as recv does.

    has_received ¶

    has_received() -> Any

    Whether recv returns a message that its writer sent, rather than the initial value.

    The writer is the peer (its send or send_to), or the host for an unconnected single-peer port (inputs of mujou.run or Run.write). Until the writer first writes, recv returns the initial value and this returns False. A restored run keeps what was true when the state was taken.

    A single-peer port returns one bool. A multi-peer port returns {channel: bool}, keyed as recv is ({} while unconnected).

    Call it only from the owning node's hooks while the network runs. Raises as recv does.

    send ¶

    send(msg: S, carry: CS | None = None) -> None

    Send msg to every peer and to what the host reads (Run.read).

    msg must match the send spec exactly; dtypes are never converted. The values are detached and copied, so changing msg afterwards changes nothing that was sent. A CUDA tensor is copied to the host on the node's stream. It never waits for the peers to read.

    A port whose send_carry is a spec takes the carried data as carry, checked and copied as msg is. A port whose send_carry is another port takes no carry: the message carries the data of the message that port last received, shared and not copied. Type checkers accept both mistakes (carry given to a port that passes data on, or left out on a port that carries a spec); only the call rejects them.

    Call it only from the owning node's hooks while the network runs.

    RAISES DESCRIPTION
    RuntimeError

    The network is not running, or the caller is not a hook of the owning node (only the owner writes its port).
    TypeError

    The port sends no messages, a value is not a dense torch.Tensor of the spec's dtype, or a DictSpec message is not a dict; carry is missing for a port that carries a spec, or given to a port that carries nothing or passes data on.
    ValueError

    A shape, or the keys of a dict message, differ from the spec.

    send_to ¶

    send_to(channel: Channel, msg: S, carry: CS | None = None) -> None

    Send msg only to the peer across channel.

    channel is one of channels (or a key of a multi-peer recv). Unlike send, it leaves what the host reads (Run.read) unchanged: before the first send, that is this port's initial (or the zeros() of its send spec). Carries, copies and raises as send does, and raises ValueError when channel is not one of this port's.

    carried ¶

    carried(key: str | None = None) -> Any

    Return the data carried with the message last received by recv or recv_with_time.

    Before the first recv it is the data of the message the port would have received then, the zeros() of the recv_carry spec until its writer first writes. With key, only that field of a DictSpec is returned, and only it is copied.

    Every call copies into new tensors on the owning node's device, as recv does. Call it only from the owning node's hooks while the network runs.

    RAISES DESCRIPTION
    RuntimeError

    As recv does.
    TypeError

    The port has no recv_carry, or key is given for a TensorSpec.
    KeyError

    key is not a key of the DictSpec.

    mujou.PrevPort ¶

    PrevPort(
    send: MessageSpec[S] | None = None,

    Bases: Port[S, R, M, CS, CR]

    A port for the previous side of a node or network: b.prev in a.next.connect(b.prev).

    It differs from Port only in its default: one peer, as Port; pass multi=True to merge several. It is usually named prev.

    Example::

    self.prev = PrevPort(send=TensorSpec((32, 784)), recv=TensorSpec((32, 784)))
x = self.prev.recv()  # torch.Tensor

    mujou.Channel ¶

    Channel()

    One connection between two ports, made by Port.connect.

    A channel is the handle of a peer: a multi-peer port's recv is keyed by channel and send_to takes one. Channels compare by identity, so two connections between the same ports are two different keys.

    It cannot be created directly: a channel that its ports do not know would carry nothing.

    Example::

    ch = a.next.connect(b.prev)
ch.other(a.next) is b.prev  # True

    mujou.TensorSpec ¶

    TensorSpec(shape: Sequence[int], dtype: dtype | None = None)

    Bases: MessageSpec[Tensor]

    The shape and the dtype of a message that is one torch.Tensor.

    dtype defaults to torch.get_default_dtype() at the time the spec is created; changing the default later does not change existing specs. Every dimension is an int of at least 1, and () is a scalar. A batch dimension is just a part of the shape.

    Two specs are equal when their shapes and dtypes are equal. A message whose shape or dtype differs from the spec is an error; dtypes are never converted. A spec has no device: a message of the spec may be on any device.

    zeros, rand and empty make a tensor of the spec, on the CPU unless device says otherwise. For any other initial value, fill one of them in place (spec.empty().fill_(0.5)).

    Example::

    spec = TensorSpec((32, 256))  # the default dtype, usually float32
spec = TensorSpec((32, 256), torch.bfloat16)
x0 = spec.zeros()
noise = TensorSpec((4,)).rand(seed=0)  # deterministic
ones = spec.empty(device="cuda").fill_(1.0)
    RAISES DESCRIPTION
    TypeError

    A dimension is not an int, or dtype is not supported.
    ValueError

    A dimension is less than 1.

    shape property ¶

    shape: tuple[int, ...]

    The shape of the tensor.

    dtype property ¶

    dtype: dtype

    The dtype of the tensor.

    zeros ¶

    zeros(*, device: device | str = 'cpu') -> torch.Tensor

    Return a tensor of this spec filled with zeros on device.

    empty ¶

    empty(*, device: device | str = 'cpu') -> torch.Tensor

    Return a tensor of this spec on device whose values are not set.

    Set them before use, in place: spec.empty().fill_(0.5).

    rand ¶

    rand(
    seed: int | None = None,
    *,
    generator: Generator | None = None,
    device: device | str = "cpu",
) -> torch.Tensor

    Return a tensor of this spec drawn uniformly from [0, 1) on device.

    Pass seed or a generator on device to make the result deterministic; without either, the global torch generator is used. The same seed draws different values on different kinds of device.

    RAISES DESCRIPTION
    TypeError

    The dtype is not a floating point dtype.
    ValueError

    Both seed and generator are given.

    mujou.DictSpec ¶

    DictSpec(typed_dict: type[TD], /, **specs: TensorSpec)

    Bases: MessageSpec[TD]

    The spec of a message that is a TypedDict of torch.Tensor values.

    Give the TypedDict class and one TensorSpec per key. Every key of the TypedDict must be required and annotated as torch.Tensor (no nesting), and the keyword arguments must name exactly its keys. The keys keep the order in which the TypedDict defines them.

    Two specs are equal when they use the same TypedDict class and equal TensorSpec for every key.

    Example::

    class Feedback(TypedDict):
    error: torch.Tensor
    target: torch.Tensor


spec = DictSpec(
    Feedback, error=TensorSpec((32, 256)), target=TensorSpec((32, 10))
)
msg: Feedback = spec.zeros()
    RAISES DESCRIPTION
    TypeError

    typed_dict is not a TypedDict, a key is not required, a value is not annotated as torch.Tensor, or a spec is not a TensorSpec.
    ValueError

    The TypedDict has no key, or the keyword arguments miss a key or name an unknown key.

    typed_dict property ¶

    typed_dict: type[TD]

    The TypedDict class of the message.

    specs property ¶

    specs: Mapping[str, TensorSpec]

    The TensorSpec of each key, in the order the TypedDict defines.
