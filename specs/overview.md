# 概要

## mujou とは

`mujou` は **Asynchronous Distributed Deep Learning Library for Continuous Learning**。推論と学習を同時に行い、知能に「無常」（常が無いこと）を実現する、PyTorch のような深層学習フレームワークである。

名前は「諸行無常」の「無常」から取った。従来の機械学習は学習を終えたら重みを固定して推論する。mujou はストリームから学び続け、常に変化し続ける学習機械を作る。狙う用途はリアルタイム処理、ロボティクス、生涯学習し続ける機械。

## 全体像

計算はノード単位で行う。ノードの内側は同期的に計算し、ノード同士は非同期にやり取りする。ノードの大きさは、どのノードのクラスを書くか・使うかで決まる。レイヤーが既定で、複数のレイヤーやモデル全体を 1 ノードにしてもよい。ニューロン単位のノードは future work（[ノード](nodes.md)）。ノードはフレームワークが呼ぶライフサイクル hook を override して書く。

ノード同士は、lock 付きの共有スロットへ値を読み書きするだけで通信する。1 つの実行は、その実行のタイマーの上の連続時間系（微分方程式）として定義する（[実行モデル](execution-model.md)）。ノードを回す基盤は Rust で実装し、Python はインターフェースになる（[ネイティブコア](native-core.md)）。

既定の更新手法は PC-ALM（Augmented Lagrangian Predictive Coding、<https://pub.sakana.ai/pc-alm/>）。PyTorch で実装し、`mujou.pc` から公開する（[mujou.pc](pc.md)）。これは暫定の選択で、更新手法は差し替えられる（[更新手法](update-rules.md)）。

## なぜ BP を基盤にしないか

誤差逆伝播法（BP）は、ネットワーク全体の forward と backward を同期させる必要があり、継続的・非同期な学習と相性が悪い。PC-ALM は局所的な更新で BP に近い性能を出せると報告されているので、既定に選んだ。

BP を排除するわけではない。1 つのノードの内側に閉じていれば、BP もそのノードの更新手法として使える（[ノード](nodes.md#bp-の取り込み)）。

## 不変の原則

設計で迷ったときは、次を壊さない側を選ぶ。

1. 局所性: ノードは自分の状態と、隣のノードからメッセージとして受け取った値だけで更新する。ノードをまたいで計算グラフを繋げない
2. 非同期性: ノードは互いを待たない。グローバルなバリアを持たない。例外は状態の取得・復元と観測のための停止だけで、その実行のタイマーごと止める（[実行モデル](execution-model.md#グローバルなバリアとの関係)）
3. 止まらずに学び続けること: 学習モードと推論モードを分けない。エポックを前提にしない
4. 時間軸は実行ごとに 1 本: 1 つの実行の全ノード・全スロット・ホストの入力は、その実行のタイマーを使う。既定はグローバルタイマーで、復元した実行は保存した時刻から始まる専用のタイマーで走る
5. コアは Rust、利用者が扱う値は `torch.Tensor` だけ: torch とコアの間は DLPack で必ずコピーする
6. 更新手法を差し替えられること: ノード・メッセージ・スケジューラに特定の学習則を焼き付けない
7. 理論から導いたオラクルで検証すること: 「損失が下がった」ではなく、有限差分、平衡点での BP 一致、α=0 で PC への退化などで確かめる

具体的な不変条件と禁止パターンは skill `locality-and-async` にまとめてある。
