# PC の比較実験

[mujou.pc](../pc.md) の設計を決めた実験の数値と、採らなかった案。数値は、素の PyTorch の同期シミュレーション（784→256→256→10、$B = 64$、float32）と、mujou の上の非同期の実行で測った。

## 状態の持ち方

### h の形と u の形

最初の実装は、予測からのずれ $u_i = h_i - \mu_i$ を状態にし、送るときに $h_i = \mu_i + u_i$ を組み立てていた（$u$ の形）。毎回の更新で付け替えるのと同じで、入力の変化に即座に追従するが、深い鎖で連続時間の系として不安定になる。

- $u$ の形では $u_i$ が次以降のすべての $h$ を即座に動かすので、損失のヘッセ行列が順伝播のヤコビアンの積を通して $u_i$ に返る（ループゲインは $\|\prod J\|^2$）。$h$ の形の結合は隣接層の $J^\top J$ だけ。スカラーの線形鎖（$w = 1$）の連続時間の固有値の最大実部は、深さ 8 で $u$ の形が $+0.089$、$h$ の形が $-0.068$
- ヤコビアンが 1 に近い ResBlock で効く。ResBlock 6〜12 ノードの鎖（既定の初期化、Linear + MSE、$\eta_h = 0.25$、$\tau_\lambda = 2\tau_h$）で、$u$ の形は必ず発散し（$\lambda$ が 4000 ステップで $10^{40}$）、$\eta_h$ を 0.05、0.01 に下げても発散した。$h$ の形は記事どおり収束した

同期 Jacobi での MNIST（ce、$S = 32$、$\eta_h = 0.5$、$\alpha = 0.25$、60k × 3 epoch × 3 seed）の BP との差 [pt]:

| 状態の持ち方 | relu | tanh |
| --- | --- | --- |
| $h$ で持ち、新サンプルと自分の $\theta$ の更新の次の更新で付け替える | −0.06 | −0.02 |
| ずれ $u$ で持つ | −1.23 | −0.57 |

付け替えを新サンプルのときだけにすると、$\theta$ の更新で $\mu$ が跳んだ分が $r$ に入り、relu で発散した（20k × 1 epoch、$S \in \{16, 32\}$、$\eta_h \in \{0.25, 0.5\}$ の 8 通りのうち 4 通り。tanh は 8 通りとも収束）。

### θ の跳びだけを足す理由

前の規則は、$\theta$ を更新した次の更新で $h \leftarrow \mu^{\mathrm{new}} + (h - \mu^{\mathrm{last}})$ と付け替えていた。この付け替えは $\theta$ による跳びだけでなく、その 1 更新の間の $h_{\mathrm{in}}$ の変化も $h$ に乗せる。`learn_interval=None` では毎回の更新で付け替えるので、$u$ の形そのものに戻る。

- ResBlock 8 ノードの鎖（目標は forward + 雑音、credit 0.62）を出力側から同期に回すと、前の規則では $\tau_\theta = 10^9$（$\theta$ はほぼ動かない）でも $\lambda$ が 500 ステップで $10^5$ に増えた。$\theta$ の跳び $\Delta = f(h_{\mathrm{in}};\theta_{\mathrm{new}}) - f(h_{\mathrm{in}};\theta)$ だけを足す今の規則では、$\lambda$ は credit から離れず、6000 ステップで credit と $7\times10^{-10}$ で一致した
- $\Delta$ を足すのを同じ更新にして、その更新で送る形は、非同期の MNIST のシミュレーションで 3 seed すべてが 40 バッチ前後で発散した

非同期の MNIST（実ノード、各ノードの周期 1 ms ± 10%、毎ティックで順序をシャッフル、600 バッチ × 3 seed）での比較。数字は発散しなかった seed の数。

| 方式 | 停止なし | 1 ノードが 0.5 s ごとに 115 ms 止まる | 0.25 s ごと（l2 / l1） | prequential（停止なし） |
| --- | --- | --- | --- | --- |
| 前の規則、書いた時刻から学習 | 3/3 | 2/3 | 3/3 / 3/3 | 0.989〜0.991 |
| 前の規則、入力を見た時刻から学習 | 1/3 | 0/3 | — | — |
| 連鎖、入力を見た時刻から学習 | 3/3 | 3/3 | 3/3 / 3/3 | 0.9956〜0.9958 |
| 連鎖、書いた時刻から学習 | 3/3 | 3/3 | 3/3 / 3/3 | 0.993〜0.994 |
| $\theta$ の跳びだけ + 連鎖、書いた時刻から学習（採用） | 3/3 | 3/3 | 3/3 / 3/3 | 0.993〜0.994 |

連鎖の方式は 24 回中 0 回の発散だった。この停止は 1 つのノードが周期的に止まるだけで、全ノードが不規則に遅れる実機の過負荷より穏やか。

### リセットと持ち越し

$h$、$\lambda$ はサンプルごとの状態で、i.i.d. のバッチを順に見せると、入力が切り替わった瞬間に前のサンプルの $h$ が残り、新しい予測 $\mu$ との差（活動そのものと同じ大きさ）が予測誤差として扱われる。それが credit よりずっと大きいので、$\theta$ に誤った勾配が入る。記事の公式実装は、ミニバッチごとに $h$ を forward の値に、$\lambda$ を 0 に初期化してこれを避けている（リセット）。

付け替えの無い $h$ の形での比較（BP との差 [pt]、$\eta_h = 0.5$、$\alpha = 0.2$、バッチの最後で学習）:

| $S$ | (a) リセット（relu-ce / relu-mse / tanh-ce / tanh-mse） | (b) $\lambda$ だけ 0、(c) 持ち越し |
| --- | --- | --- |
| 1 | −20.2 / −15.8 / −9.4 / −6.7 | どれも約 11%（tanh-mse は NaN） |
| 4 | −0.7 / −0.7 / −0.7 / −1.8 | 同上 |
| 8 | +0.4 / +0.2 / +0.2 / +0.1 | relu は NaN、tanh-ce −3.1 |
| 32 | −0.1 / 0.0 / −0.1 / 0.0 | relu-ce は NaN、他は −0.6〜−1.1 |
| 128 | ±0.05 | ようやく BP と同等 |

$S$ は 1 バッチを見せるステップ数。$S \le 2$ では $W_1$ の勾配が厳密に 0 になる（credit が 1 ステップに 1 層ずつ伝わるため）。付け替えればリセットは要らず、持ち越しで $S = 32$ で BP と同等になった（上の表）。

$u$ の形での測定では $S = 16$ で崩れた（relu は 34.6〜90.4%、tanh は −0.6pt）。原因は $u$、$\lambda$ の持ち越しではなく（どちらか片方を 0 に戻しても結果はほぼ変わらなかった）、**入力とラベルの時刻のずれ**だった。新しい $x$ は経路上のノードの更新を 1 回ずつ経て出力に届くが、ラベルは出力にすぐ届く。その間、出力は古い入力から作った $h$ を新しいラベルと組んで微分し、別のサンプルのラベルに対する勾配を流す。切り替え直後の $\delta_2$ は新しい credit の 3〜5 倍まで膨らんだ。ラベルを伝播の遅れの分だけ遅らせると、行き過ぎは消えた（$S = 16$ の relu が崩壊から −1.9pt、毎ステップ学習の relu が −9.9 から −0.87pt、tanh が −1.7 から −0.19pt）。そこで目標を入力に付随させ、活動と同じ経路で運ぶことにした。遅れの段数を数えずに、ラベルを伝播の遅れの分だけ遅らせられる。

## 学習の時刻

サンプルの時点が効くのは、入力が変わった直後の $\delta$ が新しいサンプルの credit になっていないからである。MNIST での比較（$h$ で持ちリセット、relu-ce、$S = 32$）:

| 学習のタイミング | BP との差 | $g_{W_1}$ の cos / ノルム比 | 1 バッチの計算時間 |
| --- | --- | --- | --- |
| 毎ステップ（$K = 1$） | +0.13pt | 0.85 / 0.68 | 26.6 ms |
| $K = S/4$ | 発散 | — | 16.3 ms |
| バッチの最後（切り替えから $S$） | −0.13pt | 0.999 / 0.97 | 15.1 ms |
| バッチの途中（切り替えから $S/2$） | +0.56pt | 0.995 / 1.18 | 15.1 ms |

- 効くのは切り替えからの時間だけで、途中で学習した結果は $S/2$ だけ見せて最後に学習した結果と完全に一致した
- 切り替えと無関係な位相で一定間隔ごとに学習すると、$u$ で持つ場合も relu で −2〜−19pt と崩れた
- 入力を見た更新から数えると、MNIST の 3 ノードを `ManualRun` で揺らいだ順に回して数十バッチで発散した（固定の Jacobi の順では 1 epoch 安定）

## learn_interval と鎖の安定

ResBlock 8 ノードの鎖（往復 18 周期、$\tau_\theta = 10^9$、credit 0.62）での `learn_interval`:

| `learn_interval` | $\lambda$ |
| --- | --- |
| `None` | credit から離れず、credit に収束 |
| 16 周期 | 同上 |
| 4 周期 | 有界だが credit の約 4 倍 |
| 2 周期、1 周期 | 発散 |

数えているのはノード数ではなくホップ数（18 = 2 × 9）。2 × ホップ数 × 周期は安定の境界ではないので、検査せず推奨値にした。

## 時定数の安定な範囲

$h$ で持ちリセット、$S = 32$:

- relu: $\eta_h \le 0.5$ なら $\alpha \in [0, 1]$ のすべてで安定。$\eta_h = 0.7$ は $\alpha \le 0.1$ で発散、$\eta_h = 1$ はほぼ発散
- tanh: $\eta_h \le 0.7$ で安定。CE で $\alpha \le 0.1$ だと劣化
- 1 つのモードを線形化すると $u'' + \eta_h c\,u' + \eta_h\alpha\,u = 0$（$c \approx 1 + \|J\|^2$）。臨界減衰は $\alpha \approx c^2\eta_h/4$ で、実測の最良帯 $\eta_h \in [0.3, 0.7]$、$\alpha \in [0.1, 0.3]$ と一致する。$\alpha$ が大きすぎると行き過ぎ（ノルム比 1.6〜1.8）、$\alpha = 1$ では勾配の向きも崩れる（cos 0.5〜0.9）

記事の公式実装は $\eta_h = 1/\lambda_{\max}$（約 0.2〜0.25）、$\alpha = 1$、$T = 64$ か $2L$、Adam を使う。$\alpha = 1$ は上の結果では大きすぎるが、公式の実験は幅 32 の深い residual MLP で、曲率 $c$ が違う。

ノード間の結合の安定の余裕もモデルに依存する。スカラーの線形の 2 層鎖を出力側から Jacobi で回すと、$\eta_h = \Delta t/\tau_h$ が $w = 1$ なら 1.0、$w = 1.5$ なら 0.5 で発散した。

## dt の伸び

- 負荷で全ノードがそろって約 230 ms 止まった直後に、学習率 0.9 の 1 歩を踏み（$\Sigma\Delta t$ が 8〜9 バッチ分）、続いて `dt` の伸びでノード間の陽的な結合が不安定になって発散した。以前は $\mu$ と $g$ を固定したまま `max_step` 以下の刻みに分けて進めていたが、分割ではノード間の結合を安定化できないので、`max_dt` に置き換えた
- MNIST の example で timer の time scale を 2 にすると、最も遅いノード（784 入力）が周期の大半を計算に使い、読むメッセージが古くなって、前の付け替えの規則では数百バッチで発散した（`dt` は 1.25 周期程度で `max_dt` に届かない）。跳びの連鎖を入れてからは、スケール 2 でも 1 epoch を完走した

## MNIST

784-256-256-10、relu、CE、$B = 64$、$S = 32$、$\tau_h = 4$ ms、$\tau_\lambda = 2\tau_h$、1 バッチの学習率 0.1（BP も同じ）、32 コア、3.14t、time scale 1、4 ワーカー。

| 条件 | PC-ALM | BP |
| --- | --- | --- |
| 3 epoch 後の test（seed 0、`pc.show` の最初の予測で測る） | 97.60% | 97.54% |
| prequential（epoch 1 / 2 / 3） | 92.39 / 97.21 / 97.93% | 91.78 / 96.83 / 97.92% |
| 1 バッチの実時間 | 32.2 ms | 0.80 ms |

- `dt` の 99% 点はどのノードも 1.25 周期以下で、8 周期を超えた更新は 0 回
- 同期のシミュレーションを 1 スレッドで回すと、1 バッチが BP の 0.9 ms に対して 15 ms（約 17 倍）だった。1 バッチを $S = 32$ ステップ緩和し、各ステップで全ノードが forward と VJP を 1 回ずつ取るため。mujou ではノードが別々のワーカーで同時に計算するので、3 ノードなら最大でおよそ 3 倍縮む

負荷の下（busy loop と並べて 1 epoch、seed 0）: time scale 1 で busy 16 本 96.62%、26 本 96.52% と 96.23%（2 回）、32 本は発散（prequential 19.5%、test 9.8%）。32 本で time scale 0.5 は完走したが 93.52% に落ちた。前の付け替えの規則では 26 本・スケール 1 と 32 本・スケール 0.5 が発散していた。過負荷で発散するのは許容している。

## 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| ずれ $u = h - \mu$ を状態にする | 深い鎖で連続時間の系として発散する（上の表） |
| 入力が変わるたびに $h$ と $\lambda$ をリセットする | 付け替えれば要らない。リセットは非同期の実行で「いつ」を決める同期を要する |
| 目標を別のポートで運び、時刻で揃える | ホストが伝播より速く書くと、目標のスロットが常に新しいサンプルで上書きされ、一致する瞬間が来なくなる |
| 目標をコアの付随データ（carry）で中継する | 使い手が PC だけで、`Activity` の普通のフィールドで同じことが成り立つ。コアの Port・Schema・Message・状態の木から付随データの分岐が消える。コストは 1 ホップあたりの y・mask・time のコピーで、MNIST の悪化は 1% 未満（[性能の基準値](benchmarks.md)） |
| 学習の時刻を、ノードが入力を見た更新から数える | 非同期の更新順で発散した |
| `learn_interval < 2 × ホップ数 × period` を断る | 安定な設定（16 周期など）まで拒む |
| $\Delta t$ を刻みに分割する | ノード間の陽的な結合を安定化しない |
| `LearnClock.tick` が 2 つの bool を返し、学習の後に `learned()` を呼ばせる | 呼ぶ順の契約を利用者に負わせる。名前付きの `Tick` を返し、`learn` を返した時点で数え直す |
| `functional.vjp` が Tensor の δ と `wrt_input` も受け取る | 使い手がいない柔軟性 |
