# 局所性と非同期性の設計規約

mujou の目標は、学習後に重みを固定して推論する従来の流儀を捨て、**ストリームから学び続け、常に変化し続ける**（無常）学習機械を作ること。そのために、計算の単位（層、将来はニューロン）が中央の指揮なしに、隣の単位とのやり取りだけで推論と学習を進められる構造にする。

学習則の数理は skill `pc-alm`。この skill は「その数理をどう実行するか」の規約を扱う。

## 不変条件

設計・実装・レビューのたびに次の 4 つを確かめる。破る必要があるなら、ユーザーに確認して理由を `memory/` に残す。

### 1. 局所性: 読めるのは自分と隣だけ

- 計算単位 $i$ が更新に使ってよいのは、自分の状態（$h_i, \lambda_i, W_i$）と、隣接単位から**メッセージとして受け取った値**だけ
- PC-ALM では、下から $h_{i-1}$（上向きのメッセージ）、上から $W_{i+1}^\top \varepsilon_{i+1}$（下向きのメッセージ）を受け取れば足りる
- 他の単位の内部状態を直接参照しない（オブジェクトをまたいだ属性アクセスで $h_{i+1}$ を覗く、など）
- **計算グラフを単位間で繋げない。** 受け取ったテンソルは detach された値として扱う。グローバルな `.backward()` は禁止

### 2. 非同期性: 全体の足並みを前提にしない

- 「全層が forward を終えたら全層が backward」といった**グローバルなバリア**を、更新則の正しさの前提にしない
- 各単位は、手元にある最新のメッセージ（古いかもしれない）で更新できる形に書く。メッセージの到着順や遅延に依存する仮定は明示する
- 同期実行（全単位を順番に 1 ステップずつ回す）は、非同期実行の**特殊ケースのスケジュール**として実装する。同期専用の別経路を作らない

### 3. 継続学習: フェーズとエポックを固定しない

- 「学習モード／推論モード」の切替や、エポック・データセット全体を前提とした API にしない。入力はストリームとして 1 ステップずつ届く
- 教師信号は届くこともあれば届かないこともある。教師の有無で分岐する箇所は単位の内側に閉じ込める
- 状態（活動・双対・重み）は常に更新され得る。推論中に重みが変わることを壊れた状態として扱わない

### 4. 状態の所有: 1 つの状態に書き手は 1 人

- 各テンソル状態は所有する単位だけが書き換える。共有テンソルへの in-place 更新で別の単位の入力が書き変わる事故を防ぐ
- メッセージは送信時点のスナップショット（コピーまたは不変な値）として渡す

## 禁止パターンと代替

| 禁止パターン | 何が壊れるか | 代替 |
| --- | --- | --- |
| `loss.backward()` でネットワーク全体の勾配を取る | 局所性。BP そのもの | skill `pc-alm` の層局所更新式 |
| 層 $i$ の forward 出力を detach せずに層 $i+1$ に渡す | 層間で計算グラフが繋がる | 受け取り側で detach、またはメッセージ型に包む |
| 全層をまとめたテンソルのリストを 1 つの関数で一括更新し、その関数でしか正しく動かない | 非同期化できない | 単位ごとの `step` を定義し、一括更新はスケジュールとして書く |
| `model.train()` / `model.eval()` 相当のグローバルなモード | 継続学習 | 教師信号の有無をメッセージで渡す |
| 単位が隣の単位オブジェクトの属性を直接読む | 局所性・状態の所有 | メッセージ経由で受け取る |

## 例外: 層の内側での autograd

単位の**内側に閉じた**ローカルエネルギーの勾配を autograd で求めるのは許容する（手書きの勾配より速くて安全な場合がある）。条件は次のとおり。

1. 入力として受け取った隣接単位の値は detach 済みであること
2. 勾配を取る対象が自分の状態（$h_i, W_i$ など）だけであること
3. その行に `# mujou: local-autograd` を付け、何のローカルエネルギーの勾配かをコメントで書くこと

このマーカーの無い `.backward()` / `autograd.grad` は PostToolUse hook（`.claude/hooks/posttooluse-locality-guard.py`）が警告する。マーカーは警告を消すためのものではなく、レビューで確認する場所の目印である（`algorithm-reviewer` が層内に閉じているか確かめる）。

## テストの決定性

非同期性を持ち込んでもテストは再現可能に保つ。

- スケジューラは「どの単位をどの順で何回動かすか」を外から与えられる形にし、テストでは固定のスケジュールを渡す
- 乱数は単位ごとに独立した generator を持たせ、seed を外から与えられるようにする
- 同期スケジュールと、いくつかの固定された非同期スケジュール（逆順・ランダム順を固定 seed で）で、同じ不動点に収束することを確かめるテストを持つ
- 実時間のスレッド・プロセス並列の検証は、決定的なスケジュールでのテストが通ってから、別の層として追加する
