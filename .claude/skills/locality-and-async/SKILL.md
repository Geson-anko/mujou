# 局所性と非同期性の設計規約

mujou の目標は、推論と学習を同時に行い、知能に「無常」（常が無いこと）を実現すること。学習後に重みを固定して推論する従来の流儀を捨て、**ストリームから学び続け、常に変化し続ける**学習機械を作る。そのために、計算を**ブロック**に分け、各ブロックが中央の指揮なしに、隣のブロックとのやり取りだけで推論と学習を進められる構造にする。

既定の更新手法 PC-ALM の数理は skill `pc-alm`。この skill は「更新手法をどう実行するか」の規約を扱い、特定の学習則には依存しない。

## ブロック

- **ブロックの内側は同期的に計算する。ブロック同士は非同期のメッセージでやり取りする。** 非同期・分散の境界は、常にブロックの境界と一致する
- ブロックの大きさは、どのブロックのクラスを書くか・使うかで決まる。設定で自動分割しない（畳み込みのような重み共有があると、分割は weight transport の問題を生む）
    1. ニューロン（1 ニューロンを 1 ブロック）。最小のブロック。future work
    2. レイヤー（1 レイヤーを 1 ブロック）。わかりやすさのため既定
    3. スタック（複数のレイヤーを 1 ブロック。モデル全体を 1 ブロックにしてもよい）
- 非同期の境界（ブロックのクラスで決まる）と実行の配置（どのワーカーでどの順に回すか）を混同しない。複数ブロックを同じワーカーで決まった順に回しても、非同期の境界は変わらない
- ブロックはライフサイクル hook（`on_start` / `on_update(dt)` / `on_pause` / `on_resume` / `on_stop` / `state_dict` / `load_state_dict`）を override して書く。ループはフレームワークが持つ。エポック・モード切替・受信ごとに呼ぶ hook は持たない（`docs/blocks.md`）
- ネットワークは構築時だけの構造で、hook を持たない。実行時の単位はブロックだけ
- ブロックの内側の計算方法は自由に選べる。ニューロンブロックの合成、行列演算、BP など
- ブロック間のメッセージは「結合ごとの値の束」として定義する。ブロックの大きさを変えても、ブロック間の契約（何を送り何を受け取るか）が変わらないようにする
- GPU での計算効率は設計目標にしない。ニューロンブロックの分割が非効率になることを理由に設計を制限しない

## 実行モデル: 共有スロットとグローバル時間

- **ブロック間の通信に queue・pipe を使わない。** 各ブロックは自分の出力を「スロット」に書き込み、隣接ブロックはそのスロットの最新値を読む。排他制御は値の読み書きの lock だけで、メッセージングのためにブロック同士が同期することはない
- **各ブロックは独自に活動する。** 自分の周期でループし、そのとき読める最新値で状態を更新して書き込む。他のブロックを待たない
- 読み手は最新値だけを見る。一度も読まれずに上書きされる値も、何度も読まれる値もある。これを正常な動作として扱う
- 複数のスロットをまとめて読んでも、全体として一貫したスナップショットにはならない。各値が個別に一貫していればよい
- **システムはグローバルタイマーの上の連続時間系として定義する。** 更新則は時間 $t$ に対する微分方程式として書き、各ブロックは前回の更新からグローバルタイマーで測った経過時間 $\Delta t$ で離散化する。更新量をステップ数で決めない
- $\Delta t$ が大きすぎると陽的な離散化は不安定になる。上限で打ち切るか、内部で刻みを分割する
- グローバルタイマーはシングルトン（システム全体で時間は 1 つ）。時間のスケール（加速・減速）、一時停止・再開、スレッドセーフ、状態の保存・復元を持つ（参考: pamiq-core の `TimeController`）
- 既定の PC-ALM の連続時間形は skill `pc-alm` 7.1 節

### 実行クラス（M:N スケジューリング）

コアは Rust で実装し、M 個のブロックを N 本のワーカースレッドに載せる。ブロックは「状態 + ライフサイクル hook」であり、他のブロックを待たないので async/await は使わない。1 ステップが協調スケジューリングの区切りになる。

| 実行クラス | 載る場所 | 向いているブロック |
| --- | --- | --- |
| タスク | 共有ワーカープール | ネイティブの小さく大量のブロック（ニューロンブロックなど） |
| 専用スレッド | 自分の OS スレッド | Python/PyTorch のブロック、ブロック内 BP、I/O、重いスタック |

- Python のコードを動かすブロックは GIL を要するので、タスクのプールに載せない
- スロットの読み書きはワーカーを止めない形（atomic なポインタ差し替えとバッファプール。`docs/messages.md`）にする
- メッセージの値の型はコアが独自に持つ。PyTorch のブロックはブロックの境界で変換する（テンソルの直接連携は future work）

## 更新手法の差し替え

- 更新手法（学習則）はブロックの基盤から分離し、差し替えられるようにする。PC-ALM は暫定の既定に過ぎない
- ブロック・メッセージ・スケジューラは特定の学習則を前提にしない。PC-ALM 固有の状態（双対変数 $\lambda$）やメッセージの中身（$W^\top \varepsilon$）は、PC-ALM の更新手法の側に閉じ込める
- BP のような非局所的な手法も、1 つのブロックの内側に閉じていれば使える。外から見れば、メッセージをやり取りする 1 つのブロックに過ぎない

## 不変条件

以下は**ブロックの間**に課す。設計・実装・レビューのたびに確かめる。破る必要があるなら、ユーザーに確認して理由を `memory/` に残す。

### 1. 局所性: 読めるのは自分と隣だけ

- ブロックが更新に使ってよいのは、自分の状態と、隣接ブロックから**メッセージとして受け取った値**だけ
- 既定の PC-ALM では、下から $h_{i-1}$（上向きのメッセージ）、上から $W_{i+1}^\top \varepsilon_{i+1}$（下向きのメッセージ）を受け取れば足りる。ニューロンブロックでは、これが結合ごとの値（$h_{i-1,k}$ と $W_{i+1}[k,j]\,\varepsilon_{i+1,k}$）になる
- 同じ層のニューロン同士の結合（softmax、LayerNorm など）も、横方向のメッセージとして表す。ニューロンブロックでも扱えるようにする
- 他のブロックの内部状態を直接参照しない（オブジェクトをまたいだ属性アクセスで隣の $h$ を覗く、など）
- **計算グラフをブロック間で繋げない。** 受け取ったテンソルは detach された値として扱う。ブロックをまたぐ `.backward()` は禁止

### 2. 非同期性: 全体の足並みを前提にしない

- 「全ブロックが forward を終えたら全ブロックが backward」といった**ブロックをまたぐグローバルなバリア**を、更新則の正しさの前提にしない
- 各ブロックは、スロットから読めた最新値（古いかもしれない）で更新できる形に書く。値の古さや更新周期に依存する仮定は明示する
- 同期実行（全ブロックを順番に固定の $\Delta t$ で 1 ステップずつ回す）は、非同期実行の**特殊ケースのスケジュール**として実装する。同期専用の別経路を作らない
- 例外は保存・復元・観測のための停止だけ。停止要求のフラグを立ててすぐにグローバルタイマーを凍結し、全ブロックがループの区切りで止まってから状態を読む（`docs/execution-model.md`）。停止中はグローバル時間が進まないので、ダイナミクスからは見えない。停止を学習アルゴリズムの一部（定期的に止めて重みを平均する、など）に使わない

### 3. 継続学習: フェーズとエポックを固定しない

- 「学習モード／推論モード」の切替や、エポック・データセット全体を前提とした API にしない。入力はストリームとして 1 ステップずつ届く
- 教師信号は届くこともあれば届かないこともある。教師の有無で分岐する箇所はブロックの内側に閉じ込める
- 状態（活動・重み、更新手法固有の状態）は常に更新され得る。推論中に重みが変わることを壊れた状態として扱わない

### 4. 状態の所有: 1 つの状態に書き手は 1 人

- 各テンソル状態は所有するブロックだけが書き換える。共有テンソルへの in-place 更新で別のブロックの入力が書き変わる事故を防ぐ
- ブロックをまたぐ結合の重みは後シナプス側のブロックが所有する。逆向きのメッセージ（例: $W[k,j]\,\varepsilon_k$）は所有側が計算して送る。両端で重みのコピーを持つと、非同期実行でコピー同士がずれる
- スロットへの書き込みは、新しい値への参照の差し替え（またはコピー）で行う。読み手が書きかけの値を見ないようにする。書いた時点のグローバル時刻はスロットが自動で添える（メッセージの型とスロットの仕様は `docs/messages.md`）

## 禁止パターンと代替

| 禁止パターン | 何が壊れるか | 代替 |
| --- | --- | --- |
| ブロックをまたいで `loss.backward()` で勾配を取る | 局所性 | 更新手法の局所更新式。BP を使うならブロックの内側に閉じる |
| ブロック $i$ の出力を detach せずにブロック $i+1$ に渡す | ブロック間で計算グラフが繋がる | 受け取り側で detach、またはメッセージ型に包む |
| 全ブロックをまとめて 1 つの関数で一括更新し、その関数でしか正しく動かない | 非同期化できない | ブロックごとの `step` を定義し、一括更新はスケジュールとして書く |
| `model.train()` / `model.eval()` 相当のグローバルなモード | 継続学習 | 教師信号の有無をメッセージで渡す |
| ブロックが隣のブロックオブジェクトの属性を直接読む | 局所性・状態の所有 | メッセージ経由で受け取る |
| ブロック・メッセージ・スケジューラの型に PC-ALM 固有の量を書き込む | 更新手法の差し替え | 更新手法の側に閉じ込める |

## ブロック内の autograd

ブロックの**内側に閉じた**勾配計算を autograd で求めるのは許容する。ローカルエネルギーの勾配でも、ブロック内の BP でもよい。条件は次のとおり。

1. 入力として受け取った隣接ブロックの値は detach 済みであること
2. 勾配を取る対象が自分のブロックの状態だけであること
3. その行に `# mujou: local-autograd` を付け、何の勾配か（どのブロックの内側に閉じているか）をコメントで書くこと

このマーカーの無い `.backward()` / `autograd.grad` は PostToolUse hook（`.claude/hooks/posttooluse-locality-guard.py`）が警告する。マーカーは警告を消すためのものではなく、レビューで確認する場所の目印である（`algorithm-reviewer` がブロック内に閉じているか確かめる）。

## テストの決定性

非同期性を持ち込んでもテストは再現可能に保つ。

- グローバルタイマーはシングルトンなので、テストではその時刻の源を手動で進める仮想時計に切り替える。実時間の `sleep` や経過時間にテストの結果を依存させない
- スケジューラは「どのブロックをどの順で、どの $\Delta t$ で何回動かすか」を外から与えられる形にし、テストでは固定のスケジュールを渡す
- 全ブロックを固定の $\Delta t$ で同期的に回したとき、更新手法の元の離散アルゴリズムに一致することを確かめる
- 乱数はブロックごとに独立した generator を持たせ、seed を外から与えられるようにする
- 同期スケジュールと、いくつかの固定された非同期スケジュール（逆順・ランダム順を固定 seed で）で、同じ不動点に収束することを確かめるテストを持つ
- ブロックの分け方（レイヤー・スタック。ニューロン単位を実装したらそれも）を変えても同じ結果・同じ不動点になることを確かめるテストを持つ
- 実時間のスレッド・プロセス並列の検証は、決定的なスケジュールでのテストが通ってから、別の層として追加する
