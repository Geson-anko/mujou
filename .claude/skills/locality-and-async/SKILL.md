# 局所性と非同期性の設計規約

mujou の目標は、推論と学習を同時に行い、知能に「無常」（常が無いこと）を実現すること。学習後に重みを固定して推論する従来の流儀を捨て、**ストリームから学び続け、常に変化し続ける**学習機械を作る。そのために、計算を**ノード**に分け、各ノードが中央の指揮なしに、隣のノードとのやり取りだけで推論と学習を進められる構造にする。

既定の更新手法 PC-ALM の数理は skill `pc-alm`。この skill は「更新手法をどう実行するか」の規約を扱い、特定の学習則には依存しない。

## ノード

- **ノードの内側は同期的に計算する。ノード同士は非同期のメッセージでやり取りする。** 非同期・分散の境界は、常にノードの境界と一致する
- ノードの大きさは、どのノードのクラスを書くか・使うかで決まる。設定で自動分割しない（畳み込みのような重み共有があると、分割は weight transport の問題を生む）
    1. ニューロン（1 ニューロンを 1 ノード）。最小のノード。future work
    2. レイヤー（1 レイヤーを 1 ノード）。わかりやすさのため既定
    3. スタック（複数のレイヤーを 1 ノード。モデル全体を 1 ノードにしてもよい）
- 非同期の境界（ノードのクラスで決まる）と実行の配置（どのワーカーでどの順に回すか）を混同しない。複数ノードを同じワーカーで決まった順に回しても、非同期の境界は変わらない
- ノードはライフサイクル hook（`on_thread_start`（専用スレッドのノードだけ）/ `on_start` / `on_update(dt)` / `on_pause` / `on_resume` / `on_exception` / `on_stop` / `state_dict` / `load_state_dict`）を override して書く。ループはフレームワークが持つ。エポック・モード切替・受信ごとに呼ぶ hook は持たない（`specs/nodes.md`）
- ネットワークは構築時だけの構造で、hook を持たない。実行時の単位はノードだけ
- ノードの内側の計算方法は自由に選べる。ニューロンノードの合成、行列演算、BP など
- ノード間のメッセージは「結合ごとの値の束」として定義する。ノードの大きさを変えても、ノード間の契約（何を送り何を受け取るか）が変わらないようにする
- GPU での計算効率は設計目標にしない。ニューロンノードの分割が非効率になることを理由に設計を制限しない

## 実行モデル: 共有スロットと実行の時間軸

- **ノード間の通信に queue・pipe を使わない。** 各ノードは自分の出力を「スロット」に書き込み、隣接ノードはそのスロットの最新値を読む。排他制御は値の読み書きの lock だけで、メッセージングのためにノード同士が同期することはない
- **各ノードは独自に活動する。** 自分の周期でループし、そのとき読める最新値で状態を更新して書き込む。他のノードを待たない
- 読み手は最新値だけを見る。一度も読まれずに上書きされる値も、何度も読まれる値もある。これを正常な動作として扱う
- 複数のスロットをまとめて読んでも、全体として一貫したスナップショットにはならない。各値が個別に一貫していればよい
- **システムはその実行のタイマーの上の連続時間系として定義する。** 更新則は時間 $t$ に対する微分方程式として書き、各ノードは前回の更新からその実行のタイマーで測った経過時間 $\Delta t$ で離散化する。更新量をステップ数で決めない
- $\Delta t$ が大きすぎると陽的な離散化は不安定になる。上限で打ち切るか、内部で刻みを分割する
- **時間軸は実行ごとに 1 本。** 1 つの実行の全ノード・全スロット・ホストの入力は、その実行のタイマーを使う。既定は全実行が共有するグローバルタイマーで、互いの停止で時間を止め合いたくない実行は別のタイマーで動かす（2026-10-16 ユーザー決定、`memory/project_timer_per_run.md`）。タイマーは時間のスケール（加速・減速）、一時停止・再開、スレッドセーフ、状態の保存・復元を持つ（参考: pamiq-core の `TimeController`）
- 既定の PC-ALM の連続時間形は skill `pc-alm` 7.1 節

### 実行クラス（M:N スケジューリング）

コアは Rust で実装し、M 個のノードを N 本のワーカースレッドに載せる。ノードは「状態 + ライフサイクル hook」であり、他のノードを待たないので async/await は使わない。1 ステップが協調スケジューリングの区切りになる。

| 実行クラス | 載る場所 | 向いているノード |
| --- | --- | --- |
| ワーカー（既定） | 実行ごとのワーカープール（`mujou.run(workers=None)`、既定は論理 CPU 数） | Python/PyTorch のノードを含むほとんどのノード |
| 専用スレッド（opt-in） | 自分の OS スレッド（`Node(dedicated_thread=True)`） | ブロッキングする I/O、スレッドごとの状態に頼るノード（`on_thread_start` はこれだけに呼ぶ） |

- ワーカーは期限の早い更新から 1 hook ずつ実行し、ノードはワーカーの間を移る。1 つのノードの hook は重ならず、前の hook の書き込みは次の hook から見える（2026-10-18 ユーザー決定、`memory/project_mn_scheduler.md`）
- hook の間で保たれるのは `contextvars`（ノードごとの `Context`）と、フレームワークが hook の前に戻す勾配モード・CUDA の device と stream だけ。`threading.local`・`threading.current_thread()` に頼らない。スレッドごとの設定は hook の中の `with` に閉じるか、内部の hook `_on_enter`（切り替えのたびに呼ぶ）に書く
- ブロッキングする hook はワーカーを占有し、ほかのノードの $\Delta t$ を伸ばす。そういうノードは専用スレッドにする
- Port の所有は「スレッドが今走らせているノード」で判定する。同じワーカーでも、ほかのノードの Port は読み書きできない
- スロットの読み書きはワーカーを止めない形（バッファプールと、スロットごとの lock の下での `Arc` の差し替え。`specs/messages.md`・`specs/native-core.md`）にする。相手の更新の進み具合は待たない。待つのは、スロットごとの lock の下で `Arc` を複製・差し替える短い区間だけ。lock-free の `arc-swap` には別のスロットの値を返す不具合があったので戻さない
- 利用者が扱う値は `torch.Tensor` だけ。コアの値は `mujou._core._native` の内部のホストバッファで、`mujou.Node` が DLPack を介して読み書きとも必ずコピーする（ゼロコピー共有・GPU 共有はしない。`specs/messages.md`）

## 更新手法の差し替え

- 更新手法（学習則）はノードの基盤から分離し、差し替えられるようにする。PC-ALM は暫定の既定に過ぎない
- ノード・メッセージ・スケジューラは特定の学習則を前提にしない。PC-ALM 固有の状態（双対変数 $\lambda$）やメッセージの中身（$W^\top \varepsilon$）は、PC-ALM の更新手法の側に閉じ込める
- BP のような非局所的な手法も、1 つのノードの内側に閉じていれば使える。外から見れば、メッセージをやり取りする 1 つのノードに過ぎない

## 不変条件

以下は**ノードの間**に課す。設計・実装・レビューのたびに確かめる。破る必要があるなら、ユーザーに確認して理由を `memory/` に残す。

### 1. 局所性: 読めるのは自分と隣だけ

- ノードが更新に使ってよいのは、自分の状態と、隣接ノードから**メッセージとして受け取った値**だけ
- 既定の PC-ALM では、下から $h_{i-1}$（上向きのメッセージ）、上から $W_{i+1}^\top \varepsilon_{i+1}$（下向きのメッセージ）を受け取れば足りる。ニューロンノードでは、これが結合ごとの値（$h_{i-1,k}$ と $W_{i+1}[k,j]\,\varepsilon_{i+1,k}$）になる
- 同じ層のニューロン同士の結合（softmax、LayerNorm など）も、横方向のメッセージとして表す。ニューロンノードでも扱えるようにする
- 他のノードの内部状態を直接参照しない（オブジェクトをまたいだ属性アクセスで隣の $h$ を覗く、など）
- **計算グラフをノード間で繋げない。** 受け取ったテンソルは detach された値として扱う。ノードをまたぐ `.backward()` は禁止

### 2. 非同期性: 全体の足並みを前提にしない

- 「全ノードが forward を終えたら全ノードが backward」といった**ノードをまたぐグローバルなバリア**を、更新則の正しさの前提にしない
- 各ノードは、スロットから読めた最新値（古いかもしれない）で更新できる形に書く。値の古さや更新周期に依存する仮定は明示する
- 同期実行（全ノードを順番に固定の $\Delta t$ で 1 ステップずつ回す）は、非同期実行の**特殊ケースのスケジュール**として実装する。同期専用の別経路を作らない
- 例外は状態の取得・復元や観測のための停止だけ。停止要求のフラグを立ててすぐにその実行のタイマーを凍結し、全ノードがループの区切りで止まってから状態を読む（`specs/execution-model.md`）。停止中はその実行の時間が進まないので、ダイナミクスからは見えない。停止を学習アルゴリズムの一部（定期的に止めて重みを平均する、など）に使わない

### 3. 継続学習: フェーズとエポックを固定しない

- 「学習モード／推論モード」の切替や、エポック・データセット全体を前提とした API にしない。入力はストリームとして 1 ステップずつ届く
- 教師信号は届くこともあれば届かないこともある。教師の有無で分岐する箇所はノードの内側に閉じ込める
- 状態（活動・重み、更新手法固有の状態）は常に更新され得る。推論中に重みが変わることを壊れた状態として扱わない

### 4. 状態の所有: 1 つの状態に書き手は 1 人

- 各テンソル状態は所有するノードだけが書き換える。共有テンソルへの in-place 更新で別のノードの入力が書き変わる事故を防ぐ
- ノードをまたぐ結合の重みは後シナプス側のノードが所有する。逆向きのメッセージ（例: $W[k,j]\,\varepsilon_k$）は所有側が計算して送る。両端で重みのコピーを持つと、非同期実行でコピー同士がずれる
- スロットへの書き込みは、新しい値への参照の差し替え（またはコピー）で行う。読み手が書きかけの値を見ないようにする。書いた時点のその実行のタイマーの時刻はスロットが自動で添える（メッセージの型とスロットの仕様は `specs/messages.md`）

## 禁止パターンと代替

| 禁止パターン | 何が壊れるか | 代替 |
| --- | --- | --- |
| ノードをまたいで `loss.backward()` で勾配を取る | 局所性 | 更新手法の局所更新式。BP を使うならノードの内側に閉じる |
| ノード $i$ の出力を detach せずにノード $i+1$ に渡す | ノード間で計算グラフが繋がる | 受け取り側で detach、またはメッセージ型に包む |
| 全ノードをまとめて 1 つの関数で一括更新し、その関数でしか正しく動かない | 非同期化できない | ノードごとの `on_update(dt)` を定義し、一括更新はスケジュールとして書く |
| `model.train()` / `model.eval()` 相当のグローバルなモード | 継続学習 | 教師信号の有無をメッセージで渡す |
| ノードが隣のノードオブジェクトの属性を直接読む | 局所性・状態の所有 | メッセージ経由で受け取る |
| ノード・メッセージ・スケジューラの型に PC-ALM 固有の量を書き込む | 更新手法の差し替え | 更新手法の側に閉じ込める |

## ノード内の autograd

ノードの**内側に閉じた**勾配計算を autograd で求めるのは許容する。ローカルエネルギーの勾配でも、ノード内の BP でもよい。条件は次のとおり。

1. 入力として受け取った隣接ノードの値は detach 済みであること
2. 勾配を取る対象が自分のノードの状態だけであること
3. その行に `# mujou: local-autograd` を付け、何の勾配か（どのノードの内側に閉じているか）をコメントで書くこと

このマーカーの無い `.backward()` / `autograd.grad` は PostToolUse hook（`.claude/hooks/posttooluse-locality-guard.py`）が警告する。マーカーは警告を消すためのものではなく、レビューで確認する場所の目印である（`algorithm-reviewer` がノード内に閉じているか確かめる）。

## テストの決定性

非同期性を持ち込んでもテストは再現可能に保つ。

- テストでは手動で進める仮想時計のタイマーを使う（ネットワークのテストは実行ごとに渡す `mujou.testing.VirtualTimer`、コアのテストは独立に作ったタイマー。グローバルタイマーを仮想時計に切り替えるのは、グローバルタイマー自体のテストだけ）。実時間の `sleep` や経過時間にテストの結果を依存させない
- スケジューラは「どのノードをどの順で、どの $\Delta t$ で何回動かすか」を外から与えられる形にし、テストでは固定のスケジュールを渡す
- 全ノードを固定の $\Delta t$ で同期的に回したとき、更新手法の元の離散アルゴリズムに一致することを確かめる
- 乱数はノードごとに独立した generator を持たせ、seed を外から与えられるようにする
- 同期スケジュールと、いくつかの固定された非同期スケジュール（逆順・ランダム順を固定 seed で）で、同じ不動点に収束することを確かめるテストを持つ
- ノードの分け方（レイヤー・スタック。ニューロン単位を実装したらそれも）を変えても同じ結果・同じ不動点になることを確かめるテストを持つ
- 実時間のスレッド・プロセス並列の検証は、決定的なスケジュールでのテストが通ってから、別の層として追加する
